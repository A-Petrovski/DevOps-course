## Введение
NGINX - это веб-сервер, прокси-сервер, обратный (reverse) прокси-сервер и балансировщик нагрузки. Раскроем эти магические понятия.

**Веб-сервер** — это программа, которая принимает и обрабатывает запросы от клиентов по протоколам HTTP и HTTPS и возвращает им ответ в виде HTML-страницы.

**Прокси-сервер** принимает и обрабатывает запросы клиентов, а затем передает их дальше другим программам.

**Обратный прокси-сервер** - принимает запрос клиента, отправляет запрос одному или нескольким прокси-серверам, получает ответ и доставляет ответ сервера клиенту.

Конкретно про разницу между прокси и обратным прокси здесь.

**Балансировщик нагрузки** - программа, которая распределяет сетевые запросы между серверами, следуя конфигурации балансировки.

NGINX выполняет роль посредника между клиентами и веб-приложениями, обеспечивая оптимальное распределение запросов, улучшенную производительность и безопасность, а также возможность кеширования статических ресурсов.

### Что он может?
1. **Обработка запросов:** NGINX может принимать запросы от клиентов, таких как веб-браузеры, и перенаправлять их к соответствующему веб-приложению для обработки. Это позволяет разделять обязанности между веб-сервером и веб-приложением, упрощая разработку и управление.
2. **Балансировка нагрузки:** NGINX может распределять запросы от клиентов на несколько экземпляров веб-приложения или серверов, что позволяет достичь равномерного распределения нагрузки. Это повышает производительность и отказоустойчивость, поскольку запросы распределяются на доступные ресурсы.
3. **Кеширование:** NGINX может кэшировать статическое содержимое, такое как изображения, CSS-файлы и JavaScript-скрипты, чтобы ускорить обработку запросов и снизить нагрузку на веб-приложение. Кеширование помогает улучшить производительность и сократить время загрузки страниц для клиентов.
4. **Обработка SSL/TLS:** NGINX может обрабатывать защищенные соединения SSL/TLS, обеспечивая шифрование и безопасность передачи данных между клиентом и сервером. Это особенно важно для обеспечения безопасности личных данных пользователей.

### Структура Nginx (важные компоненты):
1. **Главный конфигурационный файл (`nginx.conf`):** Он является основным файлом конфигурации NGINX. Он содержит глобальные настройки, такие как общие параметры, модули, настройки рабочих процессов и ссылки на другие файлы конфигурации.
2. **Директория `sites-enabled`:** Это директория, в которой хранятся файлы конфигурации для виртуальных хостов (сайтов). Каждый файл конфигурации в этой директории представляет отдельный виртуальный хост и содержит настройки для этого сайта. Обычно файлы в этой директории симлинкованы с файлами конфигурации в директории `sites-available`.
3. **Директория `sites-available`:** В этой директории хранятся доступные для активации файлы конфигурации виртуальных хостов. Обычно файлы конфигурации в этой директории настраиваются для виртуальных хостов, но не активны по умолчанию. Файлы могут быть симлинкованы в директорию `sites-enabled` для активации.

Напишем конфиг, который будет раздавать `blue.html` страницу.

```nginx
server {
    listen 80;

    location / {
        root /var/www/html;
        index blue.html;
    }
}
```

1. `server { ... }`: Определяет новый блок конфигурации для сервера.
2. `listen 80;`: Задает порт, на котором сервер будет прослушивать входящие соединения. В данном случае, сервер будет слушать на порту 80.
3. `location / { ... }`: Определяет обработку запросов для конкретного местоположения (`/`), которое является корневым.
4. `root /var/www/html;`: Задает корневой каталог для сервера, где хранятся статические файлы. В данном случае, корневой каталог установлен в `/usr/share/nginx/html`.
5. `index blue.html;`: Определяет файл, который будет возвращен клиенту, если в запросе не указан конкретный файл. В данном случае, если клиент запрашивает корневой путь (`/`), NGINX вернет файл `blue.html` из указанного корневого каталога.

## Чекпоинты

### Подготовительная часть:
1. Создайте три виртуальные машины с Ubuntu Server в VirtualBox. Дайте им понятные имена:
   * `Blue-server`
   * `Yellow-server`
   * `balancer-server`
2. Настройте сеть. Для всех трёх ВМ в настройках VirtualBox выберите тип сетевого подключения "Сетевой мост" (Bridged Adapter). Это позволит им получить уникальные IP-адреса в вашей локальной сети, как если бы это были три отдельных физических компьютера.
3. Запустите все три ВМ.

### Практическая часть:

#### 1. Настройка веб-серверов
Вам нужно настроить первые две ВМ так, чтобы они отдавали статические HTML-страницы разного цвета.

* **На ВМ blue-server:**
  1. Подключитесь к терминалу ВМ.
  2. Установите Nginx.
  3. Создайте HTML-файл:
     ```bash
     echo '<body style="background-color: blue;"><h1>Blue Server</h1></body>' | sudo tee /var/www/html/blue.html
     ```
  4. Отредактируйте стандартный конфиг Nginx: `sudo vim /etc/nginx/sites-available/default`. Приведите блок `location /` к виду обработки всех запросов на `/` и отдаче файла `blue.html`.
  5. Перезапустите Nginx: `sudo systemctl restart nginx`.
  6. Узнайте IP-адрес этой машины: `ip a`. Запишите его.

* **На ВМ yellow-server:**
  1. Проделайте те же шаги, но для жёлтой страницы.
  2. Создайте HTML-файл:
     ```bash
     echo '<body style="background-color: yellow;"><h1>Yellow Server</h1></body>' | sudo tee /var/www/html/yellow.html
     ```
  3. Отредактируйте конфиг Nginx, указав `index yellow.html;`.
  4. Перезапустите Nginx и запишите IP-адрес этой ВМ.

#### 2. Настройка Балансировщика нагрузки
Теперь настроим третью ВМ, которая будет распределять запросы между первыми двумя.

**На ВМ balancer-server:**
1. Установите Nginx.
2. Отредактируйте основной конфигурационный файл: `sudo vim /etc/nginx/sites-available/default`, чтобы он включал в себя:
   a. Группы серверов (Upstream).
   b. Настройку специального формата логов.
   c. Настройку основного сервера-прокси.
3. Перезапустите Nginx: `sudo systemctl restart nginx`.
4. Узнайте IP-адрес самого балансировщика: `ip a`.

#### 3. Проверка работы
1. На вашем основном компьютере (не на ВМ) откройте браузер.
2. Перейдите по IP-адресу вашего `balancer-server`.
3. Обновляйте страницу несколько раз — фон должен меняться с синего на жёлтый.
4. Подключитесь к `balancer-server` по SSH и посмотрите логи, чтобы убедиться, что запросы распределяются:
   ```bash
   tail -f /var/log/nginx/access.log
   ```
   В логах вы увидите, на какой из IP-адресов (`blue` или `yellow`) был отправлен каждый запрос.

#### 4. Добавление Backup-сервера
Чтобы не создавать четвёртую ВМ, мы сымитируем backup-сервер на самой машине-балансировщике.

1. На ВМ `balancer-server`:
2. Создайте HTML-файл для бэкапа:
   ```bash
   echo '<body style="background-color: grey;"><h1>Backup Server</h1></body>' | sudo tee /var/www/html/grey.html
   ```
3. Снова откройте конфиг `sudo nano /etc/nginx/sites-available/default`.
4. Добавьте в него второй `server` блок, который будет служить локальным бэкапом:
   ```nginx
   # ... (весь предыдущий конфиг)
   # Добавляем этот блок в конец файла
   server {
       listen 8081; # Будет работать на другом порту
       location / {
           root /var/www/html;
           index grey.html;
       }
   }
   ```
5. Измените блок `upstream`, добавив в него этот локальный сервер как бэкап:
   ```nginx
   upstream backend {
       least_conn;
       server <IP_АДРЕС_BLUE_SERVER>;
       server <IP_АДРЕС_YELLOW_SERVER>;
       server 127.0.0.1:8081 backup; # Добавляем backup-сервер
   }
   ```
6. Перезапустите Nginx: `sudo systemctl restart nginx`.
7. **Проверка:** В VirtualBox выключите (Power Off) ВМ `blue-server` и `yellow-server`. Теперь, обновляя в браузере страницу по IP-адресу балансировщика, вы должны видеть серый фон.
