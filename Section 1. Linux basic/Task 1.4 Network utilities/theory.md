## Введение
Данное задание предназначено дать тебе базовые знания по работе с сетями в Linux. Если тебе интересно более углубленное изучение сетей, у нас есть отдельный курс предназначенный для изучения работы сетей и их настройки.

Начнем с базовых терминов:
1. **IP-адрес:** Уникальный идентификатор устройства в сети.
2. **Маска подсети:** Определяет, какая часть IP-адреса относится к сети, а какая — к узлу.
3. **DNS (Domain Name System):** Система, преобразующая доменные имена (например, `google.com`) в IP-адреса.
4. **DHCP (Dynamic Host Configuration Protocol):** Протокол, автоматически назначающий IP-адреса устройствам в сети.
5. **MAC-адрес:** Уникальный физический адрес сетевой карты.
6. **LAN (Local Area Network):** Локальная сеть (например, ваша домашняя сеть).
7. **WAN (Wide Area Network):** Глобальная сеть (например, интернет).
8. **Межсетевой экран (Firewall):** Система, контролирующая и фильтрующая сетевой трафик.

Также для лучшего понимания работы сети нам надо ознакомиться с такими понятиями как порт и протокол.

**Сетевой порт (англ. port)** — натуральное число (как правило, в диапазоне от 1 до 65 535), записываемое в заголовках протоколов транспортного уровня модели OSI, которое используется для определения процесса-получателя пакета в пределах одного хоста. Основная задача портов — обмен данными определенного типа, а также устранение неоднозначности, возникающей при попытке установить связь с хостом по его IP-адресу. Для передачи данных с веб-сервера необходимо указать IP-адрес хоста и номер порта.

**Сетевой протокол** — это набор правил, определяющий принципы взаимодействия устройств в сети. Чтобы отправка и получение информации прошли успешно, все устройства-участники процесса должны принимать условия протокола и следовать им.

Пришло время ознакомиться с основными утилитами в Linux для работы с сетью.

* `ping` — самая базовая команда для проверки доступности того или иного хоста. Также отмечу, что пинг — это команда, которая не имеет определенного порта, она работает просто поверх протокола ICMP.
* `traceroute` — еще одна полезная команда, используемая для диагностики сетей, которая показывает маршрут, по которому проходят пакеты от вашего устройства до целевого узла в сети. Она полезна для анализа сетевых проблем, поиска задержек и выяснения, какие промежуточные маршрутизаторы обрабатывают данные.
* `ifconfig` (`ipconfig` для Windows) — используется для вывода информации о всех сетевых интерфейсах на хосте. Она выведет тебе информацию о сетевых интерфейсах и их состояние. Именно с помощью нее ты сможешь определить текущий IP-адрес своего компьютера.

Также по умолчанию в Linux установлено две утилиты для управления межсетевым экраном на хосте. Это `iptables` и `ufw`.

* **iptables** — это утилита для настройки встроенного межсетевого экрана в Linux на уровне ядра, работает на основе таблиц и цепочек (chains). Основной недостаток iptables: сложность в использовании, именно поэтому был разработан ufw.
* **UFW (Uncomplicated Firewall)** — это упрощенный интерфейс для управления iptables, созданный для пользователей Ubuntu и других дистрибутивов Linux. В данной таске ты будешь работать именно с ufw.

Еще вспомним знакомую тебе команду `ssh`, у нее есть менее безопасный собрат, которым пользоваться не рекомендуется. Это `telnet`. Команда имеет точно такое же предназначение, однако она не обеспечивает шифрование данных при передаче, поэтому в случае перехвата данных можно будет увидеть передаваемую посредством telnet информацию. Порт telnet по умолчанию — 23.

Две последние сторонние утилиты, которые помогут тебе лучше диагностировать проблемы с сетью — это **Nmap** и **Wireshark**. У последней есть графический интерфейс.

* **Nmap («Network Mapper»)** — это утилита с открытым исходным кодом для исследования сети и проверки безопасности. Простыми словами это самый простой сетевой сканер, работающий на транспортном уровне модели OSI. С его помощью можно сканировать эндпоинты на наличие открытых портов. Это бывает полезно в случае когда тебе нужно провести аудит безопасности того или иного хоста (сети), а непосредственного доступа к настройкам межсетевых экранов нет. В случае же, если доступ к серверу есть, можно воспользоваться утилитами `netstat`/`ss` или `nc` (например `nc -zv`, `netstat`/`ss -tulpn`).
  > **Важная ремарка:** помни, что использование сетевых сканеров на неподконтрольных тобой хостах считается незаконным и неэтичным.
* **Wireshark** — это широко распространенный инструмент для захвата и анализа сетевого трафика, который активно используется как для образовательных целей, так и для устранения неполадок на компьютере или в сети. Wireshark работает практически со всеми протоколами модели OSI, обладает понятным для обычного пользователя интерфейсом и удобной системой фильтрации данных.

## Чекпоинты
1. Установите VirtualBox и Ubuntu Desktop (или Server) на свой компьютер.
2. Создайте две виртуальные машины (ВМ) с Ubuntu. Назовём их "Основной хост" и "Удалённый хост".
3. Настройте сеть. Для обеих ВМ в настройках VirtualBox выберите тип сетевого подключения "Сетевой мост" (Bridged Adapter). Это позволит вашим ВМ получить IP-адреса из той же сети, что и ваш основной компьютер, как если бы это были два отдельных физических компьютера в вашей домашней сети.
4. Запустите обе ВМ и убедитесь, что они имеют доступ друг к другу.
5. **Проверка доступа к интернету.** На основном хосте выполните команду `ping google.com`. Сохраните результат в файл.
6. **Отслеживание маршрута.** На основном хосте выполните `traceroute google.com`. Изучите вывод и сохраните его в файл.
7. **Определение IP-адресов.** На обоих хостах выполните команду `ip a`, чтобы узнать их IP-адреса и названия сетевых интерфейсов.
8. **Управление файрволом.** На удалённом хосте проверьте статус файрвола командой `sudo ufw status`. Если он активен, временно отключите его: `sudo ufw disable`.
9. **Анализ небезопасного трафика.**
   a. Установите Wireshark на основной хост: `sudo apt update && sudo apt install wireshark`.
   b. Установите Telnet-сервер на удалённый хост: `sudo apt install telnetd`.
   c. На основном хосте запустите Wireshark и начните захват трафика на вашем сетевом интерфейсе.
   d. С основного хоста подключитесь к удалённому по Telnet: `telnet <IP-адрес_удалённого_хоста>`. Вам будет предложено ввести логин и пароль от пользователя на удалённой машине.
   e. В активной Telnet-сессии введите простую команду, например, `uname -a`.
   f. Остановите захват трафика в Wireshark. Используя фильтр (например, `telnet`), найдите пакеты, относящиеся к вашей сессии. Проанализируйте их содержимое. Вы должны увидеть переданную команду и её вывод в открытом, нешифрованном виде.
10. **Анализ безопасного трафика.**
    a. Удалите Telnet-сервер с удалённого хоста: `sudo apt purge telnetd`.
    b. Повторите шаг 9, но на этот раз используйте SSH для подключения (`ssh user@<IP-адрес_удалённого_хоста>`). Проанализируйте трафик SSH в Wireshark. Сравните результат с Telnet. Вы увидите, что данные зашифрованы. Запишите свои выводы в файл.
11. **Настройка правил файрвола.**
    a. На удалённом хосте включите файрвол: `sudo ufw enable`.
    b. Добавьте правило, запрещающее все входящие подключения на порт SSH (22): `sudo ufw deny 22`.
    c. Попробуйте снова подключиться с основного хоста к удалённому по SSH. Соединение должно быть заблокировано. (Чтобы вернуть доступ, выполните на удалённом хосте `sudo ufw allow 22`).
12. **Сканирование портов.**
    a. Установите Nmap на основной хост: `sudo apt install nmap`.
    b. Просканируйте удалённый хост с основного: `nmap -p- <IP-адрес_удалённого_хоста>`.
    c. На удалённом хосте выполните команду `sudo ss -tuln`, чтобы увидеть все открытые порты "изнутри".
    d. Сравните выводы обеих команд и запишите их в файл. Проанализируйте сходство.
