# Практический конспект: Ссылки, Файловые системы (XFS) и LVM в Linux

## Чекпоинт 1: Работа с каталогами, файлами и ссылками (inodes)

### Рабочие команды

```bash
# Создание каталога и файла с содержимым
mkdir -p ~/test
echo "DevOps Lab Data" > ~/test/test_123

# Создание символической (мягкой) ссылки на каталог
ln -s ~/test /tmp/soft_link

# Копирование файла в /tmp через символическую ссылку
cp /tmp/soft_link/test_123 /tmp/

# Создание жесткой ссылки на файл в пределах одной файловой системы
ln /tmp/test_123 /tmp/hard_link

# Вывод общего, использованного и свободного количества inodes
df -i /tmp
```

### Разбор флагов и параметров

* `mkdir -p` — создает каталог вместе со всеми недостающими родительскими директориями; не выдает ошибку, если каталог уже существует.
* `ln -s <цель> <ссылка>` — создает символическую (мягкую) ссылку (`symbolic link`), которая хранит путь к целевому объекту и имеет собственный номер `inode`.
* `ln <цель> <ссылка>` — создает жесткую ссылку (`hard link`), которая указывает напрямую на тот же номер `inode` на диске (работает только в пределах одной файловой системы).
* `df -i` — отображает статистику использования индексных дескрипторов (`Inodes`, `IUsed`, `IFree`, `IUse%`) вместо дискового пространства в байтах.

**Пример использования:** `ls -li /tmp/test_123 /tmp/hard_link` — проверка номеров `inode` (первый столбец) и счетчика жестких ссылок (третий столбец) у связанных файлов.

## Чекпоинт 2: Разметка диска, XFS и расширение раздела «на лету»

### Рабочие команды

```bash
# 1. Создание таблицы разделов GPT и первичного раздела размером 2 ГБ на новом диске /dev/sdb
sudo parted -s /dev/sdb mklabel gpt
sudo parted -s /dev/sdb mkpart primary xfs 0% 2GiB

# 2. Форматирование раздела в файловую систему XFS
sudo mkfs.xfs /dev/sdb1

# 3. Монтирование раздела в /mnt и создание проверочного файла
sudo mount /dev/sdb1 /mnt
echo "Persistent file" | sudo tee /mnt/check.txt

# 4. Фиксация объема до расширения
df -hT /mnt

# 5. Расширение границ раздела /dev/sdb1 до 100% объема диска (3 ГБ)
sudo growpart /dev/sdb 1

# 6. Расширение файловой системы XFS на новое доступное пространство раздела
sudo xfs_growfs /mnt

# 7. Проверка сохранности файла и нового объема файловой системы
ls -la /mnt/check.txt
df -hT /mnt
```

### Разбор флагов и параметров

* `parted -s` — запуск утилиты разметки в скриптовом (неинтерактивном) режиме без лишних запросов подтверждения.
* `mklabel gpt` — инициализация современной таблицы разделов GUID Partition Table (GPT).
* `mkpart primary xfs 0% 2GiB` — создание раздела с выравниванием от начала диска (`0%`) до отметки `2GiB`.
* `mkfs.xfs` — создание высокопроизводительной журналируемой файловой системы XFS.
* `df -hT` — вывод занятого и свободного места в человекочитаемом формате (`-h`: ГБ/МБ) с обязательным указанием типа файловой системы (`-T`).
* `growpart /dev/sdb 1` — безопасное расширение 1-го раздела на диске `/dev/sdb` до конца свободного пространства (работает на смонтированных разделах без интерактивных предупреждений).
* `xfs_growfs /mnt` — увеличение размера файловой системы XFS до границ базового блочного устройства (выполняется строго по точке монтирования, уменьшение XFS не поддерживается).

### Разница в выводе `df -hT` до и после манипуляций

* **До расширения:** поле `Size` показывает `2.0G`, доступное место `Avail` — около `1.9G`.
* **После расширения:** поле `Size` увеличивается до `3.0G`, доступное место `Avail` — до `2.9G`, при этом созданный ранее файл `/mnt/check.txt` полностью сохраняется без потери данных.

**Пример использования:** `sudo parted /dev/sdb resizepart 1 100%` — интерактивный аналог `growpart` для изменения границ существующего раздела.

## Чекпоинт 3: Настройка, управление и масштабирование LVM

### Рабочие команды

```bash
# Шаг 2. Проверка исходного состояния дисков и подсистемы LVM
df -h
sudo pvs
sudo lvs
sudo vgs

# Шаг 3–4. Инициализация PV, создание VG на первом диске и нарезка двух равных LV
sudo pvcreate /dev/sdb /dev/sdc
sudo vgcreate vg_lab /dev/sdb
sudo lvcreate -l 50%FREE -n lv_first vg_lab
sudo lvcreate -l 100%FREE -n lv_second vg_lab

# Шаг 5. Форматирование обоих логических томов в XFS
sudo mkfs.xfs /dev/vg_lab/lv_first
sudo mkfs.xfs /dev/vg_lab/lv_second

# Шаг 6. Создание точек монтирования и подключение логических томов
sudo mkdir -p /mnt/vol1 /mnt/vol2
sudo mount /dev/vg_lab/lv_first /mnt/vol1
sudo mount /dev/vg_lab/lv_second /mnt/vol2

# Шаг 7. Фиксация состояния смонтированных томов
df -h

# Шаг 8. Добавление второго физического диска в существующую группу томов VG
sudo vgextend vg_lab /dev/sdc

# Шаг 9–10. Расширение первого LV на весь объем нового диска с одновременным расширением ФС
sudo lvextend -r -l +100%FREE /dev/vg_lab/lv_first

# Шаг 11. Фиксация итоговой конфигурации хранилища
df -h
sudo pvs
sudo lvs
sudo vgs
```

### Разбор флагов и параметров

* `pvs` / `vgs` / `lvs` — вывод кратких сводных таблиц по физическим томам (`Physical Volumes`), группам томов (`Volume Groups`) и логическим томам (`Logical Volumes`).
* `pvcreate` — запись метаданных LVM на блочные устройства для их использования в пуле хранения.
* `vgcreate <имя_vg> <устройство>` — создание группы томов и включение в нее первого физического диска.
* `lvcreate -l 50%FREE -n <имя_lv> <имя_vg>` — создание логического тома заданного имени (`-n`), занимающего ровно половину от свободных экстентов (`-l 50%FREE`) в группе. Следующий вызов с `-l 100%FREE` забирает оставшуюся половину.
* `vgextend <имя_vg> <устройство>` — расширение пула группы томов за счет добавления нового физического тома.
* `lvextend -r -l +100%FREE <путь_к_lv>` — увеличение логического тома на все доступные свободные экстенты в VG (`+100%FREE`), где флаг `-r` (`--resizefs`) автоматически вызывает `fsadm`/`xfs_growfs` для расширения файловой системы без размонтирования.

**Пример использования:** `echo "/dev/vg_lab/lv_first /mnt/vol1 xfs defaults 0 0" | sudo tee -a /etc/fstab` — добавление логического тома в `/etc/fstab` для автоматического монтирования после перезагрузки ОС.
