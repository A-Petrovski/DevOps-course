# Теоретические вопросы: Обработка текста и логов в Linux (Часть 1)

## 1. Различные способы обработки текста с помощью `awk`, `sed` и `cut`. Основные функции и возможности

В Linux обработка текста строится по принципу конвейера (Unix-way), где каждая утилита решает свой класс задач построчно:

| Утилита | Главная роль | Когда применять | Ключевые возможности |
| :--- | :--- | :--- | :--- |
| **`cut`** | Нарезка столбцов | Строго структурированный текст с четким одиночным разделителем (CSV, `/etc/passwd`). | Быстрое извлечение колонок по символам, байтам или полям. Не понимает регулярные выражения и множественные пробелы. |
| **`sed`** | Потоковый редактор | Поиск, замена, удаление и вставка строк по шаблонам. | Редактирование файлов «на лету» (включая перезапись через `-i`), работа с диапазонами строк и регулярными выражениями. |
| **`awk`** | Язык обработки данных | Сложный парсинг, фильтрация по условиям, математика и агрегация. | Автоматически делит строку на поля по любым пробелам, поддерживает переменные, циклы, массивы, условия `if/else` и блоки `BEGIN`/`END`. |

## 2. Использование команды `cut` для извлечения данных. Основные опции и флаги

Утилита `cut` вырезает указанные части из каждой строки входного файла или потока.

### Ключевые флаги:
- `-d 'символ'` (`--delimiter`) — задает разделитель полей (по умолчанию используется символ табуляции `TAB`).
- `-f список` (`--fields`) — указывает номера нужных столбцов. Поддерживает перечисления и диапазоны (`-f 1`, `-f 1,3,5`, `-f 2-4`, `-f 3-`).
- `-c список` (`--characters`) — вырезает определенные позиции символов в строке (например, `-c 1-10` возьмет первые 10 символов).
- `-b список` (`--bytes`) — вырезает данные по байтам (для ASCII совпадает с `-c`, но для кириллицы в UTF-8 может разрезать символ пополам).
- `--complement` — инвертирует выбор: выводит все столбцы или символы, **кроме** указанных.
- `-s` (`--only-delimited`) — подавляет вывод строк, в которых вообще не встретился заданный разделитель.

### Примеры:
```bash
# Вывести имена пользователей (1-е поле) и их оболочки (7-е поле)
cut -d ':' -f 1,7 /etc/passwd

# Вывести все поля, кроме второго (хэша пароля)
cut -d ':' --complement -f 2 /etc/passwd

# Взять первые 15 символов из каждой строки лога (обычно это дата и время)
cut -c 1-15 /var/log/syslog
```

## 3. Работа с Input & Output Redirections и Pipes

В Linux процессы общаются с внешним миром через стандартные потоки ввода-вывода. Перенаправления и конвейеры позволяют управлять маршрутизацией этих данных.

### Перенаправления (Redirections):
- `>` — перенаправляет стандартный вывод (`stdout`) в файл, **перезаписывая** его содержимое.
- `>>` — перенаправляет `stdout` в файл, **дописывая** данные в конец (append), не стирая старые записи.
- `<` — передает содержимое файла на стандартный ввод (`stdin`) программы.
- `<<EOF` (Here-Document) — передает многострочный блок текста из терминала или скрипта на `stdin` команды до встречи стоп-слова `EOF`.
- `<<< "строка"` (Here-String) — передает одну строку текста напрямую на `stdin` команды.

### Конвейеры (Pipes `|`):
Оператор `|` берет стандартный вывод (`stdout`) команды слева и напрямую передает его на стандартный ввод (`stdin`) команды справа без создания временных файлов на диске.

```bash
# Пример цепочки: чтение -> фильтрация -> нарезка -> сортировка -> подсчет уникальных -> топ-5
cat /var/log/nginx/access.log | grep " 404 " | cut -d ' ' -f 1 | sort | uniq -c | sort -nr | head -n 5
```

## 4. Работа и возможности языка программирования `awk`

`awk` — это полноценный интерпретируемый язык, ориентированный на обработку табличных и текстовых данных.

### Логика работы программы `awk`:
1. **`BEGIN { ... }`** — блок выполняется один раз **до** чтения первой строки файла (используется для инициализации переменных, задания разделителей и печати заголовков).
2. **`условие { действие }`** — основное тело; выполняется последовательно для каждой прочитанной строки, подходящей под условие.
3. **`END { ... }`** — блок выполняется один раз **после** обработки всех строк файла (используется для вывода итоговых сумм, средних значений и отчетов).

### Встроенные переменные:
- `$0` — вся текущая строка целиком.
- `$1, $2, ..., $NF` — 1-е, 2-е и последнее поля текущей строки.
- `NF` (Number of Fields) — количество столбцов в текущей строке.
- `NR` (Number of Records) — сквозной номер текущей обрабатываемой строки.
- `FS` (Field Separator) — разделитель входных полей (задается флагом `-F`).
- `OFS` (Output Field Separator) — разделитель полей при выводе (по умолчанию пробел).

### Примеры возможностей:
```bash
# Математический подсчет трафика (10-е поле в байтах) и перевод в МБ
awk '{sum += \$10} END {print "Total MB:", sum / 1024 / 1024}' /var/log/nginx/access.log

# Условия и форматированный вывод: найти пользователей с UID >= 1000
awk -F ':' '\$3 >= 1000 {printf "User: %-15s Shell: %s\n", \$1, \$7}' /etc/passwd
```

## 5. Использование утилиты `sed`. Основные команды и флаги

`sed` (Stream Editor) читает данные построчно в специальный буфер (Pattern Space), применяет к строке заданные инструкции и выводит результат.

### Ключевые флаги:
- `-i` (`--in-place`) — сохраняет изменения непосредственно в исходный файл. С суффиксом `-i.bak` предварительно создает резервную копию.
- `-E` (или `-r`) — включает поддержку расширенных регулярных выражений (ERE), избавляя от необходимости экранировать `+`, `?`, `()`, `{}` и `|`.
- `-n` (`--quiet`) — отключает автоматический вывод каждой строки (используется вместе с командой `p`, чтобы вывести только нужные строки).
- `-e` — позволяет передать несколько команд редактирования в одном запуске.

### Основные внутренние команды:
- `s/шаблон/замена/флаги` — замена текста (`g` — все вхождения в строке, `I` — без учета регистра).
- `d` — удаление строки, совпавшей с шаблоном или номером.
- `p` — печать строки (обычно в паре с `sed -n`).
- `a\текст` — добавление новой строки **после** найденной.
- `i\текст` — вставка новой строки **перед** найденной.
- `c\текст` — полная замена найденной строки новым текстом.

### Примеры:
```bash
# Удалить пустые строки и комментарии в конфиге
sed -E '/^\s*(#|\$)/d' /etc/nginx/nginx.conf

# Вывести только строки с 10-й по 20-ю
sed -n '10,20p' /var/log/syslog

# Заменить порт только в строке, содержащей "Port"
sed -i.bak '/^#Port 22/c\Port 2222' /etc/ssh/sshd_config
```

## 6. Регулярные выражения (Regex) в `awk` и `sed`

Регулярные выражения задают шаблон поиска. В обеих утилитах лучше использовать расширенный синтаксис (`sed -E`, в `awk` ERE работает по умолчанию).

### Основные конструкции:
- **Якоря позиции:**
  - `^` — начало строки.
  - `$` — конец строки.
  - `\b` — граница слова.
- **Классы символов:**
  - `.` — любой одиночный символ (кроме переноса строки).
  - `[0-9]` — любая цифра; `[a-zA-Z]` — любая латинская буква.
  - `[^0-9]` — любой символ, **кроме** цифры (отрицание внутри квадратных скобок).
  - `\s` — пробельный символ (пробел или табуляция).
- **Квантификаторы (количество повторений):**
  - `*` — 0 или более раз.
  - `+` — 1 или более раз.
  - `?` — 0 или 1 раз (необязательный элемент).
  - `{n,m}` — от `n` до `m` раз.
- **Группировка и экранирование:**
  - `(A|B)` — логическое ИЛИ (совпадение с `A` либо с `B`).
  - `\` — экранирование спецсимвола (например, `\.` ищет буквальную точку).

### Применение в `sed` и `awk`:
- **В `sed`:** используется внутри `/шаблон/` для поиска или в первой части команды `s/шаблон/замена/`. Поддерживает обратные ссылки (`\1`, `\2`) на группы в скобках `(...)`.
  ```bash
  # Поменять местами первое и второе слово в строке
  sed -E 's/^(\w+)\s+(\w+)/\2 \1/' file.txt
  ```
- **В `awk`:** используется оператор `~` (соответствует регулярке) и `!~` (не соответствует) для проверки конкретного поля или всей строки.
  ```bash
  # Найти строки, где 7-е поле (URL) заканчивается на .php или .html
  awk '\(7 ~ /\.(php\vert{}html)\)/ {print \$1, \$7}' access.log
  ```

## 7. Практическое применение `awk`, `sed` и `cut`

Комбинирование утилит позволяет автоматизировать рутинные задачи администрирования без написания тяжелых скриптов на Python.

### Примеры практических команд:
1. **Генерация списка активных системных пользователей с их UID и оболочками:**
   ```bash
   awk -F ':' '7 !~ /(nologin|false)/ {print \$1, \$3, \$7}' /etc/passwd | column -t
   ```
2. **Пакетная замена IP-адреса или домена в конфигурации:**
   ```bash
   sed -i.bak 's|://example.com|://example.com|g' /etc/nginx/sites-available/app.conf
   ```
3. **Извлечение значений переменных из `.env` файла (отбрасывая ключи и комментарии):**
   ```bash
   grep -v '^#' .env | cut -d '=' -f 2-
   ```
   *(Здесь `2-` гарантирует, что если внутри самого значения пароля или токена встретится знак `=`, он не обрежется).*

## 8. Файловые дескрипторы и перенаправление стандартных потоков

В Linux каждый открытый файл или поток процесса получает числовой идентификатор — **файловый дескриптор (File Descriptor, FD)**.

### Три базовых дескриптора:
- **`0` (`stdin`)** — стандартный ввод (клавиатура, файл или вывод предыдущей команды).
- **`1` (`stdout`)** — стандартный вывод (нормальный результат работы команды).
- **`2` (`stderr`)** — стандартный вывод ошибок (диагностические сообщения и сбои).

### Варианты перенаправления дескрипторов:
- **Разделение нормального вывода и ошибок:**
  ```bash
  ./backup.sh 1> backup.log 2> backup_errors.log
  ```
- **Объединение `stderr` и `stdout` в один файл:**
  ```bash
  ./deploy.sh > full_deploy.log 2>&1
  ```
  *Важен порядок: сначала `1` направляется в файл, затем `2` привязывается к текущему назначению `1` (`&1`). Современный сокращенный аналог в Bash: `&> full_deploy.log`.*
- **Передача и вывода, и ошибок дальше по конвейеру (`|`):**
  ```bash
  ./test_script.sh 2>&1 | grep -i "fail"
  ```
- **Игнорирование ошибок (отправка в `/dev/null`):**
  ```bash
  grep -rn "password" /etc/ 2>/dev/null
  ```
- **Одновременный вывод на экран и запись в файл (`tee`):**
  ```bash
  ./install.sh 2>&1 | tee -a install.log
  ```

## 9. Реальные сценарии использования в DevOps

### Сценарий 1: Анализ инцидента по логам веб-сервера (Nginx)
Задача: найти топ-10 IP-адресов, которые генерируют `502 Bad Gateway` или `504 Gateway Timeout`, чтобы выявить источник нагрузки или DDoS.
```bash
awk '9 ~ /⁵⁰/ {print \$1}' /var/log/nginx/access.log | sort | uniq -c | sort -nr | head -n 10
```

### Сценарий 2: Очистка и аудит конфигурационных файлов
Задача: быстро посмотреть действующие настройки SSH-демона без сотен строк комментариев и пустых отступов.
```bash
sed -E '/^\s*(#|\$)/d' /etc/ssh/sshd_config
```

### Сценарий 3: Мониторинг состояния дисков в Bash-скрипте
Задача: получить процент заполнения корневого раздела `/` в виде чистого числа для отправки алерта.
```bash
df -P / | awk 'NR==2 {gsub("%", "", \$5); if (\$5 > 85) print "ALERT: Disk usage is " \$5 "%"}'
```

### Сценарий 4: Разбор CSV-выгрузки или отчета
Задача: посчитать среднее время ответа (в миллисекундах, 4-я колонка CSV) для успешных запросов (3-я колонка равна `200`).
```bash
awk -F ',' '\$3 == 200 {sum += \$4; count++} END {if (count > 0) print "Avg ms:", sum/count}' metrics.csv
```

## 10. Рекомендации и Best Practices для производительности и точности

1. **Используйте правильный инструмент под задачу:**
   - Нужно просто вырезать колонку по одному символу-разделителю — берите `cut` (он работает в разы быстрее `awk`).
   - Нужно заменить текст по шаблону — берите `sed`.
   - Нужны условия, множественные пробелы как разделитель или математика — берите `awk`.
2. **Ускоряйте обработку больших логов через `LC_ALL=C`:**
   Утилиты `grep`, `sed`, `awk` и `sort` по умолчанию работают с учетом локали UTF-8, что замедляет парсинг гигабайтных логов. Установка переменной `LC_ALL=C` переключает их в побайтовый режим ASCII и ускоряет работу в 5–10 раз:
   ```bash
   LC_ALL=C grep "ERROR" huge_app.log | LC_ALL=C sort | uniq -c
   ```
3. **Не стройте лишних цепочек (`Useless Use of Cat` и лишний `grep`):**
   `awk` и `sed` умеют сами читать файлы и фильтровать строки по регуляркам.
   - Плохо: `cat file.log | grep "ERROR" | awk '{print $1}'`
   - Хорошо: `awk '/ERROR/ {print $1}' file.log`
4. **Всегда страхуйтесь при использовании `sed -i`:**
   Перед массовой заменой в конфигах сначала запустите `sed` **без** флага `-i`, чтобы увидеть результат в терминале, либо используйте `sed -i.bak` для создания резервной копии.
5. **Используйте альтернативные разделители в `sed`:**
   При работе с путями (`/var/www/...`) или URL меняйте стандартный `/` на `|` или `#` (`sed 's|/old/path|/new/path|g'`), чтобы избежать ошибок экранирования («синдрома падающих зубочисток» `\/\/`).
6. **Защищайте парсинг системных утилит:**
   Для `df` всегда добавляйте флаг `-P` (POSIX-вывод в одну строку), чтобы длинные названия файловых систем не ломали нумерацию столбцов в `awk`.
