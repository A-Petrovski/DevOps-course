# Практические задания: Сети, трафик, файрвол и сканирование портов

## 1–4. Подготовка стенда и настройка сети (VirtualBox)
- **Конфигурация ВМ:** Созданы две виртуальные машины — «Основной хост» (Ubuntu Desktop) и «Удалённый хост» (Ubuntu Server).
- **Сетевой режим:** Для обеих ВМ в настройках сети VirtualBox выбран тип подключения **Сетевой мост (Bridged Adapter)**, благодаря чему обе машины получили IP-адреса из одной локальной подсети (например, `192.168.1.18` и `192.168.1.19`) и видят друг друга напрямую.

## 5. Проверка доступа к интернету (`ping`)

### На основном хосте (Ubuntu Desktop):
```bash
ping -c 4 google.com > ping_result.txt
```
- `-c 4` — ограничение количества отправляемых ICMP-пакетов (4 запроса вместо бесконечного цикла).
- `>` — перенаправление вывода команды в новый файл (с перезаписью, если файл существует).
- **Пример использования:** `ping -c 5 192.168.1.18` — быстрая проверка связности с удалённым сервером.

## 6. Отслеживание маршрута (`traceroute`)

### На основном хосте (Ubuntu Desktop):
```bash
sudo apt install -y traceroute
traceroute -n google.com > traceroute_result.txt
```
- `-y` — автоматическое подтверждение установки пакета без запроса.
- `-n` — вывод IP-адресов промежуточных узлов без попытки определить их доменные имена (ускоряет работу команды).
- **Пример использования:** `traceroute -I google.com` — трассировка маршрута с использованием ICMP-пакетов вместо стандартных UDP.

## 7. Определение IP-адресов и сетевых интерфейсов (`ip`)

### На обоих хостах:
```bash
ip -c a
```
- `a` (сокращение от `address`) — вывод списка всех сетевых интерфейсов и назначенных им IPv4/IPv6-адресов (например, интерфейс `enp0s3` с адресом `192.168.1.18/24`).
- `-c` — цветовая подсветка вывода для удобного чтения.
- **Пример использования:** `ip -br a` — краткий табличный вывод только имён интерфейсов, их статусов (`UP`/`DOWN`) и IP-адресов.

## 8. Первичная проверка и отключение файрвола (`ufw`)

### На удалённом хосте (Ubuntu Server):
```bash
sudo ufw status
sudo ufw disable
```
- `status` — проверка текущего состояния файрвола (`active` или `inactive`) и списка активных правил.
- `disable` — временное отключение межсетевого экрана, чтобы он не блокировал тестирование открытых портов и служб.
- **Пример использования:** `sudo ufw status verbose` — подробный вывод состояния файрвола, включая политики по умолчанию для входящего и исходящего трафика.
## 9. Анализ небезопасного трафика (Wireshark и Telnet)

### На основном хосте (установка и фоновый запуск Wireshark):
```bash
sudo apt update && sudo apt install -y wireshark
sudo wireshark &
jobs
fg
```
- `&` — запуск программы в фоновом режиме с возвратом управления в терминал.
- `jobs` — просмотр списка фоновых задач в текущей сессии (позволяет увидеть статус `Stopped`, если `sudo` ждёт ввода пароля).
- `fg` — возврат фоновой задачи на передний план для интерактивного ввода пароля.
- **Пример использования:** `sudo usermod -aG wireshark $USER` — добавление текущего пользователя в группу `wireshark`, чтобы запускать захват пакетов без прав `sudo`.

### На удалённом хосте (установка и запуск Telnet-сервера):
```bash
sudo apt install -y telnetd inetutils-inetd
sudo systemctl enable --now inetutils-inetd
sudo systemctl restart inetutils-inetd
which telnetd || ls -l /usr/sbin/*telnetd*
grep -q "^telnet" /etc/inetd.conf || echo "telnet stream tcp nowait root /usr/sbin/tcpd /usr/sbin/telnetd" | sudo tee -a /etc/inetd.conf
```
- `enable --now` — одновременное включение службы в автозагрузку и её немедленный запуск.
- `restart` — перезапуск демона для применения изменений из файла конфигурации `/etc/inetd.conf`.
- `-q` (в `grep`) — тихий режим проверки наличия строки без вывода на экран.
- `-a` (в `tee`) — дописывание строки в конец системного файла без перезаписи содержимого.
- **Пример использования:** `sudo ss -tlnp | grep :23` — проверка того, что сервер начал прослушивать 23-й порт Telnet (`LISTEN`).

### На основном хосте и в Windows (подключение и перехват):
```bash
telnet 192.168.1.18
uname -a
```
```powershell
dism /online /Enable-Feature /FeatureName:TelnetClient
telnet 192.168.1.18
```
- `uname -a` — вывод полной информации о ядре и архитектуре удалённой ОС внутри сессии.
- `/online /Enable-Feature` — включение встроенного клиента Telnet в Windows через утилиту `DISM`.
- **Фильтры в Wireshark:** `telnet` или `ip.addr == 192.168.1.18 && tcp.port == 23` (правый клик по пакету → **Follow → TCP Stream**).
- **Вывод анализа:** Весь трафик Telnet передаётся в открытом виде (Cleartext) — видны логин, пароль, команда `uname -a` и ответ сервера.

## 10. Анализ безопасного трафика (SSH)

### На удалённом хосте (отключение и удаление Telnet):
```bash
sudo systemctl disable --now inetutils-inetd
sudo apt purge -y telnetd inetutils-inetd
```
- `disable --now` — остановка службы и удаление её из автозагрузки.
- `purge` — полное удаление пакетов вместе с конфигурационными файлами.

### На основном хосте (подключение по SSH и фиксация выводов):
```bash
ssh amp@192.168.1.18
uname -a
echo "Вывод: трафик SSH полностью зашифрован (протокол SSHv2), логин, пароль и команды недоступны для чтения в Wireshark." > ssh_analysis.txt
```
- **Фильтры в Wireshark:** `ssh` или `ip.addr == 192.168.1.18 && tcp.port == 22`.
- **Пример использования:** `ssh -p 2222 amp@192.168.1.18` — подключение по SSH при использовании нестандартного порта.

## 11. Настройка и откат правил файрвола (`ufw`)

### На удалённом хосте:
```bash
sudo ufw enable
sudo ufw deny 22
sudo ufw allow 22
sudo ufw delete deny 22
sudo ufw status numbered
```
- `enable` — включение файрвола и добавление его в автозагрузку.
- `deny 22` — блокировка входящих соединений на порт `22` путём отбрасывания пакетов (`DROP`), из-за чего клиент зависает по тайм-ауту.
- `allow 22` — разрешение входящего трафика на порт `22` для восстановления доступа.
- `delete deny 22` — удаление конкретного правила запрета из конфигурации файрвола.
- `status numbered` — вывод списка всех правил с порядковыми номерами для удобного удаления (`sudo ufw delete <номер>`).

## 12. Сканирование портов (`nmap` и `ss`)

### На основном хосте (внешнее сканирование):
```bash
sudo apt install -y nmap
nmap -Pn -T4 -p- 192.168.1.18 > report.txt
```
- `-p-` — сканирование всех 65 535 TCP-портов.
- `-Pn` — пропуск предварительной проверки доступности хоста (пинга), необходимой при активном `ufw`.
- `-T4` — ускоренный агрессивный шаблон таймингов для быстрых локальных сетей.
- **Пример использования:** `nmap -sV -p 22,23 192.168.1.18` — определение точных версий служб на выбранных портах.

### На удалённом хосте (внутренняя проверка сокетов) и сборка отчёта:
```bash
sudo ss -tuln
sudo ss -tulnp
ssh amp@192.168.1.18 "sudo ss -tuln" >> report.txt
```
- `-t` — отображение TCP-сокетов.
- `-u` — отображение UDP-сокетов.
- `-l` — вывод только прослушиваемых портов (`LISTEN`).
- `-n` — отображение номеров портов в числовом виде (без замены на имена служб).
- `-p` — отображение имени и PID процесса, занимающего порт.
- `>>` — дописывание вывода в конец существующего файла без удаления старых записей.

### Сравнение и анализ результатов:
- **Сходство:** Обе утилиты подтверждают, что порт `22` (SSH) открыт для внешних подключений (`0.0.0.0:22` в `ss` и `22/tcp open ssh` в `nmap`).
- **Различие:** Команда `ss -tuln` показывает состояние «изнутри», включая локальные службы на `127.0.0.x` (порт `53` DNS) и UDP-сокеты (порты `68`, `323`). Утилита `nmap` сканирует сервер «снаружи» по сети: не видит локальные порты, не сканирует UDP без флага `-sU`, а закрытые файрволом порты помечает как `filtered`.

## 13. Передача файлов по сети и работа с файлами отчётов (`scp`, `ssh`, `cat`, `history`)

### Копирование файлов между хостами (в обход ошибки SFTP):
```bash
scp -O amp@192.168.1.18:~/file_task_1_4_12.txt ~/file_task_1_4_12.txt
ssh amp@192.168.1.18 "cat ~/file_task_1_4_12.txt" > ~/file_task_1_4_12.txt
cat ~/file_task_1_4_12.txt | ssh amp@192.168.1.18 "cat > ~/file_task_1_4_12.txt"
```
- `-O` (в `scp`) — принудительное использование классического протокола SCP вместо подсистемы SFTP (решает ошибку `subsystem request failed on channel 0`).
- `|` (конвейер / pipe) — передача стандартного вывода одной команды на стандартный ввод другой (позволяет записывать файлы напрямую по `ssh`).
- **Пример использования:** `scp -O ~/report.txt amp@192.168.1.18:/tmp/` — отправка локального файла в директорию `/tmp` на удалённом сервере.

### Объединение файлов, выгрузка истории и очистка:
```bash
cat nmap_out.txt >> file_task_1_4_12.txt
history > history_1_4.txt
ls -lh history_1_4.txt
rm -f ~/report.txt
```
- `cat файл1 >> файл2` — безопасное добавление содержимого одного файла в конец другого (нельзя указывать один и тот же файл слева и справа во избежание бесконечного цикла).
- `history` — вывод списка выполненных команд в текущей оболочке с сохранением в текстовый файл.
- `-lh` (в `ls`) — вывод подробного списка файлов с человекочитаемым размером (`КБ`, `МБ`, `ГБ`).
- `-f` (в `rm`) — принудительное удаление файла без запроса подтверждения и без ошибки, если файл отсутствует.
