# Контрольные вопросы и разбор критериев (Task 3.3)

## 1. В чём разница между `diff-tool` и `merge-tool`?
* **diff-tool** предназначен только для **просмотра и анализа различий** между двумя состояниями (например, рабочим каталогом и последним коммитом или двумя версиями файла). В этом режиме открываются две панели (было / стало).
* **merge-tool** предназначен для **разрешения конфликтов слияния** и формирования единого итогового файла. Он использует трёхсторонний интерфейс (3-way merge), где объединяются локальная версия (`LOCAL`), удалённая версия (`REMOTE`) и общий предок (`BASE`) в итоговый файл (`MERGED`).

```bash
# Запуск просмотра различий (2 панели)
git difftool

# Запуск разрешения конфликта слияния (3 панели)
git mergetool
```

## 2. Как Git использует внешние инструменты (Meld)?
При вызове `git difftool` или `git mergetool` Git сам извлекает нужные версии файлов из своей базы объектов (`.git/objects`) во временные файлы во временной директории системы (`/tmp`), а затем запускает внешний бинарный файл (например, `meld`), передавая ему пути к этим файлам в качестве аргументов (`$LOCAL`, `$REMOTE`, `$BASE`, `$MERGED`). Когда пользователь сохраняет итоговый файл и закрывает окно Meld, Git считывает результат и удаляет временные файлы.

```bash
# Команда, которую Git формирует под капотом при вызове mergetool
meld "/tmp/file_LOCAL_123" "/tmp/file_MERGED_123" "/tmp/file_REMOTE_123" --output "/tmp/file_MERGED_123"
```

## 3. Когда Meld удобнее встроенных diff-инструментов IDE?
* **Сравнение произвольных директорий вне проекта:** IDE хорошо показывают diff только внутри открытого Git-репозитория, тогда как Meld позволяет за секунду сравнить два любых каталога на диске (например, `/etc/nginx` и резервную копию с сервера).
* **Работа без тяжеловесной IDE:** на серверах или рабочих станциях администраторов и DevOps-инженеров часто нет установленной IDE (VS Code, JetBrains), а лёгкий Meld запускается мгновенно из терминала.
* **Гибкий 3-way merge и вставка блоков:** Meld наглядно отрисовывает кривые линии связи между блоками кода и позволяет одной кнопкой с зажатым `Ctrl` не заменять блок, а вставлять его выше или ниже существующего.

```bash
# Сравнение системных конфигураций напрямую без создания проекта в IDE
meld /etc/systemd/system /backup/systemd/system
```

## 4. Когда Meld удобнее консольных утилит (`diff`, `vimdiff`)?
* **Сравнение больших деревьев каталогов:** вывод `diff -r` в терминале превращается в длинную простыню текста, в которой сложно отделить новые файлы от изменённых. Meld строит интерактивное дерево с фильтрами и цветовой индикацией.
* **Сложные множественные конфликты слияния:** при одновременном изменении десятков строк в одном файле чтение текстовых маркеров `<<<<<<<` / `>>>>>>>` в консоли или работа в `vimdiff` повышает риск случайно удалить нужный кусок кода. Визуальный перенос стрелками в Meld снижает вероятность человеческой ошибки.
* **Низкий порог входа:** Meld не требует знания специфических клавиатурных команд режимов редактирования и буферов (`:diffget`, `:diffput`), как `vimdiff`.

```bash
# Вместо анализа длинного вывода diff -ru dir1 dir2
meld dir1 dir2
```

## 5. Как настроить Meld для работы с Git?
Для интеграции достаточно прописать Meld в глобальной конфигурации Git в качестве инструмента по умолчанию для `diff` и `merge`, а также отключить лишние запросы подтверждения и создание `.orig`-файлов.

```bash
git config --global diff.tool meld
git config --global difftool.prompt false
git config --global merge.tool meld
git config --global mergetool.keepBackup false
```
