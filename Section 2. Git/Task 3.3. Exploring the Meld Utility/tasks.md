## 3.3.3 Установка и базовая настройка

### Выполнение задания
```bash
# Установка в Ubuntu / Debian
sudo apt update && sudo apt install -y meld

# Установка в Fedora / RHEL / CentOS
sudo dnf install -y meld

# Установка в macOS (через Homebrew)
brew install --cask meld

# Проверка версии и запуск из терминала в фоновом режиме
meld --version
meld &
```

### Разбор флагов и параметров
* `update` — обновляет локальный индекс пакетов в системе перед установкой.
* `install -y` — устанавливает указанный пакет, автоматически отвечая «да» (`yes`) на запрос подтверждения.
* `--cask` — указывает пакетному менеджеру Homebrew устанавливать графическое приложение macOS (GUI).
* `--version` — выводит установленную версию утилиты Meld в терминал.
* `&` — запускает процесс Meld в фоновом режиме, освобождая терминал для дальнейшего ввода команд.

### Нюансы и возможные ошибки
* При запуске `meld` по SSH без проброса X11/Wayland появится ошибка `Gtk-WARNING **: cannot open display`. Meld требует графического окружения (GUI).

**Пример использования:** `meld &`

## 3.3.4 Сравнение файлов

### Выполнение задания
```bash
# Создание тестовой рабочей директории и двух версий файла
mkdir -p ~/meld_lab && cd ~/meld_lab

cat << 'EOF' > version_a.txt
server_name: web-01
port: 80
debug: true
max_connections: 100
EOF

cat << 'EOF' > version_b.txt
server_name: web-01
port: 443
ssl_enabled: true
max_connections: 500
EOF

# Запуск визуального сравнения двух файлов
meld version_a.txt version_b.txt
```

### Разбор флагов и параметров
* `mkdir -p` — создает директорию и все недостающие родительские каталоги без ошибки, если папка уже существует.
* `cat << 'EOF' > file` — записывает многострочный текст в файл вплоть до разделителя `EOF` без подстановки переменных окружения.
* `meld file1 file2` — запускает Meld в режиме двухстороннего сравнения (`2-way diff`), располагая `file1` слева, а `file2` справа.

### Назначение элементов интерфейса и нюансы
* **Цветовая подсветка:**
  * *Зелёный* — строки добавлены в одной из версий (отсутствуют в другой).
  * *Синий* — строки изменены в обеих версиях.
  * *Красный* — конфликтные изменения (в режиме 3-way merge).
* **Стрелки на центральной разделительной полосе:** нажатие на чёрную стрелку переносит блок изменений из одного файла в другой. Зажатие клавиши `Ctrl` превращает стрелку в знак `+`, позволяя **вставить** блок выше/ниже существующего, а не перезаписать его.
* **Навигация:** кнопки со стрелками вверх/вниз на верхней панели (или `Alt + Up` / `Alt + Down`) быстро перемещают курсор между блоками отличий.
* Изменения не применяются к файлам на диске до тех пор, пока не нажата кнопка **Save** (`Ctrl + S`) в соответствующей панели.

**Пример использования:** `meld /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak`

## 3.3.5 Сравнение директорий

### Выполнение задания
```bash
# Создание структуры исходного проекта
mkdir -p project/config project/scripts
echo "APP_ENV=prod" > project/config/app.env
echo "DB_HOST=10.0.0.1" > project/config/db.env
echo "#!/bin/bash" > project/scripts/deploy.sh

# Создание полной копии проекта
cp -r project project_copy

# Внесение изменений в копию (изменение, добавление и удаление файлов)
echo "DB_HOST=10.0.0.2" > project_copy/config/db.env
echo "NEW_FEATURE=1" > project_copy/config/feature.env
rm project/scripts/deploy.sh

# Запуск сравнения директорий
meld project project_copy
```

### Разбор флагов и параметров
* `cp -r` — рекурсивное копирование (`--recursive`) директории вместе со всеми вложенными подкаталогами и файлами.
* `meld dir1 dir2` — запускает Meld в режиме сравнения деревьев каталогов.

### Назначение элементов интерфейса и нюансы
* **Фильтры отображения на верхней панели:**
  * `Same` (Одинаковые) — скрывает/показывает полностью идентичные файлы. Для анализа расхождений эту кнопку обычно отключают.
  * `New` (Новые) — показывает файлы, которые есть только в одной из директорий (выделяются зелёным цветом).
  * `Modified` (Изменённые) — показывает файлы с одинаковыми именами, но разным содержимым (выделяются синим цветом).
* Двойной клик по изменённому файлу в списке открывает его в новой вкладке для построчного сравнения содержимого.

**Пример использования:** `meld ./deploy_v1 ./deploy_v2`

## 3.3.6 Разрешение merge-конфликтов

### Выполнение задания
```bash
# Инициализация тестового Git-репозитория
mkdir -p ~/meld_git_lab && cd ~/meld_git_lab
git init -b main

# Создание базового файла и коммита
echo "timeout=30" > config.ini
git add config.ini
git commit -m "Initial commit"

# Создание ветки feature и изменение параметра
git checkout -b feature
echo "timeout=60" > config.ini
git commit -am "Set timeout to 60 in feature"

# Возврат в main и конфликтующее изменение той же строки
git checkout main
echo "timeout=120" > config.ini
git commit -am "Set timeout to 120 in main"

# Попытка слияния (вызовет merge-конфликт)
git merge feature

# Открытие конфликта в Meld напрямую (или через git mergetool)
meld config.ini
```

### Разбор флагов и параметров
* `git init -b main` — инициализирует новый репозиторий и задаёт имя основной ветки `main`.
* `git checkout -b feature` — создаёт новую ветку `feature` и сразу переключается на неё.
* `git commit -am` — добавляет все отслеживаемые изменённые файлы в индекс (`-a`) и создаёт коммит с сообщением (`-m`).
* `git merge feature` — вливает изменения из ветки `feature` в текущую ветку `main`.
* `meld config.ini` — при передаче одного файла с маркерами конфликта (`<<<<<<<`, `=======`, `>>>>>>>`) Meld автоматически открывает его в режиме трёхстороннего слияния.

### Нюансы и работа в режиме 3-way merge
* **Чтение conflict-markers:**
  * `<<<<<<< HEAD` — начало блока изменений из текущей ветки (`LOCAL`).
  * `=======` — разделитель между версиями.
  * `>>>>>>> feature` — конец блока изменений из вливаемой ветки (`REMOTE`).
* **Структура окон при 3-way merge (`git mergetool`):**
  * **Левая панель (`LOCAL`)** — версия из вашей текущей ветки.
  * **Центральная панель (`BASE` / `MERGED`)** — итоговый файл, который будет сохранён как результат разрешения конфликта.
  * **Правая панель (`REMOTE`)** — версия из вливаемой ветки.
* После переноса нужных строк в центральную панель необходимо сохранить её (`Ctrl + S`), закрыть Meld и завершить коммит слияния командой `git commit`.

**Пример использования:** `git mergetool -t meld`

## 3.3.7 Интеграция Meld с Git

### Выполнение задания
```bash
# Настройка Meld как стандартного инструмента просмотра различий (diff)
git config --global diff.tool meld
git config --global difftool.prompt false

# Настройка Meld как стандартного инструмента разрешения конфликтов (merge)
git config --global merge.tool meld
git config --global mergetool.meld.cmd 'meld "$LOCAL" "$MERGED" "$REMOTE" --output "$MERGED"'
git config --global mergetool.keepBackup false

# Проверка конфигурации и запуск инструментов
git config --global --list | grep -E "diff|merge"
git difftool
git mergetool
```

### Разбор флагов и параметров
* `git config --global` — записывает настройки в глобальный файл конфигурации пользователя (`~/.gitconfig`), применяя их ко всем репозиториям.
* `difftool.prompt false` — отключает интерактивный запрос Git `Launch 'meld' [Y/n]?` перед открытием каждого изменённого файла.
* `mergetool.keepBackup false` — запрещает Git сохранять временные резервные файлы с расширением `*.orig` после успешного разрешения конфликта.
* `--output "$MERGED"` — явно указывает Meld, в какой файл записывать результат слияния из центральной панели.
* `grep -E` — фильтрует вывод с использованием расширенных регулярных выражений.

### Нюансы и возможные ошибки
* Если не указать `mergetool.keepBackup false`, после выполнения `git mergetool` в рабочем каталоге останутся неотслеживаемые файлы `file.orig`, которые нужно удалять вручную или через `git clean -f`.
* Без флага `difftool.prompt false` при сравнении коммитов с десятками изменённых файлов Git будет запрашивать подтверждение в терминале перед открытием каждого файла.

**Пример использования:** `git difftool HEAD~1 HEAD`

## 3.3.8 Практический сценарий

### Выполнение задания
```bash
# 1. Подготовка эталонной (old) и новой (new) директорий конфигураций
mkdir -p ~/configs_audit/config_old ~/configs_audit/config_new
cd ~/configs_audit

cat << 'EOF' > config_old/nginx.conf
worker_processes 2;
keepalive_timeout 65;
server_tokens on;
EOF

cat << 'EOF' > config_new/nginx.conf
worker_processes auto;
keepalive_timeout 65;
server_tokens off;
EOF

echo "log_level = info" > config_old/app.conf
echo "log_level = debug" > config_new/app.conf
echo "secret_key = prod_key" > config_old/secrets.conf

# 2. Визуальный аудит и выборочный перенос изменений через Meld
meld config_old config_new

# 3. Фиксация списка изменённых файлов после переноса в отчёт
diff -rq config_old config_new > changes_report.txt
cat changes_report.txt
```

### Разбор флагов и параметров
* `diff -rq` — консольная проверка после работы в Meld: флаг `-r` (`--recursive`) сравнивает подкаталоги, а `-q` (`--brief`) выводит только названия различающихся или отсутствующих файлов без показа содержимого строк.
* `> changes_report.txt` — перенаправляет стандартный вывод (`stdout`) в файл отчёта.

### Нюансы безопасной работы с конфигурациями
* **Защита от потери данных:** перед переносом изменений из `config_new` в `config_old` всегда сохраняйте резервную копию (`cp -a config_old config_old.bak`), так как сохранение в Meld перезаписывает файл на диске без истории отката после закрытия программы.
* При переносе изменений из новой конфигурации в старую (например, `worker_processes auto;` и `server_tokens off;`) удобно использовать кнопку **Revert** (значок возврата на панели инструментов), если случайный перенос блока оказался ошибочным до сохранения.

**Пример использования:** `meld /etc/ssh /root/backup/etc/ssh`
