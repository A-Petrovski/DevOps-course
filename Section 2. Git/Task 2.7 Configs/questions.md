# Вопросы для самоконтроля: Task 2.7 Configs

### 1. Что такое файл `.gitconfig` и как он используется для настройки Git?
**Ответ:**
Файл `.gitconfig` — это текстовый конфигурационный файл в формате INI, который хранит пользовательские настройки Git (имя, почту, алиасы, параметры слияния, поведение веток и др.). Глобальный файл располагается в домашней директории пользователя (`~/.gitconfig`) и применяется ко всем репозиториям в системе, если для конкретного репозитория не заданы локальные переопределения (`.git/config`).

**Пример проверки текущего конфига:**
```bash
git config --list --show-origin
```

---

### 2. Как настроить глобальную конфигурацию Git с помощью команды `git config --global`?
**Ответ:**
Команда `git config --global` позволяет записывать, читать или удалять параметры напрямую в файле `~/.gitconfig` без его ручного открытия в текстовом редакторе. При первом запуске такой команды Git автоматически создает файл `~/.gitconfig`, если его еще не существовало.

**Пример настройки:**
```bash
git config --global user.name "Ivan Ivanov"
git config --global user.email "ivan@example.com"
git config --global core.editor "vim"
```

### 3. Какие параметры можно настраивать в файле `.gitconfig`?
**Ответ:**
В `.gitconfig` можно настроить практически любое поведение Git, сгруппированное по секциям:
- `[user]` — имя (`name`), почта (`email`) и ключ GPG-подписи (`signingkey`).
- `[core]` — текстовый редактор по умолчанию (`editor`), обработка окончаний строк (`autocrlf`), глобальный файл игнорирования (`excludesfile`).
- `[alias]` — сокращения (псевдонимы) для длинных команд Git.
- `[init]` — имя ветки по умолчанию при создании репозитория (`defaultBranch`).
- `[pull]` / `[push]` — стратегии слияния при получении изменений (`rebase`) и правила отправки веток (`autoSetupRemote`).
- `[include]` / `[includeIf]` — подключение внешних конфигурационных файлов.

**Пример фрагмента `.gitconfig`:**
```ini
[init]
    defaultBranch = main
[alias]
    st = status -sb
    lg = log --oneline --graph --all
[pull]
    rebase = true
```

### 4. Что такое подконфигурации в Git и как они используются для организации различных конфигураций для разных проектов или директорий?
**Ответ:**
Подконфигурации — это отдельные файлы настроек (например, `~/.gitconfig-work`), которые подключаются к основному `~/.gitconfig` с помощью директивы `[includeIf]`. Они позволяют автоматически подменять учетные данные, ключи или настройки Git в зависимости от пути к директории репозитория или текущей ветки. Это избавляет от необходимости вручную прописывать `git config --local` в каждом новом репозитории и защищает от случайных коммитов с личной почты в рабочие проекты.

**Пример настройки в `~/.gitconfig`:**
```ini
[user]
    name = Personal User
    email = personal@gmail.com

[includeIf "gitdir:~/work/"]
    path = ~/.gitconfig-work
```
