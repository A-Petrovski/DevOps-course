### 1. Проверка и создание файлов конфигурации

**Для Linux и Windows (Git Bash):**
```bash
cd ~
ls -la .gitconfig
touch .gitconfig .gitconfig-innowise
```

**Для Windows (PowerShell):**
```powershell
cd ~
Test-Path .gitconfig
ni .gitconfig-innowise
notepad .gitconfig
notepad .gitconfig-innowise
```

**Разбор команд и параметров:**
- `cd ~` — переход в домашнюю директорию текущего пользователя (`/home/user` в Linux или `C:\Users\<ИмяПользователя>` в Windows).
- `ls -la` — вывод списка всех файлов в директории, включая скрытые (начинающиеся с точки `.`).
- `touch` — создание пустых файлов в Linux / Git Bash (если файл уже существует, команда обновит время его изменения без перезаписи содержимого).
- `Test-Path` — командлет PowerShell для проверки существования файла (возвращает `True` или `False`).
- `ni` (`New-Item`) — аналог `touch` в PowerShell для создания нового файла.
- `notepad` — запуск стандартного текстового редактора Блокнот для создания и редактирования файла.

**Пример использования:**
```bash
git config --global --list --show-origin
```

### 2. Настройка основного файла `.gitconfig`

Добавьте в конец файла `~/.gitconfig` директиву условного подключения.

**Для Linux:**
```ini
[includeIf "gitdir:~/innowise/"]
    path = ~/.gitconfig-innowise
```

**Для Windows (с учетом нечувствительности к регистру):**
```ini
[includeIf "gitdir/i:~/innowise/"]
    path = ~/.gitconfig-innowise
```

**Разбор параметров и синтаксиса:**
- `[includeIf "..."]` — секция условного подключения внешнего конфигурационного файла.
- `gitdir:` — условие, проверяющее путь к директории `.git` текущего репозитория (с учетом регистра).
- `gitdir/i:` — условие, проверяющее путь без учета регистра символов (обязательно для Windows).
- `~/innowise/` — целевой каталог; завершающий прямой слэш `/` означает, что правило применится ко всем вложенным репозиториям внутри этой папки.
- `path = ~/.gitconfig-innowise` — путь к подключаемому файлу с дополнительными настройками.

**Пример использования:**
```ini
[includeIf "gitdir/i:D:/work/projects/"]
    path = ~/.gitconfig-work
```

### 3. Настройка рабочего конфига `.gitconfig-innowise`

Откройте файл `~/.gitconfig-innowise` и пропишите рабочие данные (сохранить в кодировке **UTF-8 без BOM**):

```ini
[user]
    name = Аркадий Паровозов
    email = arkadiy_parovozov@innowise-group.com
```

**Разбор параметров:**
- `[user]` — секция настроек идентичности автора коммитов.
- `name` — имя и фамилия автора, которые будут записываться в метаданные каждого коммита.
- `email` — рабочий адрес электронной почты, привязанный к корпоративному Git-серверу.

**Пример использования:**
```bash
git config -f ~/.gitconfig-innowise user.email "arkadiy_parovozov@innowise-group.com"
```

### 4. Создание репозитория и проверка коммита

**Для Linux и Windows (Git Bash):**
```bash
mkdir -p ~/innowise/test-repo
cd ~/innowise/test-repo
git init
echo "test" > README.md
git add README.md
git commit -m "Test commit"
git log -1
```

**Для Windows (PowerShell):**
```powershell
mkdir ~/innowise/test-repo
cd ~/innowise/test-repo
git init
"test" | Out-File -Encoding utf8 README.md
git add README.md
git commit -m "Test commit"
git log -1
```

**Разбор команд и флагов:**
- `mkdir -p` — создание директории вместе со всеми недостающими родительскими папками (`-p` в Bash; в PowerShell `mkdir` делает это по умолчанию).
- `git init` — инициализация нового пустого Git-репозитория (создание скрытой папки `.git`).
- `git add` — добавление файла в индекс (область подготовленных к коммиту изменений).
- `git commit -m` — фиксация изменений в истории репозитория с указанием сообщения коммита через флаг `-m` (`--message`).
- `git log -1` — вывод информации о последнем коммите (флаг `-1` ограничивает вывод одной записью), включая строку `Author:`.

**Пример использования:**
```bash
git config --show-origin user.email
```

### Разбор ошибок и нюансов работы в Windows

1. **Ошибка `touch : The term 'touch' is not recognized` в PowerShell:**
   - **Причина:** Команда `touch` относится к UNIX-утилитам и отсутствует в стандартном Windows PowerShell.
   - **Решение:** Использовать PowerShell-командлет `ni <имя_файла>`, открывать файл напрямую через `notepad <имя_файла>` или переключить вкладку терминала на **Git Bash**.
2. **Обратные и прямые слэши в путях Windows:**
   - В синтаксисе `.gitconfig` необходимо использовать только прямые слэши (`/`), даже если папка находится на другом диске (например, `D:/projects/innowise/`). Обратный слэш `\` воспринимается Git как символ экранирования.
3. **Кодировка кириллицы:**
   - При редактировании `.gitconfig-innowise` на Windows файл должен быть сохранен в кодировке **UTF-8**, иначе в истории `git log` имя «Аркадий Паровозов» отобразится некорректно.
