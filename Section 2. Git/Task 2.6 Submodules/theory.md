## Введение

Представим, что ты разрабатываешь Wordpress сайт, который состоит из:
- Плагинов и твоего личного кода, которые и образуют этот сайт.
- Основная кодовая база Wordpress.

И тут ты сталкиваешься с дилеммой под названием “скачать-вставить”, ведь именно так до этого ты добавлял кодовую базу в репозиторий с сайтом. Но знакомые подсказали про такую штуку как сабмодули. Теперь твоя задача попробовать эти сабмодули и избавиться от постоянной халтуры с переносом содержимого из одного репозитория в другой.

## Что такое сабмодули в Git

В общем, сабмодули в git позволяют сохранить репозиторий git в качестве подкаталога другого репозитория git. Сабмодуль — это просто ссылка на другой репозиторий в определенный момент времени. Сабмодули git имеет смысл использовать, если необходимо обеспечить строгое управление версиями внешних зависимостей.

## Ситуации для использования подмодулей Git

Ниже приводится несколько ситуаций, в которых использование подмодулей git наиболее уместно:

- **Внешний компонент или подпроект изменяются слишком быстро, или предстоящие изменения могут нарушить работу API.** В этом случае можно заблокировать код для конкретного коммита в целях безопасности.
- **Поддержание проекта в актуальном состоянии:** Если ты используешь проект с открытым исходным кодом в качестве зависимости в своем проекте, можешь включить его в качестве сабмодуля, чтобы было проще следить за изменениями, вносимыми в исходный репозиторий.
- **Управление связанными проектами:** Если у тебя есть несколько связанных проектов, которые управляются как отдельные репозитории Git, ты можешь включить их в качестве сабмодулей в основной репозиторий, чтобы отслеживать их взаимосвязи и версии.
