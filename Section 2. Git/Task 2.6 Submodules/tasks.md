### 1. Создание репозитория, добавление сабмодуля и фиксация версии

**Рабочие команды (Linux / Git Bash / PowerShell):**
```bash
mkdir git-submodules && cd git-submodules
git init
git submodule add https://github.com wordpress
cd wordpress
git fetch -a --tags
git tag
git checkout 3.4.2
cd ..
git add .
git commit -m "Add WordPress 3.4.2 submodule"
```

**Разбор использованных флагов и параметров:**
- `mkdir` / `cd` — создание новой директории проекта и переход в неё.
- `git init` — инициализация нового пустого локального репозитория Git.
- `git submodule add <URL> <путь>` — подключение внешнего Git-репозитория в указанную подпапку (`wordpress`) с автоматическим созданием служебного файла `.gitmodules`.
- `git fetch -a --tags` — загрузка всех веток и меток (тегов) с удалённого репозитория без их слияния с текущей рабочей директорией (`-a` / `--all` — все удалённые репозитории, `--tags` — все теги).
- `git tag` — вывод списка всех доступных тегов в репозитории.
- `git checkout 3.4.2` — переключение рабочей директории сабмодуля на коммит, соответствующий тегу `3.4.2` (переводит репозиторий в состояние `detached HEAD`).
- `git add .` — добавление в индекс файла `.gitmodules` и ссылки на конкретный коммит сабмодуля.
- `git commit -m "..."` — фиксация состояния сабмодуля в истории основного репозитория.

**Нюансы и частые ошибки:**
- **Опечатка в условии:** В задании указан тег `11 3.4.2`, но в реальном репозитории WordPress тег называется `3.4.2`.
- **Навигация по списку тегов:** При выполнении `git tag` открывается постраничный просмотрщик `less`. Для листания используются стрелки `↑`/`↓` и `Пробел`, для поиска — `/3.4` + `Enter`, для выхода обратно в консоль — клавиша `q`.

**Пример использования:**
```bash
git tag -l "3.4*"
```

### 2. Копирование нужных файлов из сабмодуля

**Рабочие команды (Linux / Git Bash):**
```bash
cp wordpress/index.php index.php
cp wordpress/wp-config-sample.php wp-config.php
cp -Rf wordpress/wp-content .
```

**Рабочие команды (Windows PowerShell):**
```powershell
cp wordpress/index.php index.php
cp wordpress/wp-config-sample.php wp-config.php
cp -Recurse -Force wordpress/wp-content .
```

**Разбор использованных флагов и параметров:**
- `cp` — копирование файлов и директорий (в PowerShell это псевдоним командлета `Copy-Item`).
- `-R` (или `-Recurse` в PowerShell) — рекурсивное копирование каталога со всеми вложенными подкаталогами и файлами.
- `-f` (или `-Force` в PowerShell) — принудительное копирование с перезаписью существующих файлов без запроса подтверждения.
- `.` — обозначение текущей директории как места назначения.

**Нюансы и частые ошибки:**
- **Ошибка `ParameterBindingException` в PowerShell:** В Windows PowerShell команда `cp` не поддерживает Linux-флаги `-Rf` (выдаёт ошибку `A parameter cannot be found that matches parameter name 'Rf'`). Также нельзя забывать точку `.` в конце команды, иначе система не поймёт, куда копировать папку. Используйте полные флаги `-Recurse -Force` или переключите терминал на **Git Bash**.

**Пример использования:**
```bash
cp -Rf wordpress/wp-content/themes/twentyeleven wp-content/themes/
```

### 3. Очистка от ненужных файлов

**Рабочие команды (Linux / Git Bash):**
```bash
rm -Rf wp-content/plugins/hello.php wp-content/themes/twentyten
```

**Рабочие команды (Windows PowerShell):**
```powershell
rm -Recurse -Force wp-content/plugins/hello.php, wp-content/themes/twentyten
```

**Разбор использованных флагов и параметров:**
- `rm` — удаление файлов и каталогов (в PowerShell это псевдоним командлета `Remove-Item`).
- `-R` / `-Recurse` — рекурсивное удаление директории вместе со всем её содержимым.
- `-f` / `-Force` — принудительное удаление без запросов подтверждения и игнорирование атрибутов «только для чтения».

**Нюансы и частые ошибки:**
- В Windows PowerShell при перечислении нескольких объектов для удаления в одной команде `rm` их необходимо разделять запятой (`,`), а не просто пробелом, как в Bash.

**Пример использования:**
```bash
rm -rf wp-content/plugins/*.txt
```

### 4. Настройка взаимодействия файлов с сабмодулем

**Рабочие команды (Linux / Git Bash — автоматическая замена):**
```bash
sed -i "s|require('./wp-blog-header.php');|require('wordpress/wp-blog-header.php');|g" index.php
```

**Рабочие команды (Windows PowerShell — автоматическая замена):**
```powershell
(Get-Content index.php) -replace "require\('\./wp-blog-header\.php'\);", "require('wordpress/wp-blog-header.php');" | Set-Content index.php
```

**Итоговое содержимое 17-й строки файла `index.php`:**
```php
require('wordpress/wp-blog-header.php');
```

**Разбор использованных флагов и параметров:**
- `sed -i` — потоковый текстовый редактор; флаг `-i` (`--in-place`) сохраняет изменения непосредственно в исходный файл.
- `s|старое|новое|g` — команда подстановки (`substitute`) с разделителем `|`, заменяющая старый путь на новый по всему файлу (`g` — global).
- `Get-Content` / `Set-Content` — командлеты PowerShell для чтения содержимого файла в память и перезаписи файла после применения регулярного выражения `-replace`.

**Нюансы и частые ошибки:**
- В WordPress 3.4.2 в 17-й строке `index.php` по умолчанию прописан относительный путь `require('./wp-blog-header.php');`. Так как ядро WordPress теперь изолировано в подкаталоге `wordpress/`, путь необходимо скорректировать, чтобы точка входа находила загрузчик.

**Пример использования:**
```bash
grep -n "wp-blog-header.php" index.php
```

### 5. Фиксация изменений коммитом и отправка в удалённый репозиторий

**Рабочие команды:**
```bash
git status
git add index.php wp-config.php wp-content
git commit -m "Copy WordPress core files and configure index.php"
git remote add origin https://github.com<username>/<repo-name>.git
git branch -M main
git push -u origin main
```

**Разбор использованных флагов и параметров:**
- `git status` — проверка состояния рабочей директории (убеждаемся, что скопированные файлы видны как `Untracked files`, а сабмодуль не помечен как модифицированный).
- `git add` — добавление подготовленных файлов и директорий сайта в индекс (staging area).
- `git commit -m "..."` — создание коммита с описанием проделанной работы.
- `git remote add origin <URL>` — привязка локального репозитория к удалённому серверу под стандартным именем `origin`.
- `git branch -M main` — переименование текущей основной ветки в `main` (актуально, если по умолчанию создалась ветка `master`).
- `git push -u origin main` — отправка локальных коммитов на удалённый сервер; флаг `-u` (`--set-upstream`) связывает локальную ветку с удалённой для последующего использования `git push` без аргументов.

**Нюансы и частые ошибки:**
- Важно понимать, что в основной репозиторий попадают только `.gitmodules`, ссылка на конкретный хеш коммита сабмодуля и ваши собственные файлы (`index.php`, `wp-config.php`, `wp-content`). Сами исходники ядра WordPress в основной репозиторий не дублируются.

**Пример использования:**
```bash
git clone --recurse-submodules https://github.com<username>/<repo-name>.git
```
