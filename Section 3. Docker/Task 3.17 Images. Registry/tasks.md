## 1. Развертывание локального Registry

Запускаем официальный контейнер реестра второй версии (`registry:2`) и проверяем доступность его REST API.

```bash
# Запуск контейнера локального registry
docker run -d -p 5000:5000 --restart=always --name registry registry:2

# Проверка доступности API хранилища
curl -i http://localhost:5000/v2/_catalog
```

### Разбор параметров и флагов:
* `docker run` — создание и запуск нового контейнера.
* `-d` (`--detach`) — запуск контейнера в фоновом режиме.
* `-p 5000:5000` (`--publish`) — проброс порта `5000` хоста на стандартный порт службы registry `5000` внутри контейнера.
* `--restart=always` — политика перезапуска: контейнер будет автоматически подниматься при падении или перезагрузке демона Docker / сервера.
* `--name registry` — присвоение читаемого имени контейнеру.
* `registry:2` — имя и тег официального образа Docker Registry v2.
* `curl -i` — выполнение HTTP-запроса с выводом заголовков ответа сервера (ожидается статус `HTTP/1.1 200 OK`, заголовок `Docker-Distribution-Api-Version: registry/2.0` и тело `{"repositories":[]}`).

### Нюансы и подводные камни:
* **Потеря данных без Volume:** По умолчанию `registry:2` сохраняет слои и манифесты внутри контейнера в директорию `/var/lib/registry`. При удалении контейнера (`docker rm -f registry`) все загруженные образы будут потеряны. Для постоянного хранения необходимо монтировать том: `-v /opt/registry:/var/lib/registry`.

**Пример использования:**
```bash
docker run -d -p 5000:5000 --restart=always --name registry -v registry_data:/var/lib/registry registry:2
```

## 2. Подготовка контекста и сборка образа `gocalc`

Копируем директорию с исходным кодом проекта `gocalc` в рабочую папку текущей задачи и собираем образ с префиксом адреса локального реестра.

```bash
# Копирование директории gocalc из предыдущего задания в текущую папку
cp -r ../task14/gocalc/ .
cd gocalc

# Сборка образа с указанием адреса и порта локального registry
docker build -t localhost:5000/gocalc:v1 .
```

### Разбор параметров и флагов:
* `cp -r` — рекурсивное копирование директорий со всем вложенным содержимым.
* `docker build` — сборка Docker-образа из `Dockerfile`.
* `-t localhost:5000/gocalc:v1` (`--tag`) — задание имени и тега образа. Префикс `localhost:5000/` указывает демону Docker, что образ относится к локальному реестру на порту `5000`, а не к Docker Hub.
* `.` — путь к контексту сборки (текущая директория `~/task17/gocalc`, где лежат `Dockerfile` и `main.go`).

### Разбор ошибок и нюансов из практики:
* **Ошибка при копировании `cp: '.' and './.' are the same file`:** Возникает, если случайно поставить лишний пробел и точку в конце команды (`cp -r ../task14/gocalc/ . .`). Утилита `cp` воспринимает первую точку как дополнительный источник копирования в саму себя, но при этом успешно копирует папку `gocalc` в текущую директорию.
* **Копирование содержимого vs копирование самой папки:**
  * `cp -r /src/dir /dst/` создаст `/dst/dir/...`.
  * `cp -r /src/dir/. /dst/` скопирует только содержимое `/src/dir` (включая скрытые файлы, начинающиеся с `.`) прямо в корень `/dst/`.
* **Тегирование без пересборки:** Если образ `gocalc:v1` уже был собран ранее, создавать физическую копию слоев не нужно — достаточно добавить новый указатель через `docker tag gocalc:v1 localhost:5000/gocalc:v1` (оба тега будут иметь одинаковый `IMAGE ID`).

**Пример использования:**
```bash
docker tag gocalc:latest localhost:5000/gocalc:latest
```

## 3. Загрузка образа в локальный Registry и проверка

Отправляем собранный образ в локальное хранилище, убеждаемся в его появлении через API и проверяем корректность скачивания на «чистом» локальном кэше.

```bash
# Отправка образа в локальный registry
docker push localhost:5000/gocalc:v1

# Проверка списка репозиториев в registry через REST API
curl http://localhost:5000/v2/_catalog

# Удаление локального образа и тестовое скачивание из локального registry
docker rmi localhost:5000/gocalc:v1
docker pull localhost:5000/gocalc:v1
```

### Разбор параметров и флагов:
* `docker push` — отправка слоев и манифеста образа в указанный registry (передаются только отсутствующие на сервере слои).
* `/v2/_catalog` — эндпоинт Registry HTTP API v2, возвращающий JSON со списком всех загруженных репозиториев (`{"repositories":["gocalc"]}`).
* `docker rmi` — удаление локального тега или образа из кэша хоста.
* `docker pull` — загрузка образа из registry на локальный хост.

### Нюансы и подводные камни:
* **Работа по HTTP без TLS:** По умолчанию Docker требует HTTPS для работы с любыми реестрами. Адрес `localhost` и подсеть `127.0.0.0/8` являются встроенными исключениями в Docker Engine, поэтому `push` на `localhost:5000` работает по обычному HTTP. При обращении по IP-адресу соседней машины в сети потребуется добавить адрес в `"insecure-registries"` в `/etc/docker/daemon.json` и перезапустить службу Docker.
* **Поведение `docker rmi` при наличии нескольких тегов:** Если на один `IMAGE ID` ссылаются два тега (`gocalc:v1` и `localhost:5000/gocalc:v1`), команда `docker rmi` удалит только указанный тег (`Untagged: ...`). Физическое удаление слоев с диска произойдет только после удаления последнего тега.

**Пример использования:**
```bash
# Просмотр списка всех тегов конкретного репозитория в локальном registry
curl http://localhost:5000/v2/gocalc/tags/list
```

## 4. Дополнительная практика: Аутентификация в Registry (`docker login`)

Настройка защищенного локального реестра с базовой аутентификацией (`htpasswd`) и безопасная авторизация через `stdin`.

```bash
# Генерация файла учетных данных htpasswd с помощью одноразового контейнера httpd
mkdir -p ~/auth
docker run --rm --entrypoint htpasswd httpd:2 -Bbn admin MySecretPass > ~/auth/htpasswd

# Запуск защищенного registry на порту 5001
docker run -d -p 5001:5000 --name secure-registry   -v ~/auth:/auth   -e "REGISTRY_AUTH=htpasswd"   -e "REGISTRY_AUTH_HTPASSWD_REALM=Registry Realm"   -e "REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd"   registry:2

# Безопасная авторизация без сохранения пароля в истории bash
echo "MySecretPass" | docker login localhost:5001 -u admin --password-stdin

# Проверка сохраненной конфигурации авторизации
cat ~/.docker/config.json
```

### Разбор параметров и флагов:
* `--rm` — автоматическое удаление временного контейнера `httpd:2` сразу после генерации хэша пароля.
* `--entrypoint htpasswd` — переопределение стартовой команды контейнера для вызова утилиты `htpasswd`.
* `-Bbn` — флаги `htpasswd`: использовать шифрование `bcrypt` (`-B`), пакетный режим передачи пароля в аргументе (`-b`), вывод результата в `stdout` вместо записи в файл (`-n`).
* `-e "REGISTRY_AUTH=htpasswd"` — включение базовой аутентификации в официальном образе `registry:2`.
* `--password-stdin` — чтение пароля из стандартного потока ввода (`stdin`), чтобы избежать утечки пароля в `~/.bash_history` и списке процессов `ps`.

**Пример использования:**
```bash
# Удаление сохраненных учетных данных для конкретного реестра
docker logout localhost:5001
```
