## Формирование размера образа
* Размер итогового образа складывается из размеров всех входящих в него слоев.
* Размер каждого слоя напрямую зависит от операций, которые выполняются внутри инструкций `Dockerfile`.
* Один из методов уменьшения объема (актуальный для компилируемых пакетов) — сборка приложения в одном образе, а использование готового артефакта в другом (Multi-stage).

## Влияние директив Dockerfile на вес слоев
* **Метаданные (`ENV`, `ARG`, `VOLUME`):** практически не занимают места (0B), если не передавать в переменные гигантские объемы текста.
* **Файловые операции (`COPY`, `ADD`):** увеличивают размер образа строго пропорционально объему копируемых файлов.
* **Выполнение команд (`RUN`):** в конечный объем слоя попадают **только те изменения файловой системы, которые остались к моменту завершения работы этой директивы**.

## Очистка мусора внутри одной директивы RUN
Если установить пакеты, скачать архивы, распаковать их и удалить исходные архивы вместе с ненужными утилитами **внутри одной инструкции `RUN`** (через логическое `&&`), они не попадут в финальный слой:

```dockerfile
RUN apk add curl \
    && curl -SsL https://nodejs.org/dist/v$NODE_VERSION/node-v$NODE_VERSION-linux-x64.tar.gz -o /tmp/node.tgz \
    && tar -xzf /tmp/node.tgz -C /usr/local --strip-components=1 \
    && rm /tmp/node.tgz \
    && apk del curl
```
* **Разбор команды и флагов:**
  * `apk add <пакет>` — установка утилит в Alpine Linux.
  * `curl -SsL <URL> -o <путь>` — скачивание файла в тихом режиме (`-s`), с выводом ошибок (`-S`), следованием за редиректами (`-L`) и сохранением в указанный файл (`-o`).
  * `tar -xzf <архив> -C <директория> --strip-components=1` — распаковка (`-x`) gzip-архива (`-z`) из файла (`-f`) в целевую папку (`-C`) с отбрасыванием корневой вложенной папки архива (`--strip-components=1`).
  * `rm <файл>` — удаление временного архива до фиксации слоя.
  * `apk del <пакет>` — удаление утилиты (`curl`), которая требовалась только на этапе сборки.

## Объединение директив RUN и порядок COPY
* Если разбить установку пакета (`RUN apk add sed`) и его последующее удаление (`RUN apk del sed`) на **разные** инструкции `RUN`, то в первом слое пакет сохранится навсегда, а второй слой лишь скроет его поверх, добавив служебный вес (диффы файловой системы).
* Чтобы максимально сжать образ, директивы `COPY` для файлов, подлежащих модификации, выносят выше, а все команды установки, обработки и очистки объединяют в один `RUN`.
