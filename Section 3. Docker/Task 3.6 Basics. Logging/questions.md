## 1. Роль команды `logs` в работе с контейнерами

**Вопрос:** Какую информацию можно получить из логов контейнеров с помощью команды `docker logs`?

**Ответ:** Команда `docker logs` извлекает и выводит в терминал все сообщения, которые главный процесс контейнера (PID 1) отправил в стандартный поток вывода (`stdout`) и стандартный поток ошибок (`stderr`) с момента запуска контейнера (или в рамках текущего цикла ротации). С её помощью можно отслеживать ход инициализации приложения, входящие сетевые запросы (например, access-логи веб-серверов) и причины аварийного завершения контейнера без подключения внутрь через `docker exec`.

**Пример:**
```bash
docker logs inno-dkr-06-local
```

## 2. Основные флаги и параметры команды `docker logs`

**Вопрос:** Какие флаги и параметры могут быть использованы с этой командой?

**Ответ:** Помимо стандартных флагов потока и фильтрации (`-f`, `--tail`, `--since`, `-t`), команда поддерживает ограничения по верхней границе времени и деталям вывода:
* `-f` / `--follow` — непрерывное отслеживание новых записей в реальном времени.
* `--tail N` (или `-n N`) — вывод последних `N` строк журнала.
* `--since <время>` — вывод записей, созданных после указанной даты или временной дельты.
* `--until <время>` — вывод записей, созданных до указанной даты или временной дельты.
* `-t` / `--timestamps` — добавление временной метки к каждой строке лога.
* `--details` — отображение дополнительных атрибутов, переданных драйверу логирования (например, переменных окружения или меток через `--log-opt labels`).

**Пример:**
```bash
docker logs --since 30m --until 5m --tail 100 -t inno-dkr-06-local
```

## 3. Отображение логов в реальном времени с помощью флага `-f`

**Вопрос:** Как флаг `-f` позволяет подключаться к логам контейнера и выводить их по мере поступления? Какой аналог он имеет среди стандартных команд в Unix-подобных системах?

**Ответ:** При запуске с флагом `-f` (`--follow`) CLI-клиент Docker не закрывает соединение с демоном после вывода текущих логов, а подписывается на поток событий контейнера и печатает каждую новую строку сразу после её записи приложением (выход осуществляется по `Ctrl+C`, при этом сам контейнер продолжает работать). В Unix-подобных системах прямым аналогом является стандартная утилита **`tail -f`**.

**Пример:**
```bash
docker logs -f inno-dkr-06-local
```

## 4. Ограничение числа выводимых строк лога с помощью флага `--tail`

**Вопрос:** Как можно использовать флаг `--tail` для вывода определенного количества последних строк лога? Какой параметр указывается после флага `--tail` для указания числа строк?

**Ответ:** Флаг `--tail` применяется для отсечения старых записей при большом объёме журнала, что особенно удобно в связке с `-f`. После флага указывается целое положительное число `N`, определяющее количество последних строк с конца файла (или ключевое слово `all` для вывода всех строк, что является поведением по умолчанию при отсутствии флага).

**Пример:**
```bash
docker logs --tail 20 -f inno-dkr-06-local
```

## 5. Фильтрация логов по времени с помощью флага `--since`

**Вопрос:** Как флаг `--since` позволяет выводить логи, начиная с определенной даты или с дельты времени? Какой формат даты используется при указании значения для флага `--since`?

**Ответ:** Флаг `--since` сравнивает переданное значение с временными метками (timestamps), которые демон Docker автоматически присваивает каждой строке лога при сохранении, и отбрасывает все более ранние записи. Поддерживаются следующие форматы значений:
* **Относительная дельта времени:** число с единицей измерения (`s` — секунды, `m` — минуты, `h` — часы), например `15m` или `2h`.
* **Дата и время по стандарту RFC 3339 / ISO 8601:** например `2026-11-18`, `2026-11-18T19:30:00` или с указанием часового пояса `2026-11-18T19:30:00Z` / `2026-11-18T19:30:00+03:00`.
* **Unix timestamp:** количество секунд с начала эпохи Unix (например, `1795019400`).

**Пример:**
```bash
docker logs --since 1h inno-dkr-06-local
docker logs --since "2026-11-18T18:00:00Z" inno-dkr-06-local
```

## 6. Вывод временных меток (timestamp) с помощью флага `-t|--timestamps`

**Вопрос:** Как флаг `-t|--timestamps` позволяет выводить временные метки вместе с логами? Зачем это может быть полезно при анализе логов?

**Ответ:** Флаг `-t` (`--timestamps`) заставляет Docker считывать сохранённое время получения каждой строки из метаданных лога и подставлять его в начало строки в формате RFC 3339 с точностью до наносекунд (например, `2026-11-18T16:35:12.481920144Z`). Это необходимо, когда само приложение не пишет время в свои сообщения, а также для точной хронологической корреляции событий между несколькими микросервисами или системными журналами хоста при разборе инцидентов.

**Пример:**
```bash
docker logs -t --tail 5 inno-dkr-06-local
```

## 7. Механизм сборки логов в Docker

**Вопрос:** Как Docker собирает логи из контейнеров? Какие стандартные потоки используются для вывода логов (`stdout` и `stderr`)? Какие преимущества и недостатки имеет такой подход к сбору логов?

**Ответ:**
* **Механизм работы и потоки:** При запуске контейнера демон Docker перехватывает стандартные файловые дескрипторы главного процесса — поток стандартного вывода (**`stdout`**, дескриптор `1`) и поток ошибок (**`stderr`**, дескриптор `2`) — и направляет их в активный драйвер логирования (`json-file`, `local`, `syslog` и др.). Если программа внутри контейнера по умолчанию пишет логи в файлы на диске, в Docker-образах эти файлы заменяют символическими ссылками на `/dev/stdout` и `/dev/stderr` (как в официальном образе `nginx`).
* **Преимущества:**
  * Унификация: единый интерфейс просмотра (`docker logs`) и централизованной отправки для любых стеков технологий.
  * Изоляция от хранилища: приложению не нужно управлять ротацией файлов и следить за свободным местом на диске внутри контейнера.
* **Недостатки:**
  * Риск блокировки приложения: в стандартном режиме (`mode=blocking`) при переполнении буфера вывода или медленной работе драйвера логирования запись в `stdout`/`stderr` приостанавливает работу самого приложения (решается включением `--log-opt mode=non-blocking`).
  * Проблемы с многострочными логами: каждая строка с переносом `\n` (например, стектрейс исключения) обрабатывается как отдельное событие, что усложняет парсинг во внешних системах сбора логов.

**Пример проверки перенаправления логов в образе nginx:**
```bash
docker run --rm nginx:stable ls -la /var/log/nginx
```
