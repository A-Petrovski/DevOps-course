## Чекпоинт 1: Запуск контейнера с локальным драйвером логирования

Запустите контейнер `inno-dkr-06-local` в фоновом режиме на `127.0.0.1:8892` с драйвером `local` и ограничением размера файла лога до `10 MiB`:

```bash
sudo docker run -d \
  --name inno-dkr-06-local \
  -p 127.0.0.1:8892:80 \
  --log-driver local \
  --log-opt max-size=10m \
  nginx:stable
```

### Разбор параметров и флагов
* `-d` — запуск контейнера в фоновом режиме (detached mode).
* `--name inno-dkr-06-local` — присвоение контейнеру заданного имени.
* `-p 127.0.0.1:8892:80` — публикация порта `80` контейнера на локальном интерфейсе хоста `127.0.0.1` по порту `8892`.
* `--log-driver local` — выбор драйвера логирования `local` для данного контейнера.
* `--log-opt max-size=10m` — установка максимального размера одного файла лога в 10 мегабайт (`10m`).
* `nginx:stable` — имя и тег используемого образа.

### Частые ошибки и нюансы
* **Пропуск суффикса единицы измерения в `max-size`:** Если указать `--log-opt max-size=10` без буквы `m`, Docker примет значение как **10 байт**, а не 10 мегабайт. Для указания мегабайт обязательно используйте `10m`.

**Пример использования:** `docker run -d --name web-app -p 8080:80 --log-driver local --log-opt max-size=50m --log-opt max-file=3 nginx:stable`

## Чекпоинт 2: Проверка списка контейнеров, генерация и чтение файла логов на хосте

Выведите список запущенных контейнеров, выполните HTTP-запрос к веб-серверу и прочитайте файл логов напрямую из директории контейнера на хостовой системе:

```bash
sudo docker ps
curl --silent http://127.0.0.1:8892 > /dev/null
CID_LOCAL=$(sudo docker inspect --format='{{.Id}}' inno-dkr-06-local)
sudo cat /var/lib/docker/containers/$CID_LOCAL/local-logs/container.log
```

### Разбор параметров и флагов
* `docker ps` — вывод списка запущенных в данный момент контейнеров.
* `--silent` (в `curl`) — тихий режим без вывода прогресс-бара и служебных сообщений.
* `> /dev/null` — перенаправление стандартного вывода (HTML-страницы ответа) в «пустое» устройство.
* `docker inspect --format='{{.Id}}'` — получение полного 64-символьного идентификатора контейнера с помощью Go-шаблона.
* `cat /var/lib/docker/containers/$CID_LOCAL/local-logs/container.log` — вывод содержимого файла лога драйвера `local` на хостовой машине.

### Сложные моменты и нюансы
* **Пустое поле `.LogPath` при драйвере `local`:** Попытка получить путь к файлу через `docker inspect --format='{{.LogPath}}'` при использовании драйвера `local` возвращает пустую строку (в отличие от драйвера `json-file`). Из-за этого связка с `xargs dirname` выдаёт ошибку `dirname: missing operand`. Для драйвера `local` путь строится через полный ID контейнера (`{{.Id}}`): `/var/lib/docker/containers/<CONTAINER_ID>/local-logs/container.log`.
* **Бинарный формат `container.log`:** Драйвер `local` хранит данные в бинарном формате protobuf (а ротированные архивы сжимает в `.gz`). Для очистки вывода от непечатаемых служебных заголовков можно использовать `sudo strings /var/lib/docker/containers/$CID_LOCAL/local-logs/container.log`.

**Пример использования:** `sudo strings /var/lib/docker/containers/$(docker inspect -f '{{.Id}}' my-container)/local-logs/container.log | grep "GET /"`

## Чекпоинт 3: Глобальная настройка драйвера логов в `/etc/docker/daemon.json`

Настройте драйвер `local` с максимальным размером лога `10 MiB` по умолчанию для всех новых контейнеров на хосте и перезапустите службу Docker:

```bash
sudo tee /etc/docker/daemon.json <<EOF
{
  "log-driver": "local",
  "log-opts": {
    "max-size": "10m"
  }
}
EOF

sudo systemctl restart docker
```

### Разбор параметров и конфига
* `sudo tee /etc/docker/daemon.json` — запись конфигурации в системный файл настроек демона Docker с правами суперпользователя.
* `"log-driver": "local"` — установка драйвера `local` по умолчанию на уровне всего хоста.
* `"log-opts": { "max-size": "10m" }` — передача параметров драйвера по умолчанию в виде JSON-объекта (все значения внутри `log-opts` должны быть заключены в кавычки как строки).
* `systemctl restart docker` — перезапуск службы Docker для применения новой конфигурации.

### Сложные моменты и нюансы
* **Существующий файл `daemon.json`:** Если файл `/etc/docker/daemon.json` уже существовал и содержал другие ключи (например, настройки реестров или драйвера хранилища), перенаправление `<<EOF` перезапишет его. В таком случае параметры нужно добавить вручную внутрь существующего корневого объекта `{ ... }`, соблюдая валидность JSON (запятые между ключами).
* **Остановка запущенных контейнеров:** При выполнении `systemctl restart docker` контейнеры без политики перезапуска (`--restart`) будут остановлены.

**Пример использования:** `sudo docker info --format '{{.LoggingDriver}}'`

## Чекпоинт 4: Запуск контейнера с глобальными настройками логирования

Запустите второй контейнер `inno-dkr-06-global` без указания параметров `--log-driver` и `--log-opt` в командной строке:

```bash
sudo docker run -d \
  --name inno-dkr-06-global \
  -p 127.0.0.1:8893:80 \
  nginx:stable
```

### Разбор параметров и флагов
* `-d` — запуск контейнера в фоновом режиме.
* `--name inno-dkr-06-global` — имя нового контейнера.
* `-p 127.0.0.1:8893:80` — проброс порта `80` контейнера на `127.0.0.1:8893` хоста.
* `nginx:stable` — образ веб-сервера; параметры логирования автоматически наследуются из `/etc/docker/daemon.json`.

**Пример использования:** `docker inspect --format='{{json .HostConfig.LogConfig}}' inno-dkr-06-global`

## Чекпоинт 5: Проверка второго контейнера и чтение его логов на хосте

Проверьте список активных контейнеров, отправьте запрос на порт `8893` и убедитесь, что лог записался в директорию `local-logs` нового контейнера:

```bash
sudo docker ps
curl --silent http://127.0.0.1:8893 > /dev/null
CID_GLOBAL=$(sudo docker inspect --format='{{.Id}}' inno-dkr-06-global)
sudo cat /var/lib/docker/containers/$CID_GLOBAL/local-logs/container.log
```

### Разбор параметров и флагов
* `docker ps` — проверка, что контейнер `inno-dkr-06-global` находится в статусе `Up` и слушает `127.0.0.1:8893->80/tcp`.
* `curl --silent http://127.0.0.1:8893 > /dev/null` — генерация записи `GET / HTTP/1.1` в access-логе `nginx`.
* `CID_GLOBAL=\$(...)` — сохранение полного ID второго контейнера в переменную окружения.
* `sudo cat /var/lib/docker/containers/\$CID_GLOBAL/local-logs/container.log` — подтверждение того, что контейнер использует драйвер `local` без передачи флагов при запуске.

**Пример использования:** `docker logs --tail 5 -t inno-dkr-06-global`
