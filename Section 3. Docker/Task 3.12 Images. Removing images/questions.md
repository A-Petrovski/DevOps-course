# Вопросы для самоконтроля и собеседований: Task 3.12 (Удаление образов Docker)

## 1. Как работает команда `docker rmi` и в какой момент происходит реальное удаление данных с диска?

`docker rmi` удаляет указанный тег или образ. Однако если на один и тот же `IMAGE ID` ссылаются несколько тегов, команда лишь снимает указанный тег (`Untagged`), оставляя физические слои образа на диске нетронутыми. Полное удаление слоев (`Deleted`) происходит только тогда, когда на образ больше не указывает ни один тег и ни один контейнер (работает по принципу жестких ссылок в файловой системе Linux).

```bash
# Снимет только тег, если у образа есть другие имена:
docker rmi nginx:stable-alpine
```

---

## 2. Какие существуют способы удаления образов через `docker rmi` (по имени, тегу, ID, массово)?

Образы можно удалять по полному имени с тегом, по короткому или полному хэшу (`IMAGE ID`), списком через пробел, а также массово через подстановку результатов фильтрации `docker images -q`.

```bash
# По имени и тегу:
docker rmi nginx:stable-alpine

# По ID образа:
docker rmi caf4e1e032a2

# Массовое удаление всех образов конкретного репозитория:
docker rmi \$(docker images nginx -q)

# Массовое удаление абсолютно всех образов в системе:
docker rmi \$(docker images -aq)
```

## 3. Что произойдет, если удалить образ с флагом `--force` (`-f`), пока на его основе запущен контейнер?

Команда выполнится без ошибки, но физически образ с диска **не удалится**. Docker снимет с него тег (`Untagged`), превратив образ в «висячий» (*dangling*, отображается как `<none>:<none>` в `docker images -a`), а в колонке `IMAGE` вывода `docker ps` вместо имени образа появится его `IMAGE ID`. Контейнер продолжит работать и сможет перезапускаться (`docker restart`), а место на диске освободится только после удаления самого контейнера (`docker rm`).

```bash
docker rmi -f nginx:stable-alpine
docker ps  # Контейнер остается в статусе Up, в поле IMAGE указан ID
```

## 4. Как работает команда `docker image prune` и чем она отличается от `docker system prune`?

`docker image prune` удаляет только неиспользуемые образы: по умолчанию она чистит исключительно «висячие» (*dangling*) безымянные слои `<none>:<none>`, не привязанные ни к одному контейнеру. Добавление флага `-a` (`--all`) удаляет вообще все образы, для которых в данный момент нет ни одного контейнера.

`docker system prune` — комплексная команда очистки, которая за один запуск удаляет все неиспользуемые сущности сразу: остановленные контейнеры, неиспользуемые сети, dangling-образы и кэш сборки (а при добавлении флага `--volumes` — ещё и неиспользуемые тома).

```bash
# Удалить только безымянные (dangling) слои образов:
docker image prune

# Удалить все образы, не используемые ни одним контейнером:
docker image prune -a

# Комплексная очистка всей системы (включая тома):
docker system prune -a --volumes
```

## 5. Как Docker работает с промежуточными слоями образов при удалении и как освободить занятое ими место?

Образы в Docker состоят из набора слоев только для чтения (read-only), которые могут переиспользоваться разными образами (например, базовый слой `alpine` или `debian`). При удалении образа Docker проверяет счетчик ссылок на каждый его слой:
- Если промежуточный слой используется другим локальным образом или контейнером, Docker **пропустит** его и не станет удалять.
- Удаляются только те уникальные слои, на которые больше нет ни одной ссылки.
- Осиротевшие промежуточные слои от прерванных сборок или принудительно отвязанных тегов переходят в статус `<none>:<none>` и очищаются с помощью `docker image prune` или `docker builder prune`.

```bash
# Посмотреть, сколько места занимают образы, контейнеры и кэш сборки:
docker system df

# Очистить кэш сборки и промежуточные слои:
docker builder prune
```
