## 1. Загрузка образа nginx:stable-alpine

Скачиваем целевой образ из Docker Hub в локальное хранилище хоста:

```bash
sudo docker pull nginx:stable-alpine
```

- `pull` — команда загрузки образа из удаленного реестра.
- `nginx:stable-alpine` — имя репозитория (`nginx`) и конкретный тег (`stable-alpine`).

**Пример использования:** `docker pull ubuntu:22.04`

---

## 2. Добавление нового тега inno-dkr-12

Создаем локальный псевдоним (ярлык) `inno-dkr-12` для уже загруженного образа:

```bash
sudo docker tag nginx:stable-alpine inno-dkr-12
```

- `tag` — команда создания нового тега-ссылки на существующий образ.
- `nginx:stable-alpine` — исходный образ-источник.
- `inno-dkr-12` — новое имя образа (по умолчанию присваивается тег `:latest`).

**Пример использования:** `docker tag myapp:v1 ://example.com`

---

## 3. Проверка списка образов и удаление исходного тега

Выводим список локальных образов и убеждаемся, что у `nginx:stable-alpine` и `inno-dkr-12:latest` идентичный `IMAGE ID` (например, `caf4e1e032a2`). Затем удаляем исходный тег:

```bash
sudo docker images
sudo docker rmi nginx:stable-alpine
```

- `images` — выводит таблицу всех локальных образов, их тегов, ID и размеров.
- `rmi` (*remove image*) — удаляет указанный тег или образ.

**Пример использования:** `docker rmi alpine:3.18`

---

## 4. Проверка сохранения переименованного образа

Повторно выводим список образов, чтобы убедиться, что `inno-dkr-12:latest` остался в системе:

```bash
sudo docker images
```

- `images` — отображает список доступных локальных образов.

### Разбор нюансов
На предыдущем шаге Docker вывел только `Untagged: nginx:stable-alpine` без строки `Deleted`. Поскольку на физические слои образа всё ещё ссылается второй тег (`inno-dkr-12:latest`), реального удаления данных с диска не произошло — удалился только один из указателей (по принципу жестких ссылок в Linux).

**Пример использования:** `docker image ls --digests`

---

## 5. Повторная загрузка образа nginx:stable-alpine

Снова выполняем загрузку образа из реестра:

```bash
sudo docker pull nginx:stable-alpine
```

- `pull` — проверяет манифест образа в реестре и загружает недостающие слои.

**Пример использования:** `docker pull redis:alpine`

---

## 6. Сохранение списка образов в файл и сверка ID

Выводим актуальный список образов в терминал с одновременной записью в текстовый файл:

```bash
sudo docker images | tee /home/user/images.txt
```

- `|` (пайп) — перенаправляет стандартный вывод (`stdout`) команды `docker images` на вход следующей команде.
- `tee` — утилита, дублирующая поток данных одновременно на экран терминала и в указанный файл (`/home/user/images.txt`).

### Разбор нюансов
`IMAGE ID` скачанного образа `nginx:stable-alpine` остался прежним и совпадает с `inno-dkr-12:latest`. При повторном `pull` Docker сверил хэши слоев из манифеста с локальным кэшем, обнаружил, что эти слои уже есть на диске, и просто заново привязал тег к существующему ID без повторного скачивания гигабайтов данных.

**Пример использования:** `docker ps -a | tee /tmp/containers_snapshot.txt`

## 7. Удаление всех образов nginx одной командой

Удаляем все образы, относящиеся к репозиторию `nginx`, не затрагивая другие образы в системе (например, `hello-world` или `inno-dkr-11`), и проверяем результат:

```bash
sudo docker rmi -f $(sudo docker images nginx -q)
sudo docker images
```

- `docker images nginx -q` — фильтрует образы по имени репозитория `nginx` и за счет флага `-q` (*quiet*) возвращает **только их ID** без заголовков таблицы.
- `$(...)` — подстановка команд в Bash: сначала выполняется внутренняя команда, а список полученных ID передается как аргументы в `docker rmi`.
- `-f` (`--force`) — принудительное удаление, необходимое для обхода конфликтов.

### Разбор ошибок и сложных моментов (из практики)
При выполнении команды без флага `-f` (`sudo docker rmi $(sudo docker images nginx -q)`) Docker выдал два типа ошибок:
1. **`conflict: unable to delete ... - image is being used by stopped container <ID>`** — некоторые старые образы (`nginx:inno-dkr-07`, `09`, `10`, `nginx:stable`) использовались ранее остановленными контейнерами. Пока контейнер существует (даже в статусе `Exited`), его базовый образ защищен от обычного удаления.
2. **`conflict: unable to delete caf4e1e032a2 - image is referenced in multiple repositories`** — ID `caf4e1e032a2` принадлежал одновременно двум репозиториям (`nginx:stable-alpine` и `inno-dkr-12:latest`), поэтому Docker запретил удалять его по ID без подтверждения.

**Альтернативный чистый способ** (если нужно удалить сначала остановленные контейнеры, а затем только теги `nginx:*`, сохранив `inno-dkr-12:latest`):
```bash
sudo docker container prune -f
sudo docker rmi $(sudo docker images --format "{{.Repository}}:{{.Tag}}" nginx)
```

**Пример использования:** `docker rmi $(docker images "myapp*" -q)`

## 8. Запуск фонового контейнера inno-dkr-12

Запускаем новый контейнер из образа `nginx:stable-alpine` в фоновом режиме с заданным именем:

```bash
sudo docker run -d --name inno-dkr-12 nginx:stable-alpine
```

- `run` — создает и запускает новый контейнер.
- `-d` (`--detach`) — запускает контейнер в фоновом режиме (демонизирует процесс и возвращает управление в терминал).
- `--name inno-dkr-12` — присваивает контейнеру читаемое уникальное имя `inno-dkr-12`.
- `nginx:stable-alpine` — базовый образ (если его нет локально после шага 7, Docker скачает его автоматически перед запуском).

**Пример использования:** `docker run -d --name web-server -p 8080:80 nginx:alpine`

---

## 9. Попытка удаления образа без флагов

Пробуем удалить базовый образ работающего контейнера стандартной командой:

```bash
sudo docker rmi nginx:stable-alpine
```

- `rmi` — попытка стандартного удаления образа по тегу.

### Разбор ошибки
Команда завершится с ошибкой: `Error response from daemon: conflict: unable to remove repository reference "nginx:stable-alpine" (must force) - container <ID> is using its referenced image <IMAGE_ID>`. Docker блокирует удаление образа, на базе которого в данный момент запущен контейнер.

**Пример использования:** `docker rmi busybox:latest`

---

## 10. Принудительное удаление образа с флагом --force

Удаляем образ принудительно, игнорируя привязку к запущенному контейнеру:

```bash
sudo docker rmi --force nginx:stable-alpine
```

- `--force` (короткий аналог `-f`) — принудительно снимает тег `nginx:stable-alpine` с образа, несмотря на наличие активного контейнера.

**Пример использования:** `docker rmi -f nginx:latest`

---

## 11. Проверка работы контейнера и его перезапуск

Проверяем список активных контейнеров, убеждаемся, что `inno-dkr-12` работает, и перезапускаем его:

```bash
sudo docker ps
sudo docker restart inno-dkr-12
```

- `ps` — выводит список только **запущенных** в данный момент контейнеров.
- `restart` — корректно останавливает и заново запускает указанный контейнер.

### Разбор нюансов
После выполнения `docker rmi --force` в выводе `docker ps` в колонке `IMAGE` вместо имени `nginx:stable-alpine` теперь отображается сырой идентификатор образа (например, `caf4e1e032a2`). Контейнер продолжает работать и успешно перезапускается, так как флаг `--force` только снял тег (`Untagged`), превратив образ в безымянный (*dangling*), но физически сохранил слои на диске до момента удаления самого контейнера.

**Пример использования:** `docker restart my-backend-service`

---

## 12. Контрольная проверка списка запущенных контейнеров

Финально проверяем статус контейнера после перезапуска:

```bash
sudo docker ps
```

- `ps` — подтверждает, что контейнер `inno-dkr-12` находится в статусе `Up`.

*(Примечание: после сдачи задания удалить тестовый контейнер вместе с оставшимися безымянными слоями можно командой `sudo docker rm -f inno-dkr-12`).*

**Пример использования:** `docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Image}}"`
