## Введение

Контейнер внутри имеет операционную систему, использующую ядро хостовой системы для работы, а значит, внутри можно проводить те же операции, что и на обычной операционной системе: отправка команд приложению, вызов системных утилит, установка пакетов.

Для взаимодействия с окружением внутри работающего контейнера используется команда **`exec`** (`docker exec` — запустить команду в работающем контейнере).

---

## Сценарии использования команды `docker exec`

Как правило, данная команда используется в двух сценариях:
1. **Разовый вызов команды внутри контейнера** — например, отправить команду работающему приложению.
2. **Получение интерактивной оболочки внутри контейнера** — работать внутри контейнера, как в полноценной операционной системе.

### Примеры для первого сценария (запуск серверных задач)
* Повторное чтение конфига приложения без рестарта.
* Ротация файла логов.
* Запуск фоновых работ — актуально для приложений, у которых нет встроенного обработчика фоновых или повторяемых задач (например, бэкап БД либо запуск Cron-таски для приложений на PHP).

### Примеры для второго сценария (отладка изнутри)
* Посмотреть логи (если они не проброшены наружу).
* Проверить сетевую доступность.
* Изменить параметры работы приложения, чтобы после этого зафиксировать в исходном репозитории с кодом (актуально для приложений на PHP), и другие задачи при доступе изнутри.

## Разница между `docker exec` и `docker attach`

Команда **`attach`** («подключиться к стандартному вводу, выводу и ошибкам работающего контейнера») производит подключение к **приложению, запущенному в контейнере**, а не к окружению контейнера.
* Если в контейнере запущен `nginx`, мы подключимся к тем же данным, что выводит `nginx` при запуске его вручную не в фоновом режиме.
* Если же в контейнере запускается интерактивная оболочка с ожиданием, мы получим доступ к тому, что происходит в оболочке.

Использование `attach` сравнимо с двумя другими инструментами:
* **Терминальный мультиплексор (`screen` или `tmux`)** — в нём можно запустить приложение и в любой момент подключиться, имея доступ к текущему состоянию работы так, будто приложение запускалось в своём терминале.
* **Background (фоновый) режим работы приложения** — во многих интерактивных оболочках есть возможность отправить задачи в background-режим: они привязаны к сессии, но работают в фоне, и в любой момент к ним можно подключиться обратно (при закрытии сессии задача умрёт, если не выполнена).

## Флаги команды `docker exec`

Наиболее используемые флаги команды `exec` (полный список доступен в `docker exec --help` или в официальной документации):

* **`-i`** — запустить команду в интерактивном режиме, то есть после запуска команды держать соединение с ней (актуально для первого сценария использования `docker exec`).
* **`-t`** — создать для команды псевдотерминал (актуально для второго сценария использования `docker exec`).

### Особые случаи запуска без флагов
* **Не нужно ждать вывода или взаимодействия:** требуется запустить команду внутри контейнера, при этом не требуется ждать вывода команды или взаимодействовать с ней — запуск можно производить без флагов.
* **Запуск автоматизированной системой (например, в `cron`):** выделение псевдотерминала может навредить, поскольку выделение псевдотерминала в системе, которая изначально работает не из-под терминала, провалится.

При запуске терминала на компьютере или подключении к серверу по SSH в операционной системе выделяется виртуальный терминал, через который производится взаимодействие с ОС. Узнать ID текущего виртуального терминала можно командой **`who`**.
