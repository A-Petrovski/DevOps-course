## Чекпоинт 1. Подготовка конфигурационного файла и запуск контейнера `inno-dkr-03`

### 1. Подготовка первого конфигурационного файла `nginx.conf`
Если дана ссылка из методички — скачиваем файл через `curl -o ~/nginx.conf <URL_1>`, либо создаём минимальный рабочий конфиг с требуемой строкой ответа:

```bash
printf 'events {}\nhttp {\n  server {\n    listen 80;\n    location / {\n      return 200 "Welcome to the training program Innowise: Docker\\n";\n    }\n  }\n}\n' > ~/nginx.conf
```

### 2. Запуск контейнера `inno-dkr-03`
```bash
sudo docker run -d -p 127.0.0.1:8890:80 --name inno-dkr-03 -v $(pwd)/nginx.conf:/etc/nginx/nginx.conf nginx:stable
```

### Разбор параметров и флагов
* **`sudo`** — выполнение команды с правами суперпользователя (требуется, если текущий пользователь не состоит в группе `docker`).
* **`docker run`** — создание и запуск нового контейнера из образа.
* **`-d` (`--detach`)** — запуск контейнера в фоновом режиме.
* **`-p 127.0.0.1:8890:80`** — проброс портов в формате `IP_хоста:порт_хоста:порт_контейнера`:
  * **`127.0.0.1`** — привязка только к локальному интерфейсу хоста (localhost).
  * **`8890`** — порт на хосте, который принимает входящие запросы.
  * **`80`** — порт внутри контейнера, на котором работает Nginx.
* **`--name inno-dkr-03`** — присвоение контейнеру имени `inno-dkr-03`.
* **`-v $(pwd)/nginx.conf:/etc/nginx/nginx.conf`** — монтирование файла `nginx.conf` из текущей директории хоста вместо основного конфига Nginx внутри контейнера (без флага `:ro`, чтобы допускать работу с файлом).
* **`nginx:stable`** — образ Nginx из стабильной ветки.

**Пример использования:** `sudo docker run -d -p 127.0.0.1:8890:80 --name inno-dkr-03 -v ~/nginx.conf:/etc/nginx/nginx.conf nginx:stable`

## Чекпоинт 2. Первичная проверка ответа, статуса контейнера и `md5sum`

### Команды проверки
```bash
curl 127.0.0.1:8890
sudo docker ps
sudo docker exec -ti inno-dkr-03 md5sum /etc/nginx/nginx.conf
```

### Разбор параметров и флагов
* **`curl 127.0.0.1:8890`** — отправка HTTP GET-запроса на локальный адрес и порт `8890`; возвращает строку `Welcome to the training program Innowise: Docker`.
* **`docker ps`** — вывод списка всех запущенных контейнеров (проверяем, что `inno-dkr-03` находится в статусе `Up`).
* **`docker exec`** — выполнение команды внутри уже запущенного контейнера.
* **`-t` (`--tty`)** — выделение псевдотерминала для команды.
* **`-i` (`--interactive`)** — удержание стандартного потока ввода (STDIN) открытым.
* **`inno-dkr-03`** — имя работающего контейнера, в котором выполняется команда.
* **`md5sum /etc/nginx/nginx.conf`** — утилита вычисления MD5-хеша основного конфигурационного файла внутри контейнера.

**Пример использования:** `sudo docker exec -ti inno-dkr-03 bash` (вход в интерактивную оболочку Bash внутри работающего контейнера для отладки).

## Чекпоинт 3. Эксперимент с изменением конфига (`cp`, `nano`, `vim`) и `reload` nginx

### 1. Подготовка нового конфигурационного файла `~/nginx_new.conf`
```bash
printf 'events {}\nhttp {\n  server {\n    listen 80;\n    location / {\n      return 200 "Welcome to the training program Innowise: Docker! Again!\\n";\n    }\n  }\n}\n' > ~/nginx_new.conf
```

### 2. Варианты изменения файла на хосте
* **Способ 1 (через `cp`):**
  ```bash
  cp ~/nginx_new.conf ~/nginx.conf
  ```
* **Способ 2 (через `nano`):**
  ```bash
  nano ~/nginx.conf
  ```
  *(Вносим изменение строки на `Welcome to the training program Innowise: Docker! Again!`, сохраняем `Ctrl+O` -> `Enter` и выходим `Ctrl+X`).*
* **Способ 3 (через `vim`):**
  ```bash
  vim ~/nginx.conf
  ```
  *(Переходим в режим вставки `i`, меняем строку, выходим в командный режим `Esc` и сохраняем `:wq`).*

### 3. Перезагрузка конфигурации Nginx без остановки контейнера и проверка
```bash
sudo docker exec -ti inno-dkr-03 nginx -s reload
curl 127.0.0.1:8890
```

### Разбор параметров и флагов
* **`cp ~/nginx_new.conf ~/nginx.conf`** — копирует содержимое нового файла поверх существующего файла `~/nginx.conf`.
* **`nano` / `vim`** — консольные текстовые редакторы для редактирования файла на хосте.
* **`docker exec -ti inno-dkr-03 nginx -s reload`** — отправка сигнала `reload` главному процессу Nginx внутри контейнера `inno-dkr-03` для перечитывания конфигурации без остановки самого контейнера и разрыва соединений.
  * **`-s reload`** — флаг самого бинарного файла `nginx`, отправляющий сигнал мягкой перезагрузки конфигурации (`HUP`).

**Пример использования:** `sudo docker exec inno-dkr-03 nginx -t && sudo docker exec inno-dkr-03 nginx -s reload` (проверка синтаксиса конфига перед его применением внутри контейнера).

## Чекпоинт 4. Финальная проверка `md5sum`, сравнение способов и объяснение работы `inode`

### 1. Финальные команды проверки
```bash
sudo docker exec -ti inno-dkr-03 md5sum /etc/nginx/nginx.conf
sudo docker ps
```

### 2. Сравнение результатов изменения `nginx.conf` разными инструментами

| Инструмент | Отобразились ли изменения в контейнере после `nginx -s reload`? | Изменился ли `md5sum` внутри контейнера? | Что произошло с `inode` файла на хосте? |
| :--- | :--- | :--- | :--- |
| **`cp`** | **Да** (вернулась новая строка) | **Да** | `inode` остался прежним (перезапись поверх) |
| **`nano`** | **Да** (вернулась новая строка) | **Да** | `inode` остался прежним (прямая запись в файл) |
| **`vim`** | **Нет** (осталась старая строка) | **Нет** (остался старый хеш) | **Создан новый `inode`** (атомарная подмена файла) |

### 3. Почему при изменении через `vim` обновления не отображаются в контейнере?
1. **Bind Mount привязывается к `inode`, а не к имени файла:** При монтировании одиночного файла (`-v ~/nginx.conf:/etc/nginx/nginx.conf`) ядро Linux связывает точку монтирования внутри контейнера с конкретным индексным дескриптором (`inode`) файла на диске хоста.
2. **Атомарное сохранение в `vim`:** По умолчанию `vim` в Linux при сохранении пишет изменения в новый временный файл, удаляет старый `nginx.conf` и переименовывает временный файл на его место.
3. **Разрыв связи:** Новый файл на хосте получает новый номер `inode`, а контейнер продолжает ссылаться на старый `inode`, который удерживается в памяти/на диске точкой монтирования.

### Разбор параметров проверки `inode`
```bash
ls -i ~/nginx.conf
sudo docker exec -ti inno-dkr-03 ls -i /etc/nginx/nginx.conf
```
* **`ls -i`** — выводит номер индексного дескриптора (`inode`) файла; после сохранения через `vim` числа на хосте и внутри контейнера будут отличаться.

**Пример использования:** `sudo docker restart inno-dkr-03` (перезапуск контейнера для повторного монтирования файла по новому `inode` после редактирования в `vim`).

## Разбор сложных моментов и ошибок

1. **Ошибка `nginx: invalid option: "curl"` при вызове `sudo nginx -s reload curl`:**
   * **Причина:** Команда `nginx -s reload` была запущена напрямую на хосте (без `docker exec`), а следующая команда `curl` была приписана в ту же строку как аргумент.
   * **Решение:** Всегда запускать `nginx -s reload` строго внутри целевого контейнера через `sudo docker exec -ti inno-dkr-03 nginx -s reload`, а проверку `curl` выполнять следующей отдельной строкой.

2. **Ошибка `curl: (7) Failed to connect to 127.0.0.1 port 8890: Could not connect to server`:**
   * **Причина:** Попытка обратиться к порту `8890` до запуска нового контейнера `inno-dkr-03` (на тот момент был запущен только контейнер из предыдущей задачи на порту `8889`).
   * **Решение:** Предварительно проверить список запущенных контейнеров через `sudo docker ps` и убедиться, что `inno-dkr-03` запущен и слушает порт `8890`.
