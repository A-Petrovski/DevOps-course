# Task 3.3 Basics. Контрольные вопросы для самопроверки

## 1. Как работает команда `attach` в Docker и в каких случаях её можно использовать?

Команда **`docker attach`** подключает стандартные потоки ввода (`STDIN`), вывода (`STDOUT`) и ошибок (`STDERR`) текущего терминала напрямую к **главному процессу (`PID 1`)**, запущенному внутри работающего контейнера.

* **Как работает:** В отличие от `docker exec`, команда `attach` не запускает новый процесс внутри контейнера, а прикрепляется к уже существующему. Если нажать `Ctrl+C` внутри сессии `attach` (без специального флага `--sig-proxy=false`), сигнал `SIGINT` передастся главному процессу и **остановит весь контейнер**. Чтобы выйти из сессии без остановки контейнера, используется комбинация **`Ctrl+P`, затем `Ctrl+Q`**.
* **Когда использовать:**
  * Для просмотра логов и вывода веб-сервера или приложения в реальном времени, если оно запущено на переднем плане (например, `nginx` без демонизации).
  * Для взаимодействия с интерактивной оболочкой или консольным приложением (например, Python REPL, `bash` или игровой/административный консоль-сервер), если именно они запущены как главный процесс контейнера (`PID 1`).

**Пример использования:**
```bash
# Подключение к главному процессу контейнера без проброса сигналов завершения (безопасный выход по Ctrl+C)
sudo docker attach --sig-proxy=false inno-dkr-03
```

## 2. Какие флаги используются с командой `exec` при использовании `attach` для взаимодействия с контейнерами?

При интерактивном взаимодействии с процессами или оболочкой внутри контейнера (аналогично подключению через `attach`) у команды **`docker exec`** используются два основных флага, которые обычно объединяют в **`-it`** (или `-ti`):

* **`-i` (`--interactive`)** — удерживает стандартный поток ввода (`STDIN`) открытым, позволяя передавать команды и ввод с клавиатуры процессу внутри контейнера.
* **`-t` (`--tty`)** — выделяет псевдотерминал (TTY), обеспечивая корректное форматирование вывода, работу приглашения командной строки (`prompt`), автодополнение по `Tab` и работу консольных редакторов (`vim`, `nano`).

*(Примечание: сама команда `docker attach` не имеет флагов `-i` и `-t`, так как подключается к уже существующим потокам процесса; эти флаги задаются при создании контейнера `docker run -it` или при запуске нового процесса через `docker exec -it`).*

**Пример использования:**
```bash
# Запуск интерактивной оболочки внутри работающего контейнера
sudo docker exec -it inno-dkr-03 /bin/bash
```

## 3. Как обрабатываются команды `exec` без флагов `-i` и `-t` в автоматизированных системах?

При запуске **`docker exec`** без флагов `-i` и `-t` Docker выполняет команду внутри контейнера в **неинтерактивном фоновом/пакетном режиме** без привязки к клавиатуре и без выделения псевдотерминала:

* **Обработка потоков:** Стандартный ввод (`STDIN`) сразу закрывается, а стандартный вывод (`STDOUT`) и ошибки (`STDERR`) просто транслируются в поток вывода вызывающего скрипта или планировщика, после чего `docker exec` завершается и возвращает код выхода (`exit code`) выполненной внутри команды.
* **Почему в автоматизации (Cron, CI/CD, systemd) нельзя использовать `-t`:** Автоматизированные планировщики и пайплайны запускают задачи без реального управляющего терминала (TTY). Если передать флаг `-t`, Docker попытается выделить псевдотерминал для несуществующего TTY и завершится с ошибкой **`the input device is not a TTY`**, из-за чего скрипт или задача в `cron` упадут.

**Пример использования в Cron или CI/CD-скрипте:**
```bash
# Безопасный вызов reload Nginx или резервного копирования из планировщика cron без флагов -it
0 3 * * * /usr/bin/docker exec inno-dkr-03 nginx -s reload
```
