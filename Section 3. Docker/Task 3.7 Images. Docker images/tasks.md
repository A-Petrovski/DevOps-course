## Чекпоинт 1: Загрузка образа, тегирование и просмотр списка

**Задача:** выполнить загрузку образа `nginx:stable-alpine` на локальный хост, добавить к нему новый тег `inno-dkr-07` с сохранением имени репозитория и вывести список локальных образов.

```bash
docker pull nginx:stable-alpine
docker tag nginx:stable-alpine nginx:inno-dkr-07
docker images
```

**Разбор команд и параметров:**
* `docker pull` — команда для скачивания образа из удаленного реестра (по умолчанию используется Docker Hub).
* `nginx:stable-alpine` — указание целевого репозитория (`nginx`) и конкретного тега (`stable-alpine`).
* `docker tag` — команда создания нового псевдонима (тега) для существующего локального образа.
* `nginx:inno-dkr-07` — целевое имя образа, где репозиторий `nginx` оставлен без изменений, а после двоеточия задан требуемый тег `inno-dkr-07`.
* `docker images` — вывод таблицы всех образов, сохраненных на локальном хосте.

**Нюансы и возможные ошибки:**
* Команда `docker tag` не копирует содержимое образа и не занимает дополнительное место на диске. Она создает новую ссылку, указывающую на тот же `IMAGE ID`, что и исходный образ `nginx:stable-alpine`.
* Если при тегировании не указать двоеточие и тег в целевом имени (например, написать `docker tag nginx:stable-alpine nginx`), Docker по умолчанию присвоит тег `latest`.
* При удалении исходного тега через `docker rmi nginx:stable-alpine` сам образ (слои на диске) не удалится, так как на его `IMAGE ID` продолжает ссылаться тег `nginx:inno-dkr-07`.

**Пример использования:**
```bash
docker images nginx --format "table {{.Repository}}\t{{.Tag}}\t{{.ID}}\t{{.Size}}"
```

## Чекпоинт 2: Запуск контейнера в фоновом режиме

**Задача:** запустить контейнер в фоне на базе нового образа, полученного после добавления тега (`nginx:inno-dkr-07`).

```bash
docker run -d nginx:inno-dkr-07
```

**Разбор команд и параметров:**
* `docker run` — команда создания и запуска нового контейнера из указанного образа.
* `-d` (или `--detach`) — запуск контейнера в фоновом режиме (detached mode). Терминал не блокируется логами процесса, а в консоль возвращается только полный ID запущенного контейнера.
* `nginx:inno-dkr-07` — имя репозитория и тег образа, из которого разворачивается контейнер.

**Нюансы и возможные ошибки:**
* Если запустить контейнер без флага `-d`, терминал перейдет в режим вывода логов (attached mode), и нажатие `Ctrl+C` остановит веб-сервер и завершит работу контейнера.
* Так как в задании не требовался проброс портов (`-p`), веб-сервер `nginx` будет работать внутри изолированной сети Docker, но не будет доступен по `localhost` с хост-машины.

**Пример использования:**
```bash
docker run -d --name my-nginx -p 8080:80 nginx:inno-dkr-07
```

## Чекпоинт 3: Проверка списка запущенных контейнеров

**Задача:** вывести список активных контейнеров и убедиться, что созданный контейнер находится в состоянии запуска.

```bash
docker ps
```

**Разбор команд и параметров:**
* `docker ps` — вывод списка всех работающих в данный момент контейнеров (сокращение от *process status*, аналог `docker container ls`).

**Нюансы и возможные ошибки:**
* В выводе `docker ps` необходимо обратить внимание на колонку `IMAGE` (там должно быть указано `nginx:inno-dkr-07`) и колонку `STATUS` (значение должно начинаться с `Up`, например `Up 10 seconds`).
* Если контейнер сразу завершился с ошибкой, `docker ps` его не покажет — для просмотра остановленных контейнеров потребуется добавить флаг `-a` (`docker ps -a`).

**Пример использования:**
```bash
docker ps --filter "ancestor=nginx:inno-dkr-07"
```
