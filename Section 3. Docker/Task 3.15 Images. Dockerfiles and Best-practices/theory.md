## Зачем использовать несколько Dockerfile в одном репозитории

Продолжаем работать с образами. На этом занятии мы узнаем, зачем использовать несколько Dockerfile в одном репозитории.

Несколько Dockerfile в одном репозитории используется, если:
- нужно использовать разный базовый образ;
- в рамках образа добавляется разный набор инструментов;
- собираются образы с разным набором зависимостей.

Все эти варианты распространены и могут быть актуальны для совершенно разных случаев. Подробные примеры ты можешь посмотреть в полезных ссылках.

## Как использовать разные Dockerfile

Теперь посмотрим, как можно использовать разные Dockerfile.

Как ты уже понял из предыдущих заданий, для этого у `docker build` есть опция `--file`, она указывает на Dockerfile, который необходимо собрать.

Например, если у тебя есть два Dockerfile с именами `Dockerfile.prod` и `Dockerfile.dev`, то их сборка, соответственно, будет вызываться разными командами:

```bash
docker build --file Dockerfile.prod .
docker build --file Dockerfile.dev .
```

## Размещение Dockerfile в репозитории

Никто не запрещает помещать Dockerfile в отдельные директории внутри репозитория. Например, если у тебя есть два файла для разных окружений, они могут располагаться в директории `docker` и иметь имена `prod` и `dev` (да, наличие слова `Dockerfile` в имени файла — не обязательно), то вызов сборки будет выглядеть следующим образом:

```bash
docker build --file ./docker/prod .
docker build --file ./docker/dev .
```

Хорошей практикой считается держать `Dockerfile` в корне проекта, что позволяет просто вызывать `docker build .`, не задумываясь о том, какой файл используется, но, как мы сказали выше, ситуации могут быть разные.
