## Чекпоинт 1: Запуск Docker-in-Docker первым методом (DinD)

Запускаем официальный образ `docker:dind`, который поднимает внутри контейнера собственный изолированный процесс демона `dockerd`.

```bash
docker run -d --privileged --name dind-test docker:dind
```

**Разбор флагов и параметров:**
- `run` — команда создания и запуска нового контейнера.
- `-d` (`--detach`) — запуск контейнера в фоновом режиме (демонизация).
- `--privileged` — выдача контейнеру расширенных привилегий ядра Linux (доступ к устройствам хоста, монтированию файловых систем, управлению `cgroups` и сетевыми пространствами имен). Без этого флага внутренний `dockerd` не сможет стартовать.
- `--name dind-test` — присвоение читаемого имени контейнеру для удобного обращения к нему.
- `docker:dind` — официальный образ Docker с предустановленным демоном для вложенного запуска.

**Пример использования:**
```bash
docker run -d --privileged --name ci-dind-daemon -e DOCKER_TLS_CERTDIR="" docker:dind
```

## Чекпоинт 2: Работа с образами и контейнерами внутри DinD

Подключаемся к запущенному контейнеру и выполняем полный цикл управления дочерним контейнером в изолированном окружении.

```bash
# 1. Подключение к интерактивной оболочке контейнера
docker exec -it dind-test sh

# 2. Проверка текущих образов и всех контейнеров (списки будут пустыми)
docker images
docker ps -a

# 3. Загрузка образа Redis 5-й версии
docker pull redis:5

# 4. Запуск фонового контейнера из скачанного образа
docker run -d --name inno-dkr-26 redis:5

# 5. Проверка списка всех контейнеров (появился inno-dkr-26)
docker ps -a

# 6. Принудительное удаление работающего контейнера
docker rm -f inno-dkr-26

# 7. Повторная проверка списка контейнеров (список снова пуст) и выход
docker ps -a
exit
```

**Разбор флагов и параметров:**
- `exec` — выполнение новой команды внутри уже работающего контейнера.
- `-i` (`--interactive`) — удержание стандартного потока ввода (`STDIN`) открытым для интерактивного взаимодействия.
- `-t` (`--tty`) — выделение псевдотерминала (TTY) для корректной работы командной оболочки.
- `sh` — запуск стандартной POSIX-оболочки внутри Alpine-образа (в образах `docker` по умолчанию нет `bash`).
- `images` — вывод списка локально загруженных образов внутри текущего демона.
- `ps -a` — вывод списка всех контейнеров, включая остановленные (`-a` / `--all`).
- `pull redis:5` — скачивание образа `redis` с тегом `5` из Docker Hub.
- `rm -f` — удаление контейнера с принудительной остановкой (`-f` / `--force`), так как `inno-dkr-26` находится в статусе `Up`.

**Пример использования:**
```bash
docker exec -it dind-test docker run --rm alpine echo "Isolated build test"
```

## Чекпоинт 3: Запуск Docker-out-of-Docker вторым методом (проброс сокета) и повтор цикла

Запускаем контейнер с Docker CLI, пробрасывая UNIX-сокет родительского демона с хоста. Команды внутри такого контейнера управляют напрямую Docker-демоном хост-машины.

```bash
# 1. Запуск контейнера с пробросом сокета и удержанием оболочки sh
docker run -dit -v /var/run/docker.sock:/var/run/docker.sock --name dood-test docker sh

# 2. Подключение к контейнеру
docker exec -it dood-test sh

# 3. Выполнение цикла проверок (отобразятся все образы и контейнеры хоста!)
docker images
docker ps -a
docker pull redis:5
docker run -d --name inno-dkr-26 redis:5
docker ps -a
docker rm -f inno-dkr-26
docker ps -a
exit
```

**Разбор флагов и параметров:**
- `-dit` — комбинация флагов фонового запуска (`-d`), интерактивного ввода (`-i`) и псевдотерминала (`-t`).
- `-v /var/run/docker.sock:/var/run/docker.sock` (`--volume`) — bind-монтирование UNIX-сокета Docker-демона хоста внутрь контейнера по аналогичному пути.
- `docker` — базовый образ, содержащий только клиентскую утилиту (`docker` CLI) без собственного демона `dockerd`.
- `sh` (в конце `docker run`) — явная переопределяющая команда (`CMD`), которая удерживает контейнер в активном состоянии `Up`.

**Пример использования:**
```bash
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock docker ps --format "table {{.ID}}\t{{.Names}}\t{{.Status}}"
```

## Разбор сложных моментов и типовых ошибок

1. **Контейнер `dood-test` мгновенно завершается (`Error response from daemon: container ... is not running`):**
   - *Причина:* В официальном образе `docker:latest` стандартная точка входа (`ENTRYPOINT`) без аргументов просто выводит справку CLI и завершает процесс с кодом `0`, даже если переданы флаги `-dit`.
   - *Решение:* Всегда передавать в конце команды `docker run` долгоживущий процесс, например `sh` или `sleep infinity`.
2. **Конфликт имен при повторном запуске (`Conflict. The container name "/dood-test" is already in use`):**
   - *Причина:* После мгновенного завершения контейнер перешел в статус `Exited`, но остался в базе демона.
   - *Решение:* Предварительно удалить остановленный контейнер командой `docker rm dood-test` или сразу запускать временные контейнеры с флагом `--rm`.
3. **Разница в видимости ресурсов (Изоляция vs Соседство):**
   - В методе **DinD** списки `docker ps -a` и `docker images` изначально пусты, так как внутри работает независимый демон со своей директорией `/var/lib/docker` (хранится в анонимном volume хоста).
   - В методе **DooD (сокет)** списки показывают все контейнеры и образы хоста, включая сам контейнер `dood-test`, поскольку CLI внутри контейнера отправляет API-запросы напрямую хостовому демону.
4. **Ошибка прав доступа к сокету (`permission denied while trying to connect to the Docker daemon socket`):**
   - *Причина:* Текущий пользователь Linux не состоит в группе `docker`, которой принадлежит `/var/run/docker.sock`.
   - *Решение:* Использовать `sudo` или добавить пользователя в группу: `sudo usermod -aG docker $USER` (требуется перелогин).
