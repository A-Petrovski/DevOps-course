## Чекпоинт 1: Создание параметризованного Dockerfile

Создаем файл `/home/user/Dockerfile` (или в твоей рабочей директории, например `/home/amp/Dockerfile`), который:
1. Собирается из образа `nginx`, версия которого параметризуется через `ARG NG_VERSION`.
2. Устанавливает переменную окружения `ENV NG_VERSION`, значение которой берется из `ARG`.
3. Создает файл `/opt/$ARG_FILE`, где значение переменной передается через `ARG`, но не сохраняется в `ENV`.

```dockerfile
ARG NG_VERSION=stable-alpine
FROM nginx:${NG_VERSION}

ARG NG_VERSION
ENV NG_VERSION=${NG_VERSION}

ARG ARG_FILE=default_file.txt
RUN touch /opt/${ARG_FILE}
```

**Разбор директив и параметров:**
* `ARG NG_VERSION=stable-alpine` (до `FROM`) — объявляет аргумент сборки с именем `NG_VERSION` и значением по умолчанию `stable-alpine` для подстановки в базовый образ.
* `FROM nginx:${NG_VERSION}` — выбирает базовый образ, подставляя значение аргумента `NG_VERSION` в качестве тега.
* `ARG NG_VERSION` (после `FROM`) — повторное объявление аргумента внутри контекста сборки образа. **Критически важный нюанс:** любой `ARG`, объявленный до `FROM`, сбрасывается после инструкции `FROM` и не виден внутри дальнейших шагов сборки, пока не будет объявлен повторно без значения (тогда он унаследует значение, переданное через `--build-arg`).
* `ENV NG_VERSION=${NG_VERSION}` — сохраняет значение аргумента `NG_VERSION` в постоянную переменную окружения образа, чтобы она была доступна внутри запущенного контейнера.
* `ARG ARG_FILE=default_file.txt` — объявляет временный аргумент сборки, который будет виден только на этапе выполнения инструкций `Dockerfile`, но не попадет в переменные окружения (`ENV`) итогового контейнера.
* `RUN touch /opt/${ARG_FILE}` — создает пустой файл в директории `/opt/` с именем, переданным через `ARG_FILE`.

**Пример использования:** `docker build --build-arg NG_VERSION=1.25-alpine --build-arg ARG_FILE=build_info.txt -t my-nginx:custom .` (сборка образа с переопределением всех значений по умолчанию).

## Чекпоинт 2: Сборка образа nginx:inno-dkr-10 с передачей аргументов

Выполняем сборку образа, передавая через флаг `--build-arg` значения для обоих аргументов (`NG_VERSION` и `ARG_FILE`):

```bash
docker build --build-arg NG_VERSION=stable-alpine --build-arg ARG_FILE=inno_dkr_10.txt -t nginx:inno-dkr-10 .
```

**Разбор команды и флагов:**
* `docker build` — запуск процесса сборки образа из `Dockerfile`.
* `--build-arg NG_VERSION=stable-alpine` — передает значение `stable-alpine` в аргумент `NG_VERSION` (используется и для выбора базового образа `nginx:stable-alpine`, и для записи в `ENV`).
* `--build-arg ARG_FILE=inno_dkr_10.txt` — передает имя файла `inno_dkr_10.txt` в аргумент `ARG_FILE` для создания `/opt/inno_dkr_10.txt` во время сборки.
* `-t nginx:inno-dkr-10` — присваивает собранному образу имя репозитория `nginx` и тег `inno-dkr-10`.
* `.` — указывает текущую директорию в качестве контекста сборки.

### Нюансы и возможные ошибки
Если забыть продублировать `ARG NG_VERSION` после строки `FROM nginx:${NG_VERSION}`, переменная `ENV NG_VERSION=${NG_VERSION}` окажется пустой (`NG_VERSION=`), так как директива `FROM` очищает область видимости всех предыдущих `ARG`.

**Пример использования:** `docker build --build-arg NG_VERSION=latest -f /home/user/Dockerfile -t nginx:inno-dkr-10 /home/user` (сборка с явным указанием пути к `Dockerfile` и контексту).

## Чекпоинт 3: Вывод списка образов на хосте

Проверяем, что образ `nginx:inno-dkr-10` успешно собран и сохранен локально:

```bash
docker images
```

**Разбор команды и параметров:**
* `docker images` — выводит список всех локальных образов на хосте. В таблице должны отображаться и скачанный базовый образ `nginx:stable-alpine`, и собранный нами `nginx:inno-dkr-10`.

**Пример использования:** `docker images --filter "reference=nginx:inno-dkr-*"` (вывод списка образов с фильтрацией по маске имени и тега).

## Чекпоинт 4: Запуск контейнера с передачей переменной окружения

Запускаем контейнер из собранного образа в фоновом режиме, передавая дополнительную переменную окружения `INNO=DKR10` на этапе старта:

```bash
docker run -d --name inno-dkr-10 -e INNO=DKR10 nginx:inno-dkr-10
```

**Разбор команды и флагов:**
* `docker run` — создает и запускает новый контейнер.
* `-d` (`--detach`) — запускает контейнер в фоновом режиме.
* `--name inno-dkr-10` — назначает контейнеру имя `inno-dkr-10`.
* `-e INNO=DKR10` (сокращение от `--env INNO=DKR10`) — передает переменную окружения `INNO` со значением `DKR10` непосредственно в запущенный контейнер (в дополнение к тем переменным, которые уже зашиты в образ через `ENV`).
* `nginx:inno-dkr-10` — имя и тег образа, из которого создается контейнер.

**Пример использования:** `docker run -d --name inno-dkr-10 --env-file .env nginx:inno-dkr-10` (массовая загрузка переменных окружения из локального файла `.env` при старте контейнера).

## Чекпоинт 5: Проверка списка запущенных контейнеров

Убеждаемся, что контейнер `inno-dkr-10` успешно запустился и работает:

```bash
docker ps
```

**Разбор команды и параметров:**
* `docker ps` — выводит список всех работающих в данный момент контейнеров. В колонке `NAMES` должен присутствовать `inno-dkr-10` со статусом `Up`.

**Пример использования:** `docker ps -f "name=inno-dkr-10"` (проверка статуса конкретного контейнера по его имени).

## Чекпоинт 6: Проверка переменных окружения внутри контейнера

Выводим список всех переменных окружения внутри работающего контейнера `inno-dkr-10`, чтобы убедиться в наличии `NG_VERSION` (из `Dockerfile`) и `INNO` (из `docker run`), а также в отсутствии `ARG_FILE`:

```bash
docker exec inno-dkr-10 env
```

**Разбор команды и параметров:**
* `docker exec` — выполняет команду внутри уже запущенного контейнера.
* `inno-dkr-10` — имя целевого контейнера.
* `env` — стандартная утилита Linux, выводящая все активные переменные окружения текущего процесса. В выводе должны присутствовать строки `NG_VERSION=stable-alpine` и `INNO=DKR10`, но **не должно быть** `ARG_FILE`.

**Пример использования:** `docker exec inno-dkr-10 printenv NG_VERSION INNO` (точечный вывод значений только указанных переменных окружения).

## Чекпоинт 7: Проверка созданного файла в директории /opt/

Проверяем содержимое директории `/opt/` внутри контейнера, чтобы убедиться, что файл с именем из `ARG_FILE` был успешно создан на этапе сборки:

```bash
docker exec inno-dkr-10 ls -la /opt/
```

**Разбор команды и параметров:**
* `docker exec inno-dkr-10` — выполнение команды в контейнере `inno-dkr-10`.
* `ls -la /opt/` — вывод подробного списка всех файлов (включая скрытые, `-a`) в формате расширенной таблицы (`-l`) в директории `/opt/`. В выводе должен отображаться файл `inno_dkr_10.txt`.

**Пример использования:** `docker exec inno-dkr-10 test -f /opt/inno_dkr_10.txt && echo "File exists"` (программная проверка существования файла внутри контейнера для скриптов).
