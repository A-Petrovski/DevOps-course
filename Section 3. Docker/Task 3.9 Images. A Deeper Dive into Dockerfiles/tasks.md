## Чекпоинт 1: Создание конфигурации Nginx и Dockerfile

### 1.1. Подготовка конфигурационного файла `nginx.conf`
Перед сборкой образа необходимо подготовить конфигурационный файл `nginx.conf` в той же директории, где будет находиться `Dockerfile`. Он настраивает сервер на прослушивание 80-го порта и возврат требуемой текстовой строки.

```nginx
events {
    worker_connections 1024;
}

http {
    server {
        listen 80;
        location / {
            default_type text/plain;
            return 200 "Welcome to the training program Innowise: Docker!\n";
        }
    }
}
```

**Разбор параметров конфигурации:**
* `events { worker_connections 1024; }` — обязательный блок в `nginx.conf`, определяющий максимальное количество одновременных соединений на один рабочий процесс.
* `listen 80;` — указывает Nginx принимать входящие HTTP-подключения на стандартном порту `80` внутри контейнера.
* `location /` — блок обработки запросов к корневому URL.
* `default_type text/plain;` — устанавливает MIME-тип ответа как обычный текст (чтобы браузер или утилита не пытались скачать ответ как бинарный файл).
* `return 200 "..."` — немедленно возвращает HTTP-статус `200 OK` и заданную строку с переносом строки `\n`.

**Пример использования:** `nginx -t -c /etc/nginx/nginx.conf` (проверка синтаксиса конфигурационного файла перед перезапуском службы).

---

### 1.2. Написание `Dockerfile`
Создаем файл `Dockerfile` со следующими требованиями:
1. Базовый образ `ubuntu:18.04`.
2. Установка пакета `nginx`.
3. Копирование конфигурационного файла `nginx.conf`.
4. Запуск `nginx` через `ENTRYPOINT`.
5. Передача аргументов `-g daemon off;` через `CMD` (как в официальном образе `nginx:stable`).
6. Рабочая директория `/etc/nginx/`.
7. Определение тома `VOLUME` по пути `/var/lib/nginx`.

```dockerfile
FROM ubuntu:18.04

RUN apt-get update && \
    apt-get install -y nginx && \
    rm -rf /var/lib/apt/lists/*

COPY nginx.conf /etc/nginx/nginx.conf

WORKDIR /etc/nginx/

VOLUME /var/lib/nginx

EXPOSE 80

ENTRYPOINT ["nginx"]
CMD ["-g", "daemon off;"]
```

**Разбор директив и параметров:**
* `FROM ubuntu:18.04` — задает базовый образ операционной системы, на основе которого собирается наш образ.
* `RUN apt-get update && apt-get install -y nginx && rm -rf /var/lib/apt/lists/*` — обновляет индекс пакетов, устанавливает `nginx` без интерактивного подтверждения (`-y`) и очищает кэш `apt` в одном слое для уменьшения итогового размера образа.
* `COPY nginx.conf /etc/nginx/nginx.conf` — копирует локальный файл конфигурации из контекста сборки внутрь файловой системы образа.
* `WORKDIR /etc/nginx/` — устанавливает рабочую директорию внутри контейнера (в нее же будет попадать пользователь при входе через `docker exec`).
* `VOLUME /var/lib/nginx` — создает точку монтирования для внешнего тома Docker, чтобы данные в директории `/var/lib/nginx` сохранялись независимо от жизненного цикла контейнера.
* `EXPOSE 80` — документирует, что приложение внутри контейнера слушает 80-й TCP-порт.
* `ENTRYPOINT ["nginx"]` — задает основной исполняемый файл в `exec`-формате (без запуска оболочки `/bin/sh`).
* `CMD ["-g", "daemon off;"]` — передает параметры по умолчанию в `ENTRYPOINT`. Директива `daemon off;` заставляет Nginx работать на переднем плане (foreground), чтобы контейнер не завершал работу сразу после старта.

**Пример использования:** `docker build -f Dockerfile.custom -t my-nginx:v1 .` (сборка образа с указанием нестандартного имени файла инструкции).

## Чекпоинт 2: Сборка образа nginx:inno-dkr-09

Выполняем сборку образа из текущей директории (`.`):

```bash
sudo docker build -t nginx:inno-dkr-09 .
```

**Разбор команды и флагов:**
* `sudo` — запуск команды с правами суперпользователя (необходимо, если текущий пользователь не добавлен в системную группу `docker`).
* `docker build` — команда сборки Docker-образа из `Dockerfile`.
* `-t nginx:inno-dkr-09` — флаг `--tag`, задающий имя репозитория (`nginx`) и тег (`inno-dkr-09`) для собранного образа.
* `.` — путь к контексту сборки (текущая директория, откуда Docker берет `Dockerfile` и `nginx.conf`).

### Нюансы и разбор ошибок
При попытке запустить сборку без прав администратора (`docker build -t nginx:inno-dkr-09 .`) возникла ошибка:
`ERROR: permission denied while trying to connect to the Docker API at unix:///var/run/docker.sock`
* **Причина:** Сокет демона Docker принадлежит пользователю `root` и группе `docker`, а текущий пользователь не состоит в этой группе.
* **Решение:** Использовать `sudo` перед командами `docker` или добавить пользователя в группу командой `sudo usermod -aG docker $USER` (с последующим перелогином).

**Пример использования:** `docker build --no-cache -t nginx:inno-dkr-09 .` (принудительная пересборка всех слоев образа без использования локального кэша).

## Чекпоинт 3: Вывод списка образов на хосте

Проверяем, что новый образ успешно появился в локальном хранилище:

```bash
docker images
```

**Разбор команды и параметров:**
* `docker images` (аналог `docker image ls`) — выводит таблицу всех локальных образов на хосте с указанием репозитория (`REPOSITORY`), тега (`TAG`), идентификатора (`IMAGE ID`), времени создания и размера.

**Пример использования:** `docker images nginx` (фильтрация списка образов по конкретному имени репозитория).

## Чекпоинт 4: Запуск контейнера в фоне с пробросом порта

Запускаем контейнер из собранного образа в фоновом режиме с привязкой к локальному интерфейсу хоста `127.0.0.1:8901`:

```bash
docker run -d -p 127.0.0.1:8901:80 --name inno-nginx-09 nginx:inno-dkr-09
```

**Разбор команды и флагов:**
* `docker run` — создает и запускает новый контейнер из указанного образа.
* `-d` (`--detach`) — запускает контейнер в фоновом режиме и выводит его ID в терминал.
* `-p 127.0.0.1:8901:80` (`--publish`) — пробрасывает порт `80` контейнера на порт `8901` хоста, ограничивая доступ только локальным адресом `127.0.0.1` (извне сервера порт доступен не будет).
* `--name inno-nginx-09` — задает читаемое уникальное имя для контейнера.
* `nginx:inno-dkr-09` — имя и тег образа, из которого разворачивается контейнер.

### Нюансы и разбор ошибок
При первом запуске с именем `--name inno-nginx` возникла ошибка:
`docker: Error response from daemon: Conflict. The container name "/inno-nginx" is already in use by container "..."`
* **Причина:** В системе уже существовал созданный ранее (работающий или остановленный) контейнер с именем `inno-nginx`. Имена контейнеров в пределах одного хоста должны быть уникальными.
* **Решение:** Удалить конфликтующий старый контейнер (`docker rm -f inno-nginx`) либо указать при запуске новое уникальное имя (например, `--name inno-nginx-09`), либо не указывать флаг `--name` вовсе, чтобы Docker сгенерировал имя автоматически.

**Пример использования:** `docker run -d --restart unless-stopped -p 127.0.0.1:8901:80 nginx:inno-dkr-09` (запуск контейнера с автоматическим перезапуском при падении или перезагрузке сервера).

## Чекпоинт 5: Проверка списка запущенных контейнеров

Убеждаемся, что контейнер находится в статусе `Up` и проброс портов настроен корректно:

```bash
docker ps
```

**Разбор команды и параметров:**
* `docker ps` (аналог `docker container ls`) — отображает список всех активных (запущенных в данный момент) контейнеров. В колонке `PORTS` должно отображаться `127.0.0.1:8901->80/tcp`.

**Пример использования:** `docker ps -a` (вывод всех контейнеров, включая остановленные или завершившиеся с ошибкой).

## Чекпоинт 6: Проверка работы веб-сервера

Отправляем HTTP-запрос к проброшенному порту на локальном хосте:

```bash
curl http://127.0.0.1:8901
```

**Разбор команды и параметров:**
* `curl` — консольная утилита для отправки сетевых запросов по различным протоколам.
* `http://127.0.0.1:8901` — адрес и порт на хост-машине, перенаправляющие трафик на 80-й порт внутри контейнера. Ожидаемый вывод в терминале: `Welcome to the training program Innowise: Docker!`.

**Пример использования:** `curl -i http://127.0.0.1:8901` (вывод ответа сервера вместе со служебными HTTP-заголовками, такими как `HTTP/1.1 200 OK` и `Server: nginx`).
