# Task 3.2 Basics. Контрольные вопросы для самопроверки

## 1. Каковы основные компоненты и функции Docker Engine?

**Docker Engine** — это клиент-серверное приложение, состоящее из трёх ключевых компонентов:

1. **Docker Daemon (`dockerd`)** — фоновый серверный процесс, который управляет объектами Docker (образами, контейнерами, сетями и томами) и взаимодействует с ядром операционной системы.
2. **Docker REST API** — программный интерфейс, который определяет протокол взаимодействия с демоном `dockerd` и позволяет отправлять ему команды.
3. **Docker CLI (`docker`)** — консольная утилита (клиент), через которую пользователь вводит команды в терминале; CLI преобразует их в запросы к REST API.

*(На более низком уровне `dockerd` также делегирует управление жизненным циклом контейнеров компонентам **containerd** и **runc**).*

**Пример проверки статуса и версии компонентов:**
```bash
docker version
systemctl status docker
```

## 2. Как Docker Engine взаимодействует с операционной системой на уровне контейнеров?

Docker Engine не эмулирует аппаратное обеспечение (как виртуальные машины), а использует встроенные механизмы ядра Linux для изоляции процессов на одном хосте:

1. **Namespaces (пространства имён)** — обеспечивают изоляцию видимости ресурсов. Каждый контейнер получает свои изолированные деревья процессов (`PID`), сетевые интерфейсы (`NET`), точки монтирования (`MNT`), имена хостов (`UTS`) и пользователей (`USER`).
2. **cgroups (Control Groups — контрольные группы)** — ограничивают и учитывают потребление аппаратных ресурсов (CPU, оперативной памяти, дискового ввода-вывода) для каждого контейнера, чтобы один контейнер не исчерпал ресурсы всей хост-системы.
3. **UnionFS (объединённые файловые системы, например `overlay2`)** — позволяют строить образы из слоёв только для чтения (`read-only`) и добавлять поверх них тонкий слой для записи (`read-write`) при запуске контейнера.

**Пример просмотра изолированных пространств имён контейнера на хосте:**
```bash
sudo docker inspect --format '{{.State.Pid}}' inno-dkr-02
sudo ls -l /proc/<PID_контейнера>/ns
```

## 3. Что такое Docker REST API и как оно обеспечивает программное управление Docker?

**Docker REST API** — это HTTP-интерфейс, предоставляемый демоном `dockerd`, через который внешние клиенты и приложения могут управлять Docker программно без использования CLI.

* **Механизм работы:** По умолчанию REST API слушает локальный UNIX-сокет `/var/run/docker.sock` (для безопасности внутри хоста), но при необходимости может быть настроен на работу по сети через TCP-порт (`2375` без шифрования или `2376` с TLS).
* **Программное управление:** Любая программа, скрипт (на Python, Go и др.) или утилита (`curl`) может отправить стандартный HTTP-запрос (`GET`, `POST`, `DELETE`) на соответствующий эндпоинт API и получить структурированный ответ в формате JSON.

**Пример прямого запроса к Docker REST API через UNIX-сокет:**
```bash
sudo curl --unix-socket /var/run/docker.sock http://localhost/info
```

## 4. Как использовать Docker REST API для управления контейнерами, образами, сетями и другими объектами Docker?

Управление объектами сводится к отправке HTTP-запросов на конкретные эндпоинты API (с указанием версии API, например `/v1.45/`):

* **Контейнеры (`/containers`):**
  * `GET /containers/json` — получить список запущенных контейнеров (аналог `docker ps`).
  * `POST /containers/create` — создать новый контейнер (передав конфигурацию в теле JSON).
  * `POST /containers/{id}/start` — запустить созданный контейнер.
  * `DELETE /containers/{id}?force=true` — удалить контейнер (аналог `docker rm -f`).
* **Образы (`/images`):**
  * `GET /images/json` — получить список локальных образов (аналог `docker images`).
  * `POST /images/create?fromImage=nginx&tag=stable` — скачать образ из реестра (аналог `docker pull`).
* **Сети (`/networks`) и тома (`/volumes`):**
  * `GET /networks` — получить список сетей (аналог `docker network ls`).
  * `POST /volumes/create` — создать новый том (аналог `docker volume create`).

**Практический пример (получение списка запущенных контейнеров и запуск конкретного контейнера через `curl`):**
```bash
# Список запущенных контейнеров
sudo curl --unix-socket /var/run/docker.sock http://localhost/containers/json

# Остановка контейнера inno-dkr-02 через REST API
sudo curl -X POST --unix-socket /var/run/docker.sock http://localhost/containers/inno-dkr-02/stop
```
