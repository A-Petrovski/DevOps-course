## Чекпоинт 1. Подготовка конфигурационного файла nginx

Чтобы веб-сервер внутри контейнера возвращал требуемую строку `Welcome to the training program Innowise: Docker`, необходимо скачать оригинальный конфигурационный файл из методички/репозитория курса или сформировать конфигурацию вручную.

### Вариант А. Скачивание готового файла по ссылке (если дана в задании)
```bash
curl -o ~/nginx.conf <URL_конфигурационного_файла>
```

### Вариант Б. Создание минимального рабочего `nginx.conf` вручную (если ссылки нет)
```bash
printf 'events {}\nhttp {\n  server {\n    listen 80;\n    location / {\n      return 200 "Welcome to the training program Innowise: Docker\\n";\n    }\n  }\n}\n' > ~/nginx.conf
```

### Разбор параметров и команд
* **`curl -o ~/nginx.conf <URL>`** — скачивает файл по указанной ссылке и сохраняет его под именем `nginx.conf` в домашнюю директорию (`~`).
  * **`-o` (`--output`)** — указывает путь и имя файла, в который нужно записать скачанный результат.
* **`printf '...' > ~/nginx.conf`** — форматирует строку с переносами (`\n`) и записывает её в файл `~/nginx.conf`, перезаписывая старое содержимое.
* **`events {}`** — обязательная секция в основном конфиге Nginx, отвечающая за настройку обработки соединений.
* **`http { server { listen 80; ... } }`** — секция HTTP-сервера, прослушивающая порт `80` внутри контейнера.
* **`return 200 "..."`** — директива, которая при обращении к корню сайта (`location /`) немедленно возвращает HTTP-статус `200 OK` и указанный текст.

**Пример использования:** `docker run --rm nginx:stable cat /etc/nginx/nginx.conf > ~/nginx.conf` (извлечение стандартного основного конфига Nginx напрямую из образа без сохранения контейнера).

## Чекпоинт 2. Запуск контейнера с заданными параметрами

Запуск контейнера в фоне с привязкой к локальному интерфейсу хоста и пробросом файла конфигурации:

```bash
sudo docker run -d -p 127.0.0.1:8889:80 --name inno-dkr-02 -v $(pwd)/nginx.conf:/etc/nginx/nginx.conf:ro nginx:stable
```

### Разбор параметров и флагов
* **`sudo`** — запуск команды с правами суперпользователя (необходимо, если текущий пользователь не добавлен в группу `docker`).
* **`docker run`** — команда создания и запуска нового контейнера из указанного образа.
* **`-d` (`--detach`)** — запускает контейнер в фоновом режиме (демоне) и выводит в консоль его идентификатор.
* **`-p 127.0.0.1:8889:80`** — правило проброса портов (port mapping) в формате `IP_хоста:порт_хоста:порт_контейнера`:
  * **`127.0.0.1`** — ограничивает доступ к порту только локальным интерфейсом хоста (localhost).
  * **`8889`** — порт на хостовой машине, на который будут приходить запросы.
  * **`80`** — порт внутри контейнера, который слушает Nginx.
* **`--name inno-dkr-02`** — присваивает контейнеру фиксированное имя `inno-dkr-02`.
* **`-v $(pwd)/nginx.conf:/etc/nginx/nginx.conf:ro`** — монтирование тома (bind mount) для подмены основного конфигурационного файла:
  * **`$(pwd)/nginx.conf`** — абсолютный путь к скачанному файлу на хосте (подставляется автоматически из текущей директории).
  * **`/etc/nginx/nginx.conf`** — путь к основному конфигурационному файлу внутри контейнера.
  * **`ro` (`read-only`)** — монтирует файл в режиме «только для чтения», защищая конфиг на хосте от случайного изменения процессами внутри контейнера.
* **`nginx:stable`** — название образа (`nginx`) и тег стабильной ветки (`stable`).

**Пример использования:** `sudo docker run -d -p 127.0.0.1:8080:80 --name web-test --restart unless-stopped -v /opt/nginx/nginx.conf:/etc/nginx/nginx.conf:ro nginx:stable`

## Чекпоинт 3. Проверка работы, статуса контейнера и контрольной суммы md5sum

### 1. Проверка ответа веб-сервера
```bash
curl 127.0.0.1:8889
```
*Ожидаемый вывод:* `Welcome to the training program Innowise: Docker`

### 2. Проверка списка запущенных контейнеров
```bash
sudo docker ps
```
*Ожидаемый вывод:* в таблице отображается контейнер `inno-dkr-02` в статусе `Up`.

### 3. Подсчет `md5sum` конфигурационного файла внутри контейнера
```bash
sudo docker exec -ti inno-dkr-02 md5sum /etc/nginx/nginx.conf
```

### Разбор параметров и флагов
* **`curl 127.0.0.1:8889`** — отправляет HTTP GET-запрос на локальный адрес и порт `8889`, выводя тело ответа в терминал.
* **`docker ps`** — выводит список всех запущенных в данный момент контейнеров.
* **`docker exec`** — выполняет указанную команду внутри уже работающего контейнера.
* **`-t` (`--tty`)** — выделяет псевдотерминал (TTY) для корректного отображения вывода.
* **`-i` (`--interactive`)** — сохраняет стандартный поток ввода (STDIN) открытым.
* **`inno-dkr-02`** — имя целевого контейнера.
* **`md5sum /etc/nginx/nginx.conf`** — системная утилита Linux внутри контейнера, вычисляющая 128-битный MD5-хеш файла конфигурации для проверки его целостности.

**Пример использования:** `sudo docker exec -it inno-dkr-02 nginx -t` (проверка синтаксиса примонтированного конфигурационного файла Nginx внутри запущенного контейнера).

## Разбор сложных моментов и ошибок

1. **Ошибка `docker: invalid hostPort: 127.0.0.1`:**
   * **Причина:** В параметре `-p 127.0.0.1:8889` был пропущен внутренний порт контейнера (`:80`). При наличии только одного двоеточия Docker воспринимает левую часть (`127.0.0.1`) как номер порта хоста, а правую (`8889`) — как порт контейнера.
   * **Решение:** Всегда указывать все три части при привязке к конкретному IP-адресу: `-p 127.0.0.1:8889:80`.

2. **Проброс пустой директории вместо файла при ошибке пути:**
   * **Причина:** Если на момент выполнения `docker run -v \$(pwd)/nginx.conf:/etc/nginx/nginx.conf` файл `nginx.conf` отсутствует по указанному пути на хосте, Docker автоматически создаст на хосте **пустую папку** с именем `nginx.conf`, из-за чего Nginx внутри контейнера упадет с ошибкой запуска.
   * **Решение:** Перед запуском контейнера всегда проверять наличие и тип объекта командой `ls -la ~/nginx.conf` (первый символ прав должен быть `-`, а не `d`).

3. **Пересоздание контейнера при изменении параметров или имени:**
   * **Причина:** Если контейнер с именем `inno-dkr-02` уже был создан (даже если он остановлен или упал с ошибкой), повторный запуск `docker run --name inno-dkr-02 ...` вызовет конфликт имён.
   * **Решение:** Перед повторным запуском удалить старый контейнер командой `sudo docker rm -f inno-dkr-02`.
