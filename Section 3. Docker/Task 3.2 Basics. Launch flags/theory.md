## Введение

В ходе выполнения предыдущего задания были вызваны следующие команды:
* `docker run -d -p 127.0.0.1:28080:80 --name inno-dkr-01 nginx:stable`
* `docker ps`
* `docker stop inno-dkr-01`

Все команды начинаются с вызова утилиты `docker` — это Docker CLI. Под капотом Docker CLI обращается к Docker REST API, который отправляет системные запросы к Docker Daemon для исполнения команд.

---

## Условные обозначения

* **`\$VAR_NAME`** — переменная, задаваемая вне задачи, она может иметь любое значение в зависимости от контекста. Пример: `docker run \$IMAGE`.
* **`[]`** — необязательное содержимое внутри квадратных скобок, команда может работать без него. Пример: `docker run [-d] \(IMAGE[:\)TAG]`.
* **`[() ...]`** — необязательное содержимое внутри квадратных скобок, но команда внутри круглых скобок может повторяться сколько угодно раз. Пример: при подстановке значений в шаблон `docker run [-d] [(-p \(HOST_PORT:\)CONTAINER_PORT) ...] \(IMAGE[:\)TAG]` результатом будет `docker run -d -p 80:80 -p 443:443 nginx:stable`.
* **`(\(VAR1\vert{}\)VAR2)`** — возможные значения: `VAR1` или `VAR2`.

Каждая команда поддерживает вывод справки с добавлением флага `--help` в конце, что приводит к выводу всех ключей, которые можно передавать конкретной команде с кратким описанием. Более развернутое описание находится в официальной документации.

## Разбор базовых команд

### `docker run`

Команда используется для запуска контейнера. Имеет большое количество параметров, которые позволяют определить поведение контейнера: его разрешения, сетевые настройки и другие параметры.

Аргументы и опции:
* **`-d` (`detach`)** — означает, что нужно запустить контейнер и оставить работать его в фоне. Без этого флага контейнер запускается так, как если бы команда была запущена вручную: логи утилиты отправляются в консоль, других действий при этом совершать нельзя, а при закрытии консоли приложение останавливается.
* **`-p 127.0.0.1:28080:80`** — определяет перенаправление сетевых портов (port mapping), показывая, как получить доступ к приложению внутри контейнера из хостовой системы так, будто оно запущено на самой хостовой системе.
  * Общий синтаксис флага: `-p [[\(HOST_LISTEN_ADDRESS:]\)HOST_LISTEN_PORT:]\(CONTAINER_LISTEN_PORT[/\)PROTOCOL]`
  * **`HOST_LISTEN_ADDRESS`** — адрес, на котором должен быть проброшен порт на хосте. По умолчанию `0.0.0.0` (запросы слушаются на всех адресах). Возможные значения: `(ipv4|ipv6)` адрес.
  * **`HOST_LISTEN_PORT`** — порт, на который должен быть проброшен порт на хосте. При отсутствии использует случайный порт.
  * **`CONTAINER_LISTEN_PORT`** — порт внутри контейнера, который должен быть проброшен на хост. Возможные значения: `(0 .. 65535)`.
  * **`PROTOCOL`** — протокол, который требуется пробросить. Возможные значения: `(udp|tcp)`.
  * Пример после подстановки значений: `-p 192.168.1.100:8080:80/tcp`.
* **`--name rbm-dkr-01`** — имя контейнера. В случае, если опция не задана, Docker сгенерирует случайное имя.
* **`nginx:stable`** — имя образа и его тег. Образ запускает nginx из ветки `stable` (версии с четной минорной версией).

---

### `docker ps`

Команда выводит список работающих контейнеров, их имена, используемый для запуска образ, порты и прочую информацию.
* По умолчанию команда выводит только работающие контейнеры.
* С использованием флага **`-a`** можно получить список всех контейнеров, которые есть в системе, в том числе и остановленные.

---

### `docker rm`

Команда **`docker rm --force`** используется для удаления запущенных контейнеров.
* Без флага **`--force`** при попытке удалить работающий контейнер Docker укажет на необходимость предварительной остановки контейнера, после чего можно будет выполнить удаление.
* Использование `docker rm --force` сродни использованию `git push --force`: применение возможно, но только обдуманное.
