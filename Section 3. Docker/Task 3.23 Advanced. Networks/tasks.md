## Чекпоинт 1: Создание пользовательской сети

**Задача:** Создай сеть с драйвером `bridge` и именем `inno-25-bridge`.

```bash
docker network create --driver bridge inno-25-bridge
```

### Разбор параметров и флагов:
* `docker network create` — команда создания новой виртуальной сети в Docker.
* `--driver bridge` (короткий аналог `-d bridge`) — явное указание сетевого драйвера моста. Используется по умолчанию, но указывается для читаемости.
* `inno-25-bridge` — уникальное имя создаваемой пользовательской сети.

### Нюансы и подводные камни:
* При создании пользовательской `bridge`-сети Docker автоматически выделяет ей подсеть из диапазона `172.17.0.0/16` – `172.31.0.0/16`. Если ваша корпоративная сеть или VPN использует пересекающийся диапазон, трафик начнет маршрутизироваться некорректно (решается явным указанием флага `--subnet`).

**Пример использования:** `docker network create -d bridge --subnet 10.10.50.0/24 prod-backend-net`

## Чекпоинт 2: Вывод списка всех сетей

**Задача:** Выведи список всех сетей.

```bash
docker network ls
```

### Разбор параметров и флагов:
* `docker network ls` — отображает таблицу всех зарегистрированных сетей на хосте (их ID, имя, драйвер и область действия `Scope`).

### Нюансы и подводные камни:
* В выводе всегда присутствуют 3 системные сети (`bridge`, `host`, `none`). Важно не путать имя дефолтной сети `bridge` с одноименным драйвером `bridge`: в дефолтной сети не работает автоматический DNS-резолвинг между контейнерами, а в пользовательской сети на том же драйвере — работает.

**Пример использования:** `docker network ls --filter driver=bridge --format "table {{.ID}}	{{.Name}}	{{.Driver}}"`

## Чекпоинт 3: Запуск Nginx в фоне внутри новой сети

**Задача:** Создай из образа `nginx:stable` контейнер с именем `inno-dkr-25-nginx`, работающий в фоне и подключенный к новой сети.

```bash
docker run -d --name inno-dkr-25-nginx --network inno-25-bridge nginx:stable
```

### Разбор параметров и флагов:
* `docker run` — создание и запуск нового контейнера.
* `-d` (`--detach`) — запуск контейнера в фоновом (отсоединенном) режиме с выводом его полного ID в терминал.
* `--name inno-dkr-25-nginx` — присвоение контейнеру фиксированного имени, которое автоматически регистрируется во встроенном DNS Docker.
* `--network inno-25-bridge` — подключение контейнера к указанной пользовательской сети вместо дефолтной `bridge`.
* `nginx:stable` — имя образа и тег стабильной ветки веб-сервера.

### Разбор ошибок и сложных моментов (из практики):
1. **Конфликт имен (`Conflict. The container name ... is already in use`):** Если контейнер с таким именем уже создавался ранее (даже если он остановлен), Docker не даст запустить новый с тем же именем. Необходимо предварительно удалить старый контейнер командой `docker rm -f <имя>`.
2. **Опечатка в имени контейнера:** При запуске была допущена опечатка (`inno-dkr-25nginx` вместо `inno-dkr-25-nginx`), из-за чего запрос по целевому имени приводил к ошибке DNS. Имя контейнера в `--name` должно посимвольно совпадать с DNS-запросом.
3. **Лишние флаги для демонов:** Для фоновых сервисов вроде Nginx не нужно добавлять `-it` — достаточно одного `-d`.

**Пример использования:** `docker run -d --restart unless-stopped --name web-proxy --network app-net -p 8080:80 nginx:stable`

## Чекпоинт 4: Запуск Alpine, установка curl и обращение по DNS

**Задача:** Запусти второй контейнер с именем `inno-dkr-25-pinger` в интерактивном режиме из образа `alpine:3.10` и подключенный к новой сети, установи в нем `curl` и обратись к контейнеру `inno-dkr-25-nginx` по DNS-записи.

```bash
# 1. Запуск интерактивного контейнера в той же сети
docker run -it --name inno-dkr-25-pinger --network inno-25-bridge alpine:3.10

# 2. Установка curl внутри оболочки Alpine
apk add --no-cache curl

# 3. Проверка доступности Nginx по имени контейнера (DNS)
curl http://inno-dkr-25-nginx
```

### Разбор параметров и флагов:
* `-it` — комбинация флагов `-i` (`--interactive`, держит STDIN открытым) и `-t` (`--tty`, выделяет псевдо-терминал) для интерактивной работы в консоли контейнера.
* `alpine:3.10` — легковесный базовый образ Linux (по умолчанию запускает оболочку `/bin/sh`).
* `apk add` — команда установки пакетов через пакетный менеджер Alpine Linux.
* `--no-cache` — скачивает индекс репозитория в оперативную память и удаляет его после установки пакета, не засоряя файловую систему контейнера.
* `curl http://inno-dkr-25-nginx` — отправка HTTP GET-запроса по имени целевого контейнера.

### Разбор ошибок и сложных моментов (из практики):
* **Ошибка `curl: (6) Could not resolve host: inno-dkr-25-nginx`:** Возникает в трех случаях:
  1. Целевой контейнер остановлен или удален (встроенный DNS Docker `127.0.0.11` резолвит только запущенные контейнеры).
  2. Контейнеры находятся в разных сетях или в дефолтной сети `bridge`.
  3. Допущена опечатка в имени целевого контейнера при его создании (`--name`).

**Пример использования:** `docker run --rm -it --network inno-25-bridge alpine:3.10 sh -c "apk add --no-cache curl && curl -I http://inno-dkr-25-nginx"`

## Бонус: Инспекция сети и подключение контейнера на лету

**Задача:** Посмотреть сетевые параметры моста и подключить уже запущенный контейнер к пользовательской сети без перезапуска.

```bash
# Просмотр подсети, шлюза и списка подключенных контейнеров
docker network inspect inno-25-bridge

# Подключение работающего контейнера к сети на лету
docker network connect inno-25-bridge temp-web
```

### Разбор параметров и флагов:
* `docker network inspect <сеть>` — выводит подробную JSON-конфигурацию сети: драйвер, подсеть (`Subnet`), адрес шлюза (`Gateway`) и внутренние IPv4-адреса всех активных контейнеров.
* `docker network connect <сеть> <контейнер>` — добавляет работающему контейнеру новый виртуальный сетевой интерфейс (`eth1`), привязанный к указанной сети, сохраняя его предыдущие подключения.

**Пример использования:** `docker network inspect -f '{{range .Containers}}{{.Name}} -> {{.IPv4Address}}{{"
"}}{{end}}' inno-25-bridge`
