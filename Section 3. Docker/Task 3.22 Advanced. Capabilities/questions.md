# Контрольные вопросы для самопроверки: Task 3.22

## 1. Режимы безопасности в Docker: что означает параметр `--privileged` и как он влияет на безопасность контейнера и хостовой системы?

Флаг `--privileged` (по умолчанию `false`) снимает почти всю изоляцию на уровне ядра между контейнером и хостовой машиной: контейнер получает полный набор всех Linux capabilities, доступ ко всем устройствам хоста в `/dev` (дискам, сетевым интерфейсам, шинам) и возможность менять сетевой стек и параметры ядра хоста. При компрометации приложения внутри привилегированного контейнера злоумышленник может легко выйти за пределы изоляции (container escape) и получить полный контроль над хостовой ОС.

```bash
# Небезопасный запуск с полным доступом к ресурсам хоста (использовать только при крайней необходимости, например для Docker-in-Docker)
docker run --rm --privileged alpine ls /dev
```

## 2. Как использовать `--device` (`--devices`) для проброса устройств в контейнер и как это влияет на безопасность?

Опция `--device` позволяет точечно пробросить конкретное символьное или блочное устройство хоста внутрь контейнера без включения полного `--privileged` режима. С точки зрения безопасности это гораздо безопаснее `--privileged`, так как ограничивает поверхность атаки одним конкретным устройством, однако передача критичных устройств (например, системного диска `/dev/sda` или памяти `/dev/mem`) всё равно позволяет процессу внутри контейнера перезаписать файловую систему или данные хоста напрямую.

```bash
# Точечный проброс конкретного блочного устройства в контейнер с правами только на чтение (r)
docker run --rm --device=/dev/sdd:/dev/sdd:r nginx:stable-alpine
```

## 3. Какова роль директивы `USER` в Dockerfile и почему важно устанавливать правильного пользователя для безопасности контейнера?

Директива `USER` определяет UID/GID (имя или числовой идентификатор пользователя и группы), от имени которого будут выполняться инструкции `RUN`, `CMD` и `ENTRYPOINT`, а также сам основной процесс приложения при старте контейнера. По умолчанию процессы в Docker запускаются от имени `root` (UID `0`), который внутри контейнера совпадает с `root` на хосте; если злоумышленник проэксплуатирует уязвимость в приложении и вырвется из контейнера, он получит права суперпользователя на хост-машине. Запуск от непривилегированного пользователя (например, `USER 1001:1001`) реализует принцип наименьших привилегий и блокирует изменение системных файлов внутри контейнера и на примонтированных томах.

```dockerfile
FROM nginx:stable-alpine

# Запуск процесса от непривилегированного пользователя
USER nginx
```
