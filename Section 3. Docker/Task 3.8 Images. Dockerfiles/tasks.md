## Чекпоинт 1: Подготовка конфигурационного файла nginx.conf

**Задача:** Скачать или подготовить конфигурационный файл `nginx.conf`, который заставит веб-сервер возвращать строку `Welcome to the training program Innowise: Docker!`.

```bash
mkdir -p ~/task-3-8 && cd ~/task-3-8

cat << 'EOF' > nginx.conf
events {}

http {
    server {
        listen 80;
        location / {
            default_type text/plain;
            return 200 'Welcome to the training program Innowise: Docker!\n';
        }
    }
}
EOF
```

**Разбор использованных команд и директив:**
- `mkdir -p ~/task-3-8` — создаёт рабочую директорию контекста сборки; флаг `-p` подавляет ошибку, если папка уже существует, и создаёт родительские каталоги при необходимости.
- `cat << 'EOF' > nginx.conf` — записывает многострочный блок текста в файл `nginx.conf` (одинарные кавычки вокруг `'EOF'` защищают содержимое от интерпретации переменных оболочкой bash).
- `events {}` — обязательная секция конфигурации Nginx для обработки соединений (оставлена пустой для использования параметров по умолчанию).
- `http { ... }` — блок конфигурации HTTP-сервера.
- `listen 80;` — указывает Nginx принимать входящие подключения на стандартном 80-м порту внутри контейнера.
- `default_type text/plain;` — задаёт MIME-тип ответа как обычный текст, чтобы браузер или `curl` не пытались скачать ответ в виде бинарного файла.
- `return 200 '...'` — немедленно возвращает HTTP-статус `200 OK` с указанной текстовой строкой.

**Пример использования:** `wget https://example.com -O nginx.conf` (если в учебном стенде выдана прямая ссылка на скачивание готового конфига).

## Чекпоинт 2: Описание Dockerfile

**Задача:** Описать `Dockerfile`, в котором как базовый образ используется `nginx:stable`, а внутрь контейнера как основной конфигурационный файл копируется `nginx.conf`.

```bash
cat << 'EOF' > Dockerfile
FROM nginx:stable
COPY nginx.conf /etc/nginx/nginx.conf
EOF
```

**Разбор использованных директив и параметров:**
- `FROM nginx:stable` — задаёт базовый образ из Docker Hub (`nginx` — имя репозитория, `stable` — тег стабильной ветки релиза).
- `COPY` — инструкция копирования локальных файлов из контекста сборки в файловую систему образа.
- `nginx.conf` — относительный путь к исходному файлу в текущей директории (контексте сборки).
- `/etc/nginx/nginx.conf` — абсолютный путь назначения внутри контейнера, по которому Nginx по умолчанию ищет свой главный конфигурационный файл.

**Пример использования:** `COPY --chown=nginx:nginx nginx.conf /etc/nginx/nginx.conf` (копирование файла с одновременной сменой владельца и группы на пользователя `nginx`).

## Чекпоинт 3: Сборка Docker-образа

**Задача:** Собрать образ с именем `nginx` и тегом `inno-dkr-08`.

```bash
docker build -t nginx:inno-dkr-08 .
```

**Разбор использованных флагов и параметров:**
- `docker build` — команда запуска сборки образа по инструкциям из Dockerfile.
- `-t nginx:inno-dkr-08` (от `--tag`) — присваивает собранному образу имя репозитория (`nginx`) и тег (`inno-dkr-08`).
- `.` — указывает текущую директорию как контекст сборки (откуда `COPY` будет брать файлы и где по умолчанию ищется `Dockerfile`).

**Пример использования:** `docker build --no-cache -f Dockerfile.prod -t my-nginx:v1.0 .` (сборка без использования кэша слоёв из нестандартного файла `Dockerfile.prod`).

## Чекпоинт 4: Вывод списка образов на хосте

**Задача:** Убедиться, что новый образ успешно создан и сохранён в локальном хранилище Docker.

```bash
docker images
```

**Разбор использованных команд и параметров:**
- `docker images` — выводит таблицу всех локально доступных образов с указанием репозитория (`REPOSITORY`), тега (`TAG`), идентификатора (`IMAGE ID`), времени создания (`CREATED`) и размера (`SIZE`).

**Пример использования:** `docker images nginx` (вывод списка образов с фильтрацией только по репозиторию `nginx`).

## Чекпоинт 5: Запуск контейнера в фоне на 127.0.0.1:8900

**Задача:** Запустить контейнер из собранного образа в фоновом режиме с публикацией порта на локальном адресе хоста `127.0.0.1:8900`.

```bash
docker run -d --name task-3-8-nginx -p 127.0.0.1:8900:80 nginx:inno-dkr-08
```

**Разбор использованных флагов и параметров:**
- `docker run` — создаёт и запускает новый контейнер из указанного образа.
- `-d` (от `--detach`) — запускает контейнер в фоновом режиме и возвращает управление терминалу.
- `--name task-3-8-nginx` — задаёт читаемое уникальное имя контейнера для удобного управления.
- `-p 127.0.0.1:8900:80` (от `--publish`) — пробрасывает порт `80` контейнера на порт `8900` хоста, привязывая его строго к локальному loopback-интерфейсу `127.0.0.1` (сервис не будет доступен из внешней сети).
- `nginx:inno-dkr-08` — имя и тег образа, из которого создаётся контейнер.

**Пример использования:** `docker run -d --restart unless-stopped -p 127.0.0.1:8900:80 nginx:inno-dkr-08` (фоновый запуск с политикой автоматического перезапуска при сбоях или перезагрузке демона Docker).

## Чекпоинт 6: Вывод списка запущенных контейнеров

**Задача:** Проверить, что контейнер запустился, не упал из-за синтаксических ошибок в конфиге и слушает нужный порт.

```bash
docker ps
```

**Разбор использованных команд и параметров:**
- `docker ps` — отображает список всех запущенных в данный момент контейнеров, их статус (`Up`), проброшенные порты (`127.0.0.1:8900->80/tcp`) и имена.

**Пример использования:** `docker ps -a --filter "name=task-3-8-nginx"` (просмотр статуса конкретного контейнера, включая остановленные, если он аварийно завершился).

## Чекпоинт 7: Проверка работы сервиса

**Задача:** Обратиться по адресу `127.0.0.1:8900` и убедиться, что в ответ возвращается строка `Welcome to the training program Innowise: Docker!`.

```bash
curl http://127.0.0.1:8900
```

**Ожидаемый вывод:**
```text
Welcome to the training program Innowise: Docker!
```

**Разбор использованных команд и параметров:**
- `curl` — консольная утилита для отправки сетевых HTTP-запросов.
- `http://127.0.0.1:8900` — целевой URL с указанием протокола, локального IP-адреса и назначенного порта.

**Пример использования:** `curl -i http://127.0.0.1:8900` (отправка запроса с выводом HTTP-заголовков ответа для проверки статус-кода `200 OK` и заголовка `Content-Type`).

## Разбор сложных моментов и нюансов

1. **Отсутствие ссылки на `nginx.conf` в методичке:** В тексте задания указано «Скачай конфигурационный файл nginx», но внешняя ссылка не приведена. Если конфиг не остался от предыдущего задания курса, необходимо создать минимальный рабочий `nginx.conf` с директивой `return 200`, так как дефолтный конфиг базового образа `nginx:stable` отдаёт стандартную страницу приветствия Nginx, а не требуемую строку Innowise.
2. **Почему в `Dockerfile` не прописана инструкция `CMD`:** При наследовании от официального образа `nginx:stable` дочерний образ автоматически наследует метаданные и точку запуска родительского образа (`CMD ["nginx", "-g", "daemon off;"]`). Переопределять её вручную не требуется.
3. **Замена основного конфига против `conf.d`:** В образе `nginx` главный файл `/etc/nginx/nginx.conf` подключает дополнительные файлы из `/etc/nginx/conf.d/*.conf`. Так как по условию требовалось скопировать файл именно *как основной конфигурационный файл*, мы перезаписали `/etc/nginx/nginx.conf`, поэтому в нём обязательно должна присутствовать корневая секция `events {}` и обёртка `http {}`.
4. **Безопасность публикации портов (`127.0.0.1:8900:80` vs `8900:80`):** Если указать `-p 8900:80` без IP-адреса, Docker опубликует порт на `0.0.0.0` (все сетевые интерфейсы хоста), сделав контейнер доступным извне. Явное указание `127.0.0.1` ограничивает доступ только локальной машиной, как того требует чекпоинт.
