## Введение

В данном задании мы поймем, как можно собрать образ со своим приложением при помощи Dockerfile, и изучим базовые директивы.

**Dockerfile** — это файл, определяющий сценарий сборки образа. Этот файл похож на Makefile, Rakefile и другие файлы, которые описывают действия, однако Dockerfile отличается прописанным синтаксисом, где каждая директива должна начинаться со служебного слова. Именно эти директивы определяют, что будет в этот момент производиться на конкретном этапе сборки, и что будет содержаться в полученном образе.

## FROM

Директива, с которой, как правило, начинается любой Dockerfile, это:

**FROM** — определяет, на базе какого образа создается новый образ. Зачастую используется либо образ с базовым приложением (с тем же nginx), у которого меняется окружение запуска — параметры запуска или конфигурационный файл, либо образ со средой сборки/исполнения. Для примера, с Golang или с Python нужной версии.

Так, частым паттерном сборки является использование образа nginx, в который добавляются файлы статического сайта.

**Формат использования:**

```dockerfile
FROM REPOSITORY_NAME[:TAG_NAME]
```

**В котором:**
- `REPOSITORY_NAME` — образ (адрес реестра и имя репозитория). По умолчанию используется реестр Docker Hub Container Image Library | App Containerization, поэтому можно писать только имя репозитория, например, `nginx`.
- `TAG_NAME` — тег образа, например, `stable`. Это опциональный параметр, так как по умолчанию Docker сам поставит `latest`.

## COPY

Чтобы добавить файл в образ, используется директива:

**COPY** — команда используется для копирования файла из директории, откуда начинается сборка, в путь внутри образа. Команда используется в описанном выше случае, когда нам требуется добавить статичный файл (собранный бинарник или файлы статичного сайта) в образ или исходные файлы, над которыми далее будет производиться работа.

**Формат использования:**

```dockerfile
COPY [--chown=USER:GROUP] SRC DEST
```

**В котором:**
- `USER` — пользователь, который будет владеть файлом в образе;
- `GROUP` — группа, которая будет владеть файлом в образе;
- `SRC` — исходный относительный путь до файла в исходной директории;
- `DEST` — абсолютный или относительный (рабочей директории) путь до файла в целевой директории.

> **Важно!** Docker из соображений безопасности не позволяет копировать из файлов, расположенных вне текущей рабочей директории, поэтому `SRC` не может быть вида `../secret/data`.

## ADD

Есть еще одна похожая на `COPY` команда:

**ADD** — команда используется для копирования файла в путь внутри образа. Определение очень похоже на определение `COPY`, правда? Между ними есть разница. `ADD`, кроме копирования файлов из локальной директории, еще умеет скачивать удаленные файлы и разархивировать архивы (формата `tar.gz`). О том, почему официальная документация не рекомендует использовать эти функциональные возможности, мы поговорим позднее.

Пока мы остановимся только на этих трех директивах и разберем, как собирать образы.

## build

Для сборки образов используется команда `docker build`. Эта команда запускает сборку образа согласно описанному Dockerfile в указанной рабочей директории. Самый простой пример директории, используемой для сборки образа, имеет следующий вид:

```text
.
├── Dockerfile
└── static
    └── index.html
```

Тогда вызов сборки будет выглядеть следующим образом:

```bash
docker build .
```

**Однако у такого вызова есть несколько нюансов:**
- Подразумевается, что Dockerfile расположен в той же директории, где вызывается команда.
- Имя образа не обозначено, а значит, в `docker images` имени тоже не будет — только тег `latest` и сгенерированный `IMAGE ID`.

**Более развернутый формат использования команды выглядит следующим образом:**

```bash
docker build [-f DOCKERFILE_PATH] [-t REPOSITORY_NAME[:TAG_NAME]...] [PATH|URL|-]
```

**В котором:**
- `DOCKERFILE_PATH` — указание пути к Dockerfile в случае, если файл расположен в поддиректории или наименован нестандартно. Например, если есть еще один Dockerfile, который используется для Dev-разработки, имеет другой сценарий сборки и называется, к примеру, `Dockerfile.dev`.
- `REPOSITORY_NAME` — имя и адрес реестра, где он должен храниться. Возможно использование имени и без реестра, по аналогии с образом `nginx`.
- `TAG_NAME` — тег образа. Он может отсутствовать, и тогда автоматически устанавливается тег `latest`. Возможно множественное использование опции `-t` в том случае, когда образ имеет несколько тегов. Пример использования — образ `nginx` (`stable` и `1.16.1`).
- `PATH` — локальный путь, который должен использоваться как контекст сборки. Например, откуда будут копироваться файлы.
- `URL` — позволяет указать удаленный архив (`tar.gz`) или репозиторий (например, git-репозиторий на github), который будет использоваться как контекст.
- `-` — позволяет передавать контекст через перенаправление стандартных выводов или pipeline.
