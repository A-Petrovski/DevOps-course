## 1. Клонирование репозитория fat_free_crm

Переходим в рабочую директорию пользователя и клонируем официальный репозиторий проекта:

```bash
cd /home/user && git clone https://github.com
```

### Разбор параметров и команд:
* `cd /home/user` — переход в целевую родительскую директорию, внутри которой будет создана папка проекта.
* `&&` — логический оператор «И»; следующая команда выполнится только при успешном завершении предыдущей.
* `git clone` — подкоманда Git для создания локальной копии удаленного репозитория со всей историей коммитов.
* `https://github.com` — URL-адрес удаленного репозитория.

**Пример использования:** `git clone --depth 1 https://github.com` (клонирование только последнего коммита без всей истории, чтобы сэкономить место и время).

## 2. Создание и настройка файла .dockerignore

Создаем файл `/home/user/fat_free_crm/.dockerignore` и записываем в него паттерны исключения:

```bash
cat << 'EOF' > /home/user/fat_free_crm/.dockerignore
.git
.*.yml
config/*.yml
!config/settings.default.yml
!config/database.sqlite.yml
!config/database.postgres.docker.yml
public/avatars/**/*.gif
EOF
```

### Разбор параметров и синтаксиса паттернов:
* `cat << 'EOF' > <файл>` — перенаправление многострочного ввода (Here-Document) в файл; кавычки вокруг `'EOF'` запрещают оболочке bash раскрывать спецсимволы внутри блока.
* `.git` — исключает директорию `.git` со всей историей репозитория.
* `.*.yml` — исключает все скрытые файлы в корне контекста (начинающиеся с `.`) с расширением `.yml`.
* `config/*.yml` — исключает все `.yml` файлы непосредственно внутри директории `config/`.
* `!config/<имя_файла>` — префикс инверсии (`!`) отменяет запрет для конкретных файлов, возвращая их в контекст сборки.
* `public/avatars/**/*.gif` — рекурсивно (`**`) находит и исключает все файлы с расширением `.gif` на любом уровне вложенности внутри `public/avatars/`.

### Важные нюансы и разбор ошибок:
1. **Порядок правил критичен:** Парсер Docker читает `.dockerignore` построчно сверху вниз, и каждое последующее совпадение перезаписывает предыдущее. Разрешающие правила с `!` обязаны идти **после** общего запрещающего правила `config/*.yml`. Если поменять их местами, общее правило перекроет исключения, и нужные конфиги не попадут в образ.
2. **Подключение файла не требуется:** Docker автоматически применяет файл `.dockerignore`, если он находится в корне контекста сборки (в той же директории, откуда запускается сборка).

**Пример использования:** `ls -la /home/user/fat_free_crm/.dockerignore && cat /home/user/fat_free_crm/.dockerignore` (проверка наличия скрытого файла и его содержимого).

## 3. Проверка работы правил .dockerignore

В CLI Docker нет встроенной команды вида `git check-ignore`, поэтому для верификации собираем временный тестовый образ «на лету» из стандартного ввода и проверяем скопированные файлы:

```bash
cd /home/user/fat_free_crm

docker build --no-cache -t check-ignore - << 'EOF'
FROM alpine
COPY . /test
EOF

docker run --rm check-ignore find /test/config -maxdepth 1
docker run --rm check-ignore find /test/public/avatars -name "*.gif"
docker rmi check-ignore
```

### Разбор параметров и флагов:
* `docker build ... -` — символ `-` в конце указывает Docker читать инструкции `Dockerfile` из стандартного потока ввода (`stdin`), не создавая файл на диске.
* `--no-cache` — принудительно отключает кэширование слоев при сборке, гарантируя свежую отправку контекста.
* `-t check-ignore` — присваивает временному образу имя (тег) `check-ignore`.
* `docker run --rm` — запускает контейнер из тестового образа и автоматически удаляет контейнер сразу после завершения команды.
* `find /test/config -maxdepth 1` — выводит список файлов в директории `/test/config` без погружения в подпапки (в выводе должны остаться только 3 разрешенных `.yml` файла).
* `find /test/public/avatars -name "*.gif"` — ищет все `.gif` файлы в папке аватаров (при верной настройке вывод будет пустым).
* `docker rmi check-ignore` — удаляет временный тестовый образ с хоста.

**Пример использования:** `docker build --no-cache --progress=plain -t check-size - << 'EOF'` (запуск сборки с выводом подробных логов `transferring context:`, позволяющий увидеть точный объем передаваемых данных в байтах/мегабайтах до и после настройки `.dockerignore`).
