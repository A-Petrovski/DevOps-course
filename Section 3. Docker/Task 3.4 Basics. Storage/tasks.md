## 1. Подготовка конфигурационного файла Nginx
Создаём рабочую директорию `/home/amp/study-docker` и записываем в неё чистый файл конфигурации `nginx.conf` с директивами записи логов в директорию `/etc/nginx/logs/external` и возвратом требуемой строки приветствия.

```bash
mkdir -p /home/amp/study-docker && \
printf 'events {}\n\nhttp {\n    access_log /etc/nginx/logs/external/access.log;\n    error_log /etc/nginx/logs/external/error.log;\n\n    server {\n        listen 80;\n        location / {\n            return 200 "Welcome to the training program Innowise: Docker!\\n";\n        }\n    }\n}\n' > /home/amp/study-docker/nginx.conf
```

**Разбор использованных команд и параметров:**
* `mkdir -p` — создаёт директорию и все недостающие родительские каталоги без вывода ошибки, если папка уже существует.
* `&&` — логический оператор «И», запускающий следующую команду только при успешном выполнении предыдущей.
* `printf '...' > файл` — форматированный вывод текста с записью в указанный файл (более безопасен при копировании, чем `cat << EOF` или `nano`, так как исключает случайную вставку служебных слов и обрезание символов).
* `events {}` — обязательная директива конфигурации Nginx, без которой сервер не запустится.
* `access_log` / `error_log` — директивы, направляющие журналы доступа и ошибок в примонтированную поддиректорию `/etc/nginx/logs/external/`.

**Пример использования:**
```bash
sed -i '1i events {}' /home/amp/study-docker/nginx.conf
```

## 2. Создание Docker Volume
Создаём именованный том с именем `inno-dkr-04-volume` средствами Docker CLI.

```bash
sudo docker volume create inno-dkr-04-volume
```

**Разбор использованных команд и параметров:**
* `docker volume create` — подкоманда Docker CLI для создания нового управляемого хранилища (Volume).
* `inno-dkr-04-volume` — заданное имя создаваемого тома, по которому к нему можно обращаться при запуске контейнеров.

**Пример использования:**
```bash
sudo docker volume inspect inno-dkr-04-volume
```

## 3. Запуск контейнера Nginx с подключением конфига и Volume
Запускаем контейнер `inno-dkr-04` в фоновом режиме на базе образа `nginx:stable` с пробросом файла конфигурации и монтированием тома для логов.

```bash
sudo docker run -d \
  --name inno-dkr-04 \
  -p 127.0.0.1:8891:80 \
  -v /home/amp/study-docker/nginx.conf:/etc/nginx/nginx.conf \
  -v inno-dkr-04-volume:/etc/nginx/logs/external \
  nginx:stable
```

**Разбор использованных флагов и параметров:**
* `-d` (`--detach`) — запуск контейнера в фоновом режиме.
* `--name inno-dkr-04` — присвоение контейнеру фиксированного имени.
* `-p 127.0.0.1:8891:80` — публикация порта: связывает локальный интерфейс хоста `127.0.0.1` и порт `8891` с портом `80` внутри контейнера.
* `-v /home/amp/study-docker/nginx.conf:/etc/nginx/nginx.conf` — **bind mount** одиночного файла: заменяет стандартный конфиг Nginx внутри контейнера на файл с хоста.
* `-v inno-dkr-04-volume:/etc/nginx/logs/external` — монтирование созданного **Volume** в поддиректорию логов внутри контейнера (используется поддиректория `logs/external`, чтобы не перекрыть системные файлы в `/etc/nginx`).
* `nginx:stable` — имя и тег используемого образа.

**Пример использования:**
```bash
sudo docker rm -f inno-dkr-04 && sudo docker run -d --name inno-dkr-04 -p 127.0.0.1:8891:80 -v /home/amp/study-docker/nginx.conf:/etc/nginx/nginx.conf -v inno-dkr-04-volume:/etc/nginx/logs/external nginx:stable
```

## 4. Проверка работы веб-сервера
Отправляем HTTP-запрос на локальный адрес и порт хоста, чтобы убедиться в корректности ответа Nginx.

```bash
curl 127.0.0.1:8891
```

**Разбор использованных команд и параметров:**
* `curl` — консольная утилита для выполнения сетевых запросов.
* `127.0.0.1:8891` — адрес локальной петли (localhost) и порт, на котором слушает проброшенный контейнер.

**Пример использования:**
```bash
curl -i 127.0.0.1:8891
```

## 5. Вывод списка контейнеров, томов и содержимого Volume на хосте
Выполняем финальные проверки состояния контейнера, наличия тома и появления файлов логов на файловой системе хоста.

```bash
sudo docker ps
sudo docker volume ls
sudo ls -la /var/lib/docker/volumes/inno-dkr-04-volume/_data
```

**Разбор использованных команд и параметров:**
* `docker ps` — выводит список всех запущенных в данный момент контейнеров (убеждаемся, что `inno-dkr-04` имеет статус `Up`).
* `docker volume ls` — выводит список всех созданных в системе Docker volumes.
* `sudo ls -la /var/lib/docker/volumes/inno-dkr-04-volume/_data` — отображает подробный список всех файлов (включая скрытые) внутри физической директории тома на хосте (доступ требует прав `root` / `sudo`).

**Пример использования:**
```bash
sudo ls -la $(sudo docker volume inspect -f '{{ .Mountpoint }}' inno-dkr-04-volume)
```

## Разбор типовых ошибок при выполнении
1. **Путаница в порядке путей в `-v` (`хост:контейнер`):**
   * *Ошибка:* `-v "\$(pwd)/nginx.conf":/home/amp/study-docker`.
   * *Суть:* Слева всегда указывается путь на хосте, справа — путь внутри контейнера. Nginx внутри контейнера читает конфигурацию по пути `/etc/nginx/nginx.conf`.
2. **Ошибка синтаксиса `unknown directive "cat"` или `EOF` в `nginx.conf`:**
   * *Суть:* Возникает при случайном копировании обвязки `cat << 'EOF'` внутрь самого файла конфигурации или при вставке текста в `nano` с обрезанием первых символов (`vents` вместо `events`). Контейнер при этом создаётся, но сразу завершает работу, а `curl` возвращает `Failed to connect to 127.0.0.1 port 8891`.
   * *Диагностика:* Просмотр логов упавшего контейнера командой `sudo docker logs inno-dkr-04`.
3. **Монтирование в корень `/etc/nginx` вместо `/etc/nginx/logs/external`:**
   * *Суть:* Монтирование директории перекрывает исходное содержимое папки в контейнере. Подключение тома в поддиректорию `logs/external` сохраняет стандартные конфигурационные файлы Nginx в `/etc/nginx`.
