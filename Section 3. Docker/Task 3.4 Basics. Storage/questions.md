# Вопросы для самоконтроля: Хранилища в Docker (Bind Mount и Volume)

## 1. Преимущества и недостатки прямого подключения файлов и директорий (bind mount) в контейнерах
**Ответ:**
* **Преимущества:**
  * Прямой и мгновенный доступ к файлам с хостовой машины (удобно редактировать конфиги или код привычными инструментами на хосте и сразу видеть изменения в контейнере).
  * Не требует предварительного создания сущностей через Docker CLI — монтируется любой существующий путь на хосте.
* **Недостатки:**
  * Жёсткая привязка к структуре директорий и правам доступа конкретной хостовой ОС (снижается переносимость).
  * Риск случайно перезаписать, повредить или удалить важные системные файлы хоста процессами внутри контейнера.
  * Монтирование директории поверх существующей папки в контейнере скрывает её исходные файлы.

**Пример из практики:**
```bash
# Проброс одиночного конфига с хоста в контейнер (только для чтения :ro для безопасности)
docker run -d -v /opt/app/config.yaml:/app/config.yaml:ro my-app
```

## 2. Когда рекомендуется использовать прямое подключение, а когда лучше использовать Volume?
**Ответ:**
* **Bind mount рекомендуется использовать:**
  * При локальной разработке для проброса исходного кода в контейнер с горячей перезагрузкой.
  * При передаче одиночных конфигурационных файлов с хоста в контейнер (например, `nginx.conf`).
* **Volume рекомендуется использовать:**
  * Для постоянного хранения данных баз данных (PostgreSQL, MySQL, Redis), пользовательских загрузок и логов в production-среде.
  * Когда данными должен управлять сам Docker, не привязываясь к конкретной файловой структуре хоста.
  * При необходимости делиться данными между несколькими контейнерами или использовать удалённые драйверы хранения (NFS, облачные хранилища).

**Пример из практики:**
```bash
# Использование Volume для данных БД и Bind Mount для кастомного конфига
docker run -d \
  -v pgdata:/var/lib/postgresql/data \
  -v /srv/postgres/postgresql.conf:/etc/postgresql/postgresql.conf \
  postgres:16
```

## 3. Различия между прямым подключением и использованием Volume в контексте управления данными в Docker
**Ответ:**
* **Расположение данных:** при `bind mount` данные лежат в произвольной директории хоста, указанной пользователем; при `volume` — строго в изолированной служебной директории Docker (`/var/lib/docker/volumes/<имя_тома>/_data`).
* **Инструмент управления:** `bind mount` управляется стандартными командами ОС хоста (`mkdir`, `rm`, `chmod`), а `volume` — централизованно через интерфейс `docker volume` в Docker CLI.
* **Поведение при монтировании в непустую директорию контейнера:** `bind mount` всегда перекрывает содержимое целевой директории контейнера; новый пустой `volume` при первом подключении предварительно копирует в себя исходные файлы из целевой директории контейнера.

**Пример из практики:**
```bash
# Просмотр точки монтирования Volume на хосте
docker volume inspect my_vol --format '{{ .Mountpoint }}'
```

## 4. Какие преимущества и возможности предоставляет использование Volume?
**Ответ:**
* **Безопасность и изоляция:** хранилище отделено от основной файловой системы хоста и контролируется демоном Docker.
* **Переносимость и кроссплатформенность:** синтаксис подключения тома одинаков на Linux, Windows и macOS.
* **Поддержка драйверов (Volume Drivers):** возможность хранить данные не только на локальном диске, но и на удалённых серверах (SSHFS, NFS) или в облачных провайдерах (AWS EBS, Azure File Storage).
* **Удобство резервного копирования и миграции:** том легко подключить ко временному сервисному контейнеру для архивации данных в `.tar.gz`.
* **Высокая производительность:** работает на скорости нативной файловой системы хоста без накладных расходов драйвера хранилища контейнера (OverlayFS).

**Пример из практики:**
```bash
# Резервное копирование содержимого Volume в архив на хосте
docker run --rm -v inno-dkr-04-volume:/data -v \$(pwd):/backup alpine tar czf /backup/logs_backup.tar.gz -C /data .
```

## 5. Управление Volume с помощью Docker CLI. Как создать, удалить и управлять жизненным циклом Volume с использованием подкоманды `docker volume`?
**Ответ:**
Подкоманда `docker volume` предоставляет полный набор инструментов для управления жизненным циклом томов:
* **Создание (`create`):** создаёт новый именованный том.
* **Просмотр списка (`ls`):** выводит все существующие тома на хосте.
* **Детальная информация (`inspect`):** показывает метаданные тома, драйвер и физический путь `_data` на хосте.
* **Удаление конкретного тома (`rm`):** удаляет указанный том (возможно только если он не подключён ни к одному контейнеру, даже остановленному).
* **Массовая очистка (`prune`):** удаляет все неиспользуемые (осиротевшие) тома, не привязанные ни к одному контейнеру.

**Пример из практики:**
```bash
# Создание тома
docker volume create app-data

# Просмотр списка томов
docker volume ls

# Получение подробной информации о томе
docker volume inspect app-data

# Удаление конкретного тома
docker volume rm app-data

# Удаление всех неиспользуемых томов
docker volume prune -f
```
