# Контрольные вопросы по теме: Работа с контейнерами (Task 3.5)

### 1. В чём разница между командами `docker stop` и `docker rm`? Какие действия выполняются и когда какую использовать?
* **`docker stop`** останавливает запущенный контейнер, завершая его главный процесс, но сохраняет сам контейнер, его файловую систему, конфигурацию и логи на диске (статус меняется на `Exited`). Используется, когда работу сервиса нужно приостановить с возможностью последующего перезапуска (`docker start`).
* **`docker rm`** полностью удаляет остановленный контейнер и его записываемый слой с диска. Используется для очистки системы от ненужных или отработавших контейнеров.

```bash
docker stop my-nginx   # Остановить контейнер
docker rm my-nginx     # Удалить остановленный контейнер
```

---

### 2. Какие сигналы отправляются при выполнении `docker stop`? Что происходит, если контейнер не реагирует на `SIGTERM`?
* При выполнении `docker stop` Docker сначала отправляет главному процессу контейнера (`PID 1`) сигнал **`SIGTERM`** для корректного (мягкого) завершения работы (закрытия соединений, сохранения данных).
* Если процесс не завершается в течение **10 секунд** (таймаут по умолчанию), Docker принудительно убивает его безапелляционным сигналом **`SIGKILL`**, который немедленно прерывает процесс на уровне ядра ОС.

```bash
docker stop -t 30 my-app   # Увеличить ожидание перед SIGKILL до 30 секунд
```

### 3. Как использовать команды `stop` и `start` для управления жизненным циклом контейнеров? Какие флаги могут быть использованы?
* `docker stop` переводит контейнер из состояния `Up` в состояние `Exited`.
* `docker start` повторно запускает уже существующий остановленный контейнер с сохранением всех его настроек, переменных окружения и примонтированных томов (в отличие от `docker run`, который создает новый контейнер).
* Основные флаги: `-t` (`--time`) для `stop` задает время ожидания до `SIGKILL`; `-a` (`--attach`) и `-i` (`--interactive`) для `start` подключают вывод терминала и интерактивный ввод к запускаемому контейнеру.

```bash
docker stop inno-dkr-05-stop
docker start -ai inno-dkr-05-stop
```

### 4. Зачем используется флаг `-a` при выполнении команды `ps`? Какой вывод даёт команда `docker ps -aq`?
* Без флагов команда `docker ps` показывает только запущенные в данный момент контейнеры. Флаг **`-a`** (`--all`) выводит полный список всех контейнеров в системе, включая остановленные (`Exited`), созданные (`Created`) и приостановленные (`Paused`).
* Команда **`docker ps -aq`** (комбинация `-a` и `-q` / `--quiet`) выводит только список идентификаторов (Container ID) абсолютно всех контейнеров без заголовков и дополнительных столбцов.

```bash
docker ps -aq
# Вывод:
# 201315f2f99f
# cd126ec3aeee
```

---

### 5. Как работает конструкция `$(docker ps -aq)` в команде `docker rm $(docker ps -aq)`? Какие контейнеры будут удалены?
* Конструкция `$(...)` — это подстановка вывода команды (Command Substitution) в оболочке Linux. Сначала выполняется внутренняя команда `docker ps -aq`, возвращающая список ID всех контейнеров, а затем эти ID подставляются в виде аргументов в команду `docker rm`.
* При выполнении `docker rm $(docker ps -aq)` без дополнительных флагов **будут удалены только остановленные контейнеры**. Запущенные контейнеры удалены не будут (Docker выведет ошибку о необходимости сначала остановить их или добавить флаг `--force`).

```bash
docker rm \$(docker ps -aq)       # Удалит только остановленные контейнеры
docker rm -f \$(docker ps -aq)    # Удалит вообще все контейнеры, включая запущенные
```
