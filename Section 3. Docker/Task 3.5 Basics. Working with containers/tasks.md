## Чекпоинт 1: Запуск двух контейнеров со случайным именем

Выполните следующую команду **два раза подряд**:

```bash
docker run -d --name "inno-dkr-05-run-$(cat /dev/urandom | tr -cd 'a-f0-9' | head -c 10)" nginx:stable
```

### Разбор параметров и флагов
* `docker run` — создание и запуск нового контейнера из указанного образа.
* `-d` (`--detach`) — запуск контейнера в фоновом режиме с выводом его идентификатора в терминал.
* `--name` — присвоение уникального имени контейнеру.
* `$(...)` — подстановка команд (Command Substitution) в Bash; при каждом запуске выражение внутри вычисляется заново.
* `cat /dev/urandom` — чтение потока случайных байтов из системного генератора.
* `tr -cd 'a-f0-9'` — удаление всех символов (`-d`), кроме (`-c`) шестнадцатеричных цифр и букв от `a` до `f`.
* `head -c 10` — обрезка потока ровно до первых 10 байт (символов).
* `nginx:stable` — имя образа и тег версии, из которого разворачивается контейнер.

**Пример использования:** `docker run -d --name "app-worker-$(head -c 4 /dev/urandom | xxd -p)" nginx:stable`

## Чекпоинт 2: Запуск контейнера для последующей остановки

Запустите третий контейнер с фиксированным именем:

```bash
docker run -d --name inno-dkr-05-stop nginx:stable
```

### Разбор параметров и флагов
* `docker run` — создание и запуск нового контейнера.
* `-d` — работа контейнера в фоне.
* `--name inno-dkr-05-stop` — задание строгого имени `inno-dkr-05-stop` для дальнейшего обращения к нему.
* `nginx:stable` — базовый образ веб-сервера Nginx стабильной ветки.

**Пример использования:** `docker run -d --name temp-redis redis:alpine`

## Чекпоинт 3: Сохранение вывода `docker ps` и остановка одного контейнера

Сохраните список запущенных контейнеров в файл и остановите контейнер `inno-dkr-05-stop`:

```bash
docker ps | tee /home/user/ps.txt
docker stop inno-dkr-05-stop
```

### Разбор параметров и флагов
* `docker ps` — вывод списка только активных (работающих в данный момент) контейнеров.
* `|` (pipe) — передача стандартного вывода (`stdout`) первой команды на стандартный ввод (`stdin`) второй.
* `tee /home/user/ps.txt` — чтение данных со стандартного ввода с одновременным выводом в терминал и перезаписью в указанный файл.
* `docker stop` — мягкая остановка контейнера (отправка `SIGTERM`, затем `SIGKILL` через 10 секунд).

**Пример использования:** `docker ps | tee -a /home/user/ps.txt` *(флаг `-a` дописывает новый вывод в конец существующего файла без его перезаписи)*

## Чекпоинт 4: Проверка списка, массовая остановка и удаление всех контейнеров

Выполните последовательно просмотр всех контейнеров, массовую остановку и удаление:

```bash
# 1. Вывести список всех контейнеров (включая остановленные)
docker ps -a

# 2. Одной командой остановить все запущенные контейнеры
docker stop $(docker ps -q)

# 3. Снова вывести список всех контейнеров
docker ps -a

# 4. Одной командой удалить все контейнеры
docker rm $(docker ps -aq)
```

### Разбор параметров и флагов
* `-a` (`--all`) — отображение всех контейнеров (включая остановленные со статусом `Exited`).
* `-q` (`--quiet`) — вывод только числовых/символьных идентификаторов (ID) контейнеров без заголовков и лишних столбцов.
* `docker stop $(docker ps -q)` — передача списка ID всех запущенных контейнеров в команду `stop`.
* `docker rm $(docker ps -aq)` — передача списка ID абсолютно всех контейнеров (запущенных и остановленных) в команду `rm`.

**Пример использования:** `docker container prune -f` *(удаление всех остановленных контейнеров без запроса подтверждения)*

## Разбор ошибок и нюансов из практики

### 1. Ошибка прав доступа при подстановке команд с `sudo`
* **Симптом:** При запуске `sudo docker rm $(docker ps -aq)` возникает ошибка:
  `permission denied while trying to connect to the docker API at unix:///var/run/docker.sock`
  `docker: 'docker rm' requires at least 1 argument`
* **Причина:** Оболочка Bash вычисляет конструкцию `$(docker ps -aq)` **до** выполнения `sudo`, то есть от имени обычного пользователя. Если пользователь не состоит в группе `docker`, внутренняя команда завершается с ошибкой и возвращает пустую строку.
* **Решение:** Указывать `sudo` как перед основной командой, так и внутри скобок:
  ```bash
  sudo docker rm $(sudo docker ps -aq)
  ```
  Либо добавить текущего пользователя в группу `docker`, чтобы работать без `sudo`:
  ```bash
  sudo usermod -aG docker $USER && newgrp docker
  ```

### 2. Ошибка удаления запущенных контейнеров без предварительной остановки
* **Симптом:** Команда `docker rm $(docker ps -aq)` удаляет только остановленные контейнеры, а для работающих выдает:
  `Error response from daemon: cannot remove container "...": container is running: stop the container before removing or force remove`
* **Причина:** По умолчанию `docker rm` защищает активные контейнеры от случайного удаления.
* **Решение:** Либо предварительно выполнить `docker stop $(docker ps -q)`, либо использовать принудительное удаление флагом `-f` (`--force`):
  ```bash
  docker rm -f $(docker ps -aq)
  ```

### 3. Дозапись в файл вместо перезаписи
* При повторном использовании `docker ps | tee /home/user/ps.txt` старое содержимое файла стирается. Чтобы сохранить историю выводов, необходимо использовать флаг `-a` у `tee` (`docker ps | tee -a /home/user/ps.txt`) или оператор добавления `>>` (`docker ps >> /home/user/ps.txt`).
